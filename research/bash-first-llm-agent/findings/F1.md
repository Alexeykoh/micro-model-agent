# F1: Claude Code's bash tool architecture

## Findings

### [1] Each Bash command runs as an isolated process with no state carryover except working directory
- quote: "The Bash tool runs each command in a separate process with the following persistence behavior... Environment variables don't persist. An `export` in one command won't be available in the next."
- url: https://code.claude.com/docs/en/tools
- source_type: primary
- published: unknown (official docs, accessed 2026-07-16)
- confidence: high

### [2] Default timeout is 2 minutes, configurable up to 10 minutes per command via BASH_DEFAULT_TIMEOUT_MS and BASH_MAX_TIMEOUT_MS env vars
- quote: "Timeout: two minutes by default. Claude can request up to 10 minutes per command with the `timeout` parameter. Override the default and ceiling with BASH_DEFAULT_TIMEOUT_MS and BASH_MAX_TIMEOUT_MS."
- url: https://code.claude.com/docs/en/tools
- source_type: primary
- published: unknown
- confidence: high

### [3] Output truncated at 30,000 chars by default; full output saved to file; hard ceiling of 150,000 chars via BASH_MAX_OUTPUT_LENGTH
- quote: "Output length: 30,000 characters by default. When a command produces more than that, Claude Code saves the full output to a file in the session directory and gives Claude the file path plus a short preview from the start. Claude reads or searches that file when it needs the rest. Raise the limit with BASH_MAX_OUTPUT_LENGTH, up to a hard ceiling of 150,000 characters."
- url: https://code.claude.com/docs/en/tools
- source_type: primary
- published: unknown
- confidence: high

### [4] Built-in read-only command allowlist runs without permission prompts: ls, cat, echo, pwd, head, tail, grep, find, wc, which, diff, stat, du, cd, and read-only git forms
- quote: "Claude Code recognizes a built-in set of Bash commands as read-only and runs them without a permission prompt in every mode. These include ls, cat, echo, pwd, head, tail, grep, find, wc, which, diff, stat, du, cd, and read-only forms of git. The set is not configurable."
- url: https://code.claude.com/docs/en/permissions
- source_type: primary
- published: unknown
- confidence: high

### [5] Permission rules parse compound commands (&&, ||, ;, |, |&, &, newlines) and check each subcommand independently against rules
- quote: "Claude Code is aware of shell operators, so a rule like Bash(safe-cmd *) won't give it permission to run the command safe-cmd && other-cmd. The recognized command separators are &&, ||, ;, |, |&, &, and newlines. A rule must match each subcommand independently."
- url: https://code.claude.com/docs/en/permissions
- source_type: primary
- published: unknown
- confidence: high

### [6] Process wrappers (timeout, time, nice, nohup, stdbuf) are stripped before permission rule matching so rules apply to the inner command
- quote: "Before matching Bash rules, Claude Code strips a fixed set of process wrappers so a rule like Bash(npm test *) also matches timeout 30 npm test. The recognized wrappers are timeout, time, nice, nohup, and stdbuf."
- url: https://code.claude.com/docs/en/permissions
- source_type: primary
- published: unknown
- confidence: high

### [7] Exit code 1 from grep/git-grep and git diff are NOT treated as command failures (semantic exit code handling)
- quote: "The PowerShell tool matches the Bash tool's handling of search and diff exit codes. Exit code 1 from grep, egrep, fgrep, and git grep means no matches, and exit code 1 from git diff means differences exist, so these results aren't reported to Claude as command failures."
- url: https://code.claude.com/docs/en/tools
- source_type: primary
- published: v2.1.196+
- confidence: high

### [8] OS-level sandboxing: Seatbelt on macOS, bubblewrap on Linux/WSL2, with network proxy for domain allowlisting; filesystem restricted to working directory by default
- quote: "macOS: uses Seatbelt for sandbox enforcement. Linux: uses bubblewrap for isolation. WSL2: uses bubblewrap, same as Linux... Default write behavior: read and write access to the current working directory and its subdirectories."
- url: https://code.claude.com/docs/en/sandboxing
- source_type: primary
- published: unknown
- confidence: high

### [9] Working directory persists across commands in the main session (cd carry-over) but resets if cd lands outside project dir; subagents never carry over
- quote: "When Claude runs cd in the main session, the new working directory carries over to later Bash commands as long as it stays inside the project directory... Subagent sessions never carry over working directory changes."
- url: https://code.claude.com/docs/en/tools
- source_type: primary
- published: unknown
- confidence: high

### [10] Shell startup sourcing captures aliases, functions, and shell options from ~/.zshrc, ~/.bashrc, or ~/.profile and applies them to every Bash command
- quote: "At session start, Claude Code sources ~/.zshrc, ~/.bashrc, or ~/.profile depending on your shell, captures the resulting aliases, functions, and shell options, and applies them to every Bash command."
- url: https://code.claude.com/docs/en/tools
- source_type: primary
- published: unknown
- confidence: high

### [11] Hooks system provides PreToolUse validation with JSON input on stdin, exit codes (0=no decision, 2=block), and structured permissionDecision output for programmatic command filtering
- quote: "PreToolUse hooks run before any permission prompt. The hook output can deny the tool call, force a prompt, or skip the prompt to let the call proceed... Exit 2: the action is blocked. Write a reason to stderr, and Claude receives it as feedback."
- url: https://code.claude.com/docs/en/hooks-guide
- source_type: primary
- published: unknown
- confidence: high

### [12] Background command execution via run_in_background:true parameter; long-running processes like dev servers can continue while Claude works on other tasks
- quote: "For long-running processes such as dev servers or watch builds, Claude can set run_in_background: true to start the command as a background task and continue working while it runs."
- url: https://code.claude.com/docs/en/tools
- source_type: primary
- published: unknown
- confidence: high

# F7: Working with 9B models

## Findings

### [1] 7B/9B models hit a "structure tax" threshold — forcing JSON+code dual-format generation causes syntax errors that cascade into agent failures
- quote: "Smaller models struggle to simultaneously handle JSON formatting, Python syntax, and the actual problem-solving logic. The cognitive overhead of structured generation can overwhelm models that would otherwise perform reasonably well with simpler markdown-based code generation."
- url: https://huggingface.co/blog/structured-codeagent
- source_type: primary
- published: 2025-05-28
- confidence: high

### [2] Parsing errors in the first agent step reduce overall success by 21.3% — small models error-recover poorly from malformed output
- quote: "Traces with first call parsing errors: 42.3% success rate. Traces without first call parsing errors: 51.3% success rate. Agent traces without parsing errors succeed 21.3% more often than those with parsing errors."
- url: https://huggingface.co/blog/structured-codeagent
- source_type: primary
- published: 2025-05-28
- confidence: high

### [3] Qwen2.5-Coder-7B achieves competitive code benchmarks against models 2-4x larger, but only with correct chat template — wrong templates cause "drastically worse performance" on 7B models
- quote: "Qwen2.5-Coder has been trained on 5.5 trillion tokens of code-related data, enabling even smaller coding-specific models to deliver competitive performance against larger language models on coding evaluation benchmarks." / "with the wrong control tokens, these models would have drastically worse performance"
- url: https://qwenlm.github.io/blog/qwen2.5/
- source_type: primary
- published: 2024-09-19
- confidence: high

### [4] ReAct structural constraints reduce small model flexibility — CoT sometimes outperforms ReAct on 7B models, but combining both approaches generally wins
- quote: "CoT suffers from fact hallucination... ReAct's structural constraint reduces its flexibility in formulating reasoning steps... Prompting methods that combine and support switching between ReAct and CoT+Self-Consistency generally outperform all the other prompting methods."
- url: https://www.promptingguide.ai/techniques/react
- source_type: secondary
- published: 2025
- confidence: high

### [5] Small models lose performance in the middle of long contexts ("Lost in the Middle") — system prompt and critical tool results must be at the beginning/end
- quote: "performance is often highest when relevant information occurs at the beginning or end of the input context, and significantly degrades when models must access relevant information in the middle of long contexts"
- url: https://arxiv.org/abs/2307.03172
- source_type: primary (peer-reviewed, TACL 2023)
- published: 2023-11-20
- confidence: high

### [6] Gemma 2 9B achieves competitive performance with models 2-3x larger via knowledge distillation training, demonstrating that training methodology matters more than parameter count at this scale
- quote: "We also train the 2B and 9B models with knowledge distillation (Hinton et al., 2015) instead of next token prediction. The resulting models deliver the best performance for their size, and even offer competitive alternatives to models that are 2-3 times bigger."
- url: https://arxiv.org/abs/2408.00118
- source_type: primary (peer-reviewed)
- published: 2024-07-31
- confidence: high

### [7] Pre-filling model responses via continue_final_message with partial JSON dramatically improves instruction-following for small models — they continue structured outputs more reliably than generating from scratch
- quote: "This is useful for 'prefilling' a model response... It can be very useful for improving the accuracy of instruction following when you know how to start its replies."
- url: https://huggingface.co/docs/transformers/main/en/chat_templating
- source_type: primary
- published: unknown
- confidence: medium

### [8] Code-based actions (bash/plain code) outperform JSON tool calling by up to 20% success rate across 17 LLMs — bash-first is the optimal architecture for 9B models
- quote: "CodeAct outperforms widely used alternatives (up to 20% higher success rate)" / "Writing actions in code rather than JSON-like snippets provides better: Composability... Object management... Generality... Representation in LLM training data"
- url: https://arxiv.org/abs/2402.01030
- source_type: primary
- published: 2024-02-01
- confidence: high

### [9] Too much irrelevant context actively harms small model performance — Aider warns when >4 files or >20K tokens combined, repo-map must be proportional to window size
- quote: "Warning: map-tokens > {max_map_tokens} is not recommended. Too much irrelevant code can confuse LLMs." / "warn_number_of_files = 4; warn_number_of_tokens = 20 * 1024"
- url: https://github.com/Aider-AI/aider/blob/main/aider/coders/base_coder.py
- source_type: primary (open-source production code)
- published: 2024-2026
- confidence: high

### [10] Qwen2.5-7B specifically improved JSON generation and resilience to system prompt diversity — the best small coding model choice for bash-first agents in 2024-2025
- quote: "Significant improvements in instruction following, generating long texts (over 8K tokens), understanding structured data (e.g, tables), and generating structured outputs especially JSON. More resilient to the diversity of system prompts."
- url: https://huggingface.co/Qwen/Qwen2.5-7B-Instruct
- source_type: primary
- published: 2024-09
- confidence: high

### [11] Qwen3 thinking mode creates multi-step tool use challenges — reasoning_content fields may be dropped, making multi-step tool interactions suboptimal
- quote: "the quality of multi-step tool use with Qwen3 thinking models may be suboptimal, which requires the existence of the related thinking content. While the fixes are being worked on, we recommend passing the content as it is, without extracting thinking content"
- url: https://github.com/QwenLM/Qwen3/blob/main/README.md
- source_type: primary
- published: 2025-04-29
- confidence: high

### [12] DSPy compilation for small models (llama2-13b-chat) outperforms standard few-shot prompting by 65% — automated prompt optimization is critical for 9B model performance
- quote: "DSPy programs compiled to open and relatively small LMs like 770M-parameter T5 and llama2-13b-chat are competitive with approaches that rely on expert-written prompt chains for proprietary GPT-3.5."
- url: https://arxiv.org/abs/2310.03714
- source_type: primary (peer-reviewed)
- published: 2023-10-05
- confidence: high

## Dead ends
- DeepSeek Coder 6.7B-Instruct model card contained no specific agent/tool-use benchmark data — only general code completion metrics
- Llama 3 8B documentation returned HTTP errors — could not extract specific agent limitations
- No peer-reviewed paper found specifically benchmarking 9B models in bash-first agent configurations
- WebSearch tool was unavailable, limiting search breadth to direct URL fetches only

## Suggested follow-ups
- Benchmark Qwen2.5-7B-Coder vs Llama-3.1-8B vs Gemma-2-9B specifically on multi-step bash command generation (not just code completion)
- Test whether pre-filling with `"bash"` as the assistant prefix improves bash command generation quality on Qwen2.5-7B
- Investigate effective context window limits: at what token count do 7B models start failing on multi-step agent tasks?
- Compare Qwen2.5-Coder-7B vs Qwen3-8B for bash-first agents — does thinking mode help or hurt tool use?
- Research whether tool output summarization (compressing bash output to 2-3 sentences) preserves enough signal for 9B models to reason correctly

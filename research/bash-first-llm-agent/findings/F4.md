# F4: Safety patterns for bash execution

## Findings

### [1] Bubblewrap (bwrap) is the dominant lightweight sandbox for LLM agents on Linux
- quote: "Bubblewrap (bwrap) is the sandbox Flatpak uses to isolate every desktop app. ~50KB binary, ~4000 lines of C, maintained by the GNOME team. It runs without root using CLONE_NEWUSER to create namespaces without elevated privileges."
- url: https://akitaonrails.com/en/2026/03/01/ai-jail-sandbox-for-ai-agents-from-shell-script-to-real-tool/
- source_type: primary
- published: 2026-03-01
- confidence: high

### [2] Claude Code uses bubblewrap on Linux and sandbox-exec on macOS for isolation
- quote: "ai-jail is tool-agnostic. It works with Claude, Codex, OpenCode, Crush, and any command. Claude's sandbox only protects Claude. ... Since October 2025, Claude Code has offered a runtime sandbox via the /sandbox command. And guess what it uses underneath? Bubblewrap on Linux and sandbox-exec on macOS. The same stack."
- url: https://akitaonrails.com/en/2026/03/01/ai-jail-sandbox-for-ai-agents-from-shell-script-to-real-tool/
- source_type: primary
- published: 2026-03-01
- confidence: high

### [3] Dangerous command detection requires NFKC normalization to prevent homograph bypasses
- quote: "Hermes uses regex patterns to scan commands for destructive operations. The detection logic performs command normalization (e.g., NFKC normalization) to prevent homograph-based bypasses where lookalike characters are used to hide malicious commands"
- url: https://deepwiki.com/NousResearch/hermes-agent/5.4-security-and-command-approval
- source_type: primary
- published: 2026-07-09
- confidence: high

### [4] Claude Code plugin system supports both command-based and prompt-based bash validation hooks
- quote: "Prompt-based hooks offer several advantages: Natural language reasoning: LLM understands context and intent, Better edge case handling: Adapts to unexpected scenarios, No bash scripting required: Simpler to write and maintain"
- url: https://github.com/anthropics/claude-code/blob/main/plugins/plugin-dev/skills/hook-development/references/migration.md
- source_type: primary
- published: 2026-07-09
- confidence: high

### [5] OpenCode implements granular bash permissions with pattern-based allowlist/blocklist
- quote: "Use this configuration to define granular permissions for 'bash' and 'edit' tools. Rules are evaluated by pattern match, with the last matching rule taking precedence. Example: bash permissions with \"git *\": \"allow\", \"rm *\": \"deny\", \"grep *\": \"allow\""
- url: https://github.com/anomalyco/opencode/blob/dev/packages/web/src/content/docs/permissions.mdx
- source_type: primary
- published: 2026-07-09
- confidence: high

### [6] Hermes Agent implements a hardline blocklist that cannot be bypassed even in YOLO mode
- quote: "Hardline Blocklist: A non-bypassable 'floor' that blocks catastrophic commands (like rm -rf /) regardless of YOLO mode or user overrides."
- url: https://deepwiki.com/NousResearch/hermes-agent/5.4-security-and-command-approval
- source_type: primary
- published: 2026-07-09
- confidence: high

### [7] Docker-based sandboxes provide defense-in-depth with network whitelisting via DNS proxy
- quote: "The sandbox implements defense-in-depth with three layers: 1) Container Isolation: Agent runs in separate container, only accesses mounted project directory, 2) Network Isolation: Custom Docker network with DNS proxy - only whitelisted domains resolve, 3) Path Restrictions: Within project directory, specific files/folders can be blocked via permission removal"
- url: https://github.com/siawkz/llm-sandbox
- source_type: secondary
- published: 2025-07-24
- confidence: high

### [8] LLM Sandbox library provides SecurityPolicy with regex patterns and restricted modules
- quote: "SecurityPolicy with severity_threshold=SecurityIssueSeverity.MEDIUM, patterns=[SecurityPattern(pattern=r'os\\.system', description='System command execution', severity=SecurityIssueSeverity.HIGH)]"
- url: https://context7.com/vndee/llm-sandbox/llms.txt
- source_type: primary
- published: 2025-07-09
- confidence: high

### [9] Nix-based sandboxes allow declarative security with package-level tool restrictions
- quote: "The sandbox should only contain the tools I explicitly approve. If the agent needs git and curl to do its job, then that's all it gets. It shouldn't even know the rest of my system PATH exists."
- url: https://dev.to/andersonjoseph/how-i-run-llm-agents-in-a-secure-nix-sandbox-1899
- source_type: secondary
- published: 2026-01-03
- confidence: high

### [10] gVisor provides user-space kernel isolation as a Docker runtime alternative
- quote: "gVisor is a user-space kernel that provides strong isolation by intercepting system calls made by processes inside the virtualized environment. It can run standalone or as a Docker runtime. For our purposes, I think it's a perfect middle ground for running untrusted code."
- url: https://amirmalik.net/2025/03/07/code-sandboxes-for-llm-ai-agents
- source_type: secondary
- published: 2025-03-07
- confidence: high

### [11] Claude Code dangerous command patterns include rm -rf, sudo, chmod 777, and git push --force
- quote: "Example: block-dangerous-rm, enabled: true, event: bash, pattern: rm\\s+-rf, action: block"

### [12] Code execution sandboxes should scrub environment variables to prevent credential leakage
- quote: "_scrub_child_env removes all API keys and secrets from the child process environment"

## Dead ends
- Aider shell execution safety: Limited documentation found on Aider's specific bash sandboxing approach; Aider appears to rely more on user consent than automated sandboxing
- Windows sandboxing: No mature userspace sandbox equivalent to Linux namespaces exists on Windows; WSL 2 with bubblewrap is the recommended approach

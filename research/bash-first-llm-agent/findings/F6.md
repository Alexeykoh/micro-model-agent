# F6: Agentic loops and prompt patterns

## Findings

### [1] The ReAct pattern interleaves Thought→Action→Observation in a single generation loop, where reasoning traces help the model plan and adjust while actions interface with external environments
- quote: "we explore the use of LLMs to generate both reasoning traces and task-specific actions in an interleaved manner, allowing for greater synergy between the two"
- url: https://arxiv.org/abs/2210.03629
- source_type: primary
- published: 2022-10-06
- confidence: high

### [2] The canonical agent loop is: User Query → Context Assembly (system + tools + messages) → LLM decides tool call or text response → Execute tool → Append observation → Repeat until done
- quote: "The function calling flow works as follows: User Query → Context Assembly → Tool Decision → Tool Execution → Observation → Response Generation"
- url: https://www.promptingguide.ai/agents/function-calling
- source_type: secondary
- published: 2025
- confidence: high

### [3] Tool definitions (name + description + parameter schema) are the ONLY way the LLM knows what tools exist; descriptions must include WHEN to use the tool, not just WHAT it does
- quote: "The description field is particularly important. It helps the model understand not just what the tool does, but when it should be used."
- url: https://www.promptingguide.ai/agents/function-calling
- source_type: secondary
- published: 2025
- confidence: high

### [4] The ReAct prompt format uses free-form 'Thought' lines for decomposing questions, extracting information, guiding search, and synthesizing answers—thoughts are not constrained to any fixed schema
- quote: "The free-form thoughts are used to achieve different tasks such as decomposing questions, extracting information, performing commonsense/arithmetic reasoning, guide search formulation, and synthesizing final answer."
- url: https://www.promptingguide.ai/techniques/react
- source_type: secondary
- published: 2025
- confidence: high

### [5] LangChain's agent architecture uses a middleware stack (before_model/after_model hooks) with composable layers for tool selection, retry, summarization, context editing, and shell execution—agents are not monolithic loops but composable middleware pipelines
- quote: "AgentMiddleware includes: state_schema, tools, transformers, name... hooks: before_model(), after_model(), wrap_model_call(), wrap_tool_call(), dynamic_prompt()"
- url: https://python.langchain.com/docs/modules/agents/agents
- source_type: primary
- published: 2025
- confidence: high

### [6] Context engineering for agents requires layered architecture: System Layer (identity/capabilities) → Task Layer (current task instructions) → Tool Layer (tool descriptions/usage) → Memory Layer (historical context)
- quote: "We can organize context into hierarchical layers: 1. System Layer: Core agent identity and capabilities, 2. Task Layer: Specific instructions for the current task, 3. Tool Layer: Descriptions and usage guidelines for each tool, 4. Memory Layer: Relevant historical context"
- url: https://www.promptingguide.ai/agents/context-engineering
- source_type: secondary
- published: 2025
- confidence: high

### [7] Small models on ReAct showed that CoT outperformed ReAct on some tasks (HotpotQA) because ReAct's structural constraints reduced flexibility—but combining ReAct with CoT+Self-Consistency generally outperformed all methods
- quote: "CoT suffers from fact hallucination... ReAct's structural constraint reduces its flexibility in formulating reasoning steps... Prompting methods that combine and support switching between ReAct and CoT+Self-Consistency generally outperform all the other prompting methods."
- url: https://www.promptingguide.ai/techniques/react
- source_type: secondary
- published: 2025
- confidence: high

### [8] The ReAct pattern for decision-making tasks uses thoughts more sparsely than for QA tasks—ALFWorld and WebShop examples show minimal thinking between action steps, suggesting the observe-think-act ratio should adapt to task type
- quote: "For tasks where reasoning is of primary importance (e.g., HotpotQA), multiple thought-action-observation steps are used for the task-solving trajectory. For decision making tasks involving lots of action steps, thoughts are used sparsely."
- url: https://www.promptingguide.ai/techniques/react
- source_type: secondary
- published: 2025
- confidence: high

### [9] Three core agent capabilities form the observe-think-act foundation: Planning (task decomposition via CoT), Tool Utilization (interface with external world), and Memory (short-term context buffer + long-term vector store)
- quote: "AI agents require three fundamental capabilities: planning abilities, tool utilization, and memory management... Planning: Task decomposition through chain-of-thought reasoning... Tool Utilization: code interpreters, web search, calculators... Memory: short-term (working) and long-term (vector stores)"
- url: https://www.promptingguide.ai/agents/components
- source_type: secondary
- published: 2025
- confidence: high

### [10] System prompts for tool use should include explicit tool availability lists with usage guidance AND handle error cases with recovery instructions—under-specification and over-constraint are both failure modes
- quote: "You have access to the following tools: web_search: Use this for any questions about current events... Always prefer the knowledge_base for company-specific questions before using web_search."
- url: https://www.promptingguide.ai/agents/function-calling
- source_type: secondary
- published: 2025
- confidence: high

## 2. Качество ответов

### Сильные стороны

**Генерация контента** — модель выдаёт качественные, структурированные ответы:
- Шутки, факты о космосе/пиратах/кулинарии — разнообразные, с эмодзи
- Код на TypeScript — грамотный, с типами, JSDoc, обработкой ошибок
- Объяснения (рекурсия, async/параллельность) — понятные, с примерами

**Работа с инструментами**:
- `write_file` — корректно формирует аргументы, пишет валидный код
- `read_file` — правильные пути
- `plan` — создаёт структурированные планы с шагами
- Автоматическая проверка синтаксиса (`tsc --noEmit`) после записи файлов

**Следование инструкциям**:
- Использует `@nodejs-expert` при указании скилла
- Создаёт план перед реализацией в react-todo и subagent-test
- Следует формату `<tool_call>` для вызова инструментов

### Слабые стороны

**Пустые ответы после tool calls** — главная проблема:
- В 12 из 30 промптов модель возвращала пустой контент после вызова инструментов
- Причина: `reasoning_chunks > 0`, `content_chunks = 0` — модель думает, но не генерирует текст
- Пример: после `write_file` для Logger — 35 reasoning chunks, 0 content chunks
- Механизм retry с `"Continue."` помогает частично, но не всегда

**Потеря контекста после инструментов**:
- После `read_file` для package.json — пустой ответ (80 reasoning chunks)
- После `bash` (tsc --noEmit) — пустой ответ (284 reasoning chunks)
- Модель «застревает» в reasoning-режиме и не переключается на генерацию контента

### Проблемы с bash

Все вызовы `bash` завершились ошибкой:
```
"pwsh" не является внутренней или внешней командой
```
**Причина**: На Windows PowerShell команда `pwsh` недоступна (нужна отдельная установка). Agent loop использует `execa('pwsh', ['-c', cmd])`, но `pwsh` не найден в PATH.

**Рекомендация**: Добавить fallback на `powershell.exe` или `cmd.exe` если `pwsh` недоступен.

### Subagent: проблема отображения

В сценарии `react-todo` subagent был вызван, но:
- Результат отображается как: `[Subagent done — no files, 20 turns, 5133 tokens]`
- **Фактическая работа subagent не видна** — только мета-информация
- Subagent потратил 43.4 секунды, 20 ходов, но **не создал ни одного файла**
- Причина: все `bash`-команды внутри subagent упали (pwsh не найден)

**Вывод**: subagent отвечает за изоляцию контекста, но его результаты не интегрируются в основной вывод. Пользователь не видит что именно subagent делал.

## 4. Управление контекстом

### Compaction (упаковка контекста)

Из логов видно:
- System prompt: ~19,500 символов (включая скиллы)
- Контекст растёт от 3,487 до 5,133 токенов за 20 ходов subagent
- Compaction не срабатывала — контекст не превысил лимит

### Скиллы

- Автозагрузка: 7 скиллов (typescript-expert, nodejs-expert, prisma-client-api, prisma-postgres, nestjs-expert, jest-testing-expert, writing-plans)
- Скилл `nodejs-expert` загружался по запросу через `@nodejs-expert`
- **Проблема**: скиллы загружаются в system prompt, но модель не всегда использует их guidance. Например, `nodejs-expert` содержит инструкции по Express, но модель не следует паттернам из скилла при создании REST API

### Оптимизация контекста

- `enforceSkillBudget()` — ограничивает скиллы 4000 токенов
- В base mode скиллы загружаются (в fast mode — нет)
- Правило "3+ файлов → subagent" работает: модель получает BLOCKED-сообщение при попытке создать файлы напрямую

## 5. Принятие решений

### Позитивные паттерны

1. **Планирование**: Модель создаёт план перед сложными задачами (react-todo, subagent-test)
2. **Самопроверка**: После записи файла запускает `tsc --noEmit` для проверки типов
3. **Исправление ошибок**: При синтаксических ошибках пытается перезаписать файл
4. **Следование скиллам**: Загружает `@nodejs-expert` когда указано

### Негативные паттерны

1. **Зацикливание на bash**: Subagent в react-todo 12 раз подряд пробовал variations `npm create vite` — все упали
2. **Не адаптируется к ошибкам**: Не переключается на `write_file` когда `bash` недоступен
3. **Пустые ответы**: После каждого tool call есть вероятность пустого ответа

## 7. Критические проблемы для исправления

### P0: bash-команды падают на Windows
**Симптом**: Все `bash`-вызовы завершаются с `"pwsh" не является командой`
**Влияние**: tsc --noEmit не работает, npm-команды не работают, subagent не может установить зависимости
**Рекомендация**: В `bash.ts` добавить detection текущей shell и fallback:
```typescript
const shell = process.platform === 'win32' ? 'powershell.exe' : 'sh';
```

### P1: Пустые ответы после tool calls
**Симптом**: `reasoning_chunks > 0, content_chunks = 0`
**Влияние**: Агент не может продолжить работу после вызова инструмента
**Рекомендация**: Увеличить `max_tokens` для последующих вызовов после tool call, или добавить更强 hint в retry-message

### P2: Subagent не создаёт файлы
**Симптом**: 20 ходов, 0 файлов — все bash-команды упали
**Влияние**: React TODO приложение не создано
**Рекомендация**: Subagent должен fallback на `write_file` когда `bash` недоступен

## 8. Рекомендации

1. **Исправить bash handler** — добавить fallback shell для Windows
2. **Увеличить max_tokens** после tool call — минимум 2048 для продолжения
3. **Улучшить subagent result rendering** — показывать что именно subagent делал (файлы, команды)
4. **Добавить retry с увеличением max_tokens** — если первый retry пустой, второй с бо́льшим лимитом
5. **Оптимизировать system prompt** — сократить скиллы которые не используются в текущем контексте
6. **Добавить telemetry по empty responses** — трекать частоту и причину

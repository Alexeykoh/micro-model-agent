# F4: Agent Loop Design for Small Models

## Findings

### [1] Start with the simplest loop possible; only add complexity when measurably needed
- quote: "When building applications with LLMs, we recommend finding the simplest solution possible, and only increasing complexity when needed. This might mean not building agentic systems at all."
- url: https://www.anthropic.com/engineering/building-effective-agents
- source_type: primary
- published: 2024-12-19
- confidence: high

### [2] The Ralph Loop uses external deterministic validation (tests, linters) as exit condition, not self-assessment — critical for preventing hallucination loops in small models
- quote: "Two things make it different from the Reflection Loop: The exit condition comes from deterministic software checks (tests green, type errors zero), not the agent's self-assessment. Each iteration resets context, which prevents context window degradation on long runs."
- url: https://datasciencedojo.com/blog/loop-engineering-design-patterns/
- source_type: secondary
- published: 2026-06-24
- confidence: high

### [3] Bounded execution and circuit breakers are non-negotiable production safeguards for any agentic loop
- quote: "Bounded Execution caps the loop at a defined limit: maximum iterations, maximum token spend, maximum wall time. Without it, a loop with no hard ceiling will eventually hit one you didn't plan for — a cost spike, a rate limit, or a timeout. Circuit Breaker monitors the agent's progress across iterations. If the agent is stuck — alternating between the same file states, repeating identical errors, failing to make measurable progress over three consecutive cycles — the breaker trips."
- url: https://datasciencedojo.com/blog/loop-engineering-design-patterns/
- source_type: secondary
- published: 2026-06-24
- confidence: high

### [4] Track repeated tool calls to break infinite loops — a simple deduplication strategy
- quote: "MAX_ITERATIONS = 15; seen_actions = set(); if action_key in seen_actions: return 'Error: Agent stuck in loop. Breaking out.'"
- url: https://www.youngju.dev/blog/culture/2026-03-18-llm-agent-design-patterns.en
- source_type: secondary
- published: 2026-03-18
- confidence: high

### [5] Reflection/critique loops should be limited to 2-3 rounds — more causes over-correction and second-guessing
- quote: "Too many reflection rounds can cause over-correction — the model second-guesses correct answers. Two to three rounds is usually the sweet spot."
- url: https://www.youngju.dev/blog/culture/2026-03-18-llm-agent-design-patterns.en
- source_type: secondary
- published: 2026-03-18
- confidence: high

### [6] Plan-and-Execute pattern allows different model sizes for planning vs execution — use powerful model for planning, cheaper/smaller for execution
- quote: "You can use different models for planning vs execution. Plan with GPT-4, execute with GPT-3.5 — significant cost savings on long workflows."
- url: https://www.youngju.dev/blog/culture/2026-03-18-llm-agent-design-patterns.en
- source_type: secondary
- published: 2026-03-18
- confidence: high

### [7] Small models are more reliable for narrow, specialized agentic tasks because they can be fine-tuned for strict formatting and won't drift to alternative output formats
- quote: "A crucial and decisive advantage of SLMs lies in their flexibility and alignment. They're easier to fine-tune for strict formatting and behavioral requirements, which is critical for agent workflows where every tool call and code interaction must match exact schemas. An LLM might occasionally drift and produce malformed output, where an SLM trained to always respond in a single format won't, because it isn't aware of any other output formats."
- url: https://developer.nvidia.com/blog/how-small-language-models-are-key-to-scalable-agentic-ai/
- source_type: primary
- published: 2025-08-29
- confidence: high

### [8] Tool errors should be surfaced to the LLM (not silently swallowed) so the model can adapt its approach
- quote: "Bad — silent failure: result = tool.run(args). Good — tell the LLM what went wrong so it can adapt: except Exception as e: result = f'Tool error: {str(e)}. Try a different approach.'"
- url: https://www.youngju.dev/blog/culture/2026-03-18-llm-agent-design-patterns.en
- source_type: secondary
- published: 2026-03-18
- confidence: high

### [9] The general rule for production agent loops: start with ReAct + Tool Use as base, add Bounded Execution early, layer in Circuit Breaker for autonomous runs, only add multi-agent when single-agent genuinely can't handle the task
- quote: "A common starting stack: Tool Use Loop as the base execution pattern. Bounded Execution as the hard ceiling. Circuit Breaker for stagnation detection. Multi-Agent Supervisor if the task exceeds a single context window."
- url: https://datasciencedojo.com/blog/loop-engineering-design-patterns/
- source_type: secondary
- published: 2026-06-24
- confidence: high

### [10] Heterogeneous agent architecture: use SLMs for bulk operational subtasks, reserve LLMs for complex reasoning and multi-step strategic tasks
- quote: "Think of SLMs as the workers in a digital factory (efficient, specialized, and reliable). LLMs act as consultants called in when broad expertise is required or when pleasant interactions with the outside world are needed."
- url: https://developer.nvidia.com/blog/how-small-language-models-are-key-to-scalable-agentic-ai/
- source_type: primary
- published: 2025-08-29
- confidence: high

### [11] Context window overflow is a silent killer of agent loop quality — trim oldest observations first, keep system message
- quote: "Accumulated Observations fill up the context window in long sessions. Remove oldest Observations first, keep system message."
- url: https://www.youngju.dev/blog/culture/2026-03-18-llm-agent-design-patterns.en
- source_type: secondary
- published: 2026-03-18
- confidence: high

### [12] Tool timeouts are essential — without them, an external API hang causes the agent to wait forever
- quote: "If an external API hangs, your agent waits forever. async def run_tool_with_timeout(tool, args, timeout=30): return await asyncio.wait_for(tool.arun(args), timeout=timeout)"
- url: https://www.youngju.dev/blog/culture/2026-03-18-llm-agent-design-patterns.en
- source_type: secondary
- published: 2026-03-18
- confidence: high

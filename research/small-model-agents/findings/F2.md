# F2: Context Window Optimization

## Findings

### [1] LLMs exhibit U-shaped performance on long contexts: best at beginning/end, worst in the middle ("Lost in the Middle")
- quote: "performance is often highest when relevant information occurs at the beginning or end of the input context, and significantly degrades when models must access relevant information in the middle of long contexts"
- url: https://arxiv.org/abs/2307.03172
- source_type: primary (peer-reviewed, TACL 2023)
- published: 2023-11-20
- confidence: high

**Implication for 32K-64K agents**: Place system prompt and high-priority task context at the very beginning and end of the context window. Avoid burying critical tool results or instructions in the middle of long conversations.

### [2] MemGPT implements OS-inspired virtual context management with hierarchical memory tiers to extend effective context beyond native limits
- quote: "we propose virtual context management, a technique drawing inspiration from hierarchical memory systems in traditional operating systems that provide the appearance of large memory resources through data movement between fast and slow memory"
- url: https://arxiv.org/abs/2310.08560
- source_type: primary (peer-reviewed paper)
- published: 2024-02-12
- confidence: high

**Implication for 32K-64K agents**: Treat the context window as fast (main) memory and maintain an external summary/store as slow memory. Periodically page out summarized older turns, keep active working context in-window.

### [3] Aider uses a dual-model summarization pipeline: the weak (cheap) model drafts summaries, the main model refines them, triggered when conversation history exceeds max_chat_history_tokens
- quote: `self.summarizer = summarizer or ChatSummary([self.main_model.weak_model, self.main_model], self.main_model.max_chat_history_tokens)`
- url: https://github.com/Aider-AI/aider/blob/main/aider/coders/base_coder.py
- source_type: primary (open-source production code)
- published: unknown (active codebase, 2024-2026)
- confidence: high

**Implication for 32K-64K agents**: Summarization of conversation history should be triggered proactively before context fills. A cheaper/smaller model can do initial summarization to preserve the main model's tokens for the task.

### [4] Aider moves completed conversation turns to done_messages and runs summarization in a background thread to avoid blocking the main interaction loop
- quote: `def summarize_start(self): if not self.summarizer.too_big(self.done_messages): return`
- url: https://github.com/Aider-AI/aider/blob/main/aider/coders/base_coder.py
- source_type: primary (open-source production code)
- published: unknown
- confidence: high

**Implication for 32K-64K agents**: Summarize asynchronously. Don't block the agent while compressing history. Use a "too big" threshold to trigger summarization before hitting the context limit.

### [5] When switching edit formats, Aider summarizes old assistant messages because the old format confuses the new LLM into imitating it
- quote: "If the edit format changes, we can't leave old ASSISTANT messages in the chat history. The old edit format will confused the new LLM."
- url: https://github.com/Aider-AI/aider/blob/main/aider/coders/base_coder.py
- source_type: primary (open-source production code)
- published: unknown
- confidence: high

**Implication for 32K-64K agents**: Tool output formatting changes or edit format switches should trigger context cleanup. Stale format artifacts in history can degrade small model performance.

### [6] Aider warns when added files exceed 4 files AND 20K tokens combined, recommending users only add files needing changes
- quote: `warn_number_of_files = 4; warn_number_of_tokens = 20 * 1024`
- url: https://github.com/Aider-AI/aider/blob/main/aider/coders/base_coder.py
- source_type: primary (open-source production code)
- published: unknown
- confidence: high

**Implication for 32K-64K agents**: For a 32K context window, ~20K tokens of file content is a reasonable upper bound for chat files (leaving ~12K for system prompt + conversation + tool outputs). Aggressively limit the number of files held in context.

### [7] Aider's repo-map is dynamically sized based on model's max_input_tokens, with a warning that too much irrelevant code confuses LLMs
- quote: "Warning: map-tokens > {max_map_tokens} is not recommended. Too much irrelevant code can confuse LLMs."
- url: https://github.com/Aider-AI/aider/blob/main/aider/coders/base_coder.py
- source_type: primary (open-source production code)
- published: unknown
- confidence: high

**Implication for 32K-64K agents**: Context budgeting for code maps/summaries must be proportional to window size. For 32K models, keep repo-map under ~4K tokens. Too much context of low relevance is worse than less context of high relevance.

### [8] MemGPT uses interrupts to manage control flow: the system self-manages context by paging data between tiers without user intervention
- quote: "utilizes interrupts to manage control flow between itself and the user"
- url: https://arxiv.org/abs/2310.08560
- source_type: primary
- published: 2024-02-12
- confidence: high

**Implication for 32K-64K agents**: Implement proactive context management that automatically compresses/evicts when approaching limits, rather than relying on the model to self-regulate within a fixed window.

### [9] CrewAI's unified memory system uses composite scoring (semantic similarity + recency + importance) for recall, with configurable weights and exponential time decay
- quote: "composite = semantic_weight * similarity + recency_weight * decay + importance_weight * importance"
- url: https://docs.crewai.com/concepts/memory
- source_type: primary (official documentation)
- published: 2024-2025
- confidence: medium (general framework, not specifically for small models)

**Implication for 32K-64K agents**: When deciding what to keep vs. drop from context, prioritize: (1) semantically relevant to current task, (2) recent (within last few turns), (3) high importance (errors, key decisions). Use exponential decay with a half-life tuned to conversation length.

### [10] CrewAI memory consolidation automatically deduplicates similar records above a 0.85 similarity threshold, using LLM-driven merge/keep/delete decisions
- quote: "If the similarity is above consolidation_threshold (default 0.85), the LLM decides what to do: keep, update, delete, or insert_new"
- url: https://docs.crewai.com/concepts/memory
- source_type: primary (official documentation)
- published: 2024-2025
- confidence: medium (general framework)

**Implication for 32K-64K agents**: Before storing tool outputs or conversation turns in a memory buffer, deduplicate against existing entries. Consolidate similar findings to avoid redundant context.

### [11] For small context windows, system prompt and task instruction tokens must be budgeted carefully—Aider defaults to 1024 tokens for repo-map with 8x multiplier when no files are in chat
- quote: `if map_tokens is None: map_tokens = 1024`
- url: https://github.com/Aider-AI/aider/blob/main/aider/coders/base_coder.py
- source_type: primary (open-source production code)
- published: unknown
- confidence: high

**Implication for 32K-64K agents**: Reserve explicit token budgets: ~2-4K for system prompt, ~2-4K for repo context/tools description, leaving ~24-58K for conversation + tool outputs. For 32K windows, this is tight and requires aggressive tool output truncation.

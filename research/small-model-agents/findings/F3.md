# F3: Tool Calling Reliability for Small Models

## Findings

### [1] Parsing errors in agent traces reduce success rates by 21.3%
- quote: "Traces with first call parsing errors: 42.3% success rate. Traces without first call parsing errors: 51.3% success rate."
- url: https://huggingface.co/blog/structured-codeagent
- source_type: primary
- published: May 28, 2025
- confidence: high

### [2] 2.4% of agent traces contain parsing errors that cascade into failures
- quote: "2.4% of traces had parsing errors in their first call... This isn't just about convenience - parsing errors create a cascade of failures that significantly impact overall agent performance."
- url: https://huggingface.co/blog/structured-codeagent
- source_type: primary
- published: May 28, 2025
- confidence: high

### [3] Small models (7B) fail when forced into structured JSON+code generation — the "Structure Tax"
- quote: "When a smaller model (e.g. Mistral-7B-Instruct-v0.3) tries to generate structured code - the cognitive load becomes too much: the model generates syntactically broken Python code... smaller models struggle to simultaneously handle JSON formatting, Python syntax, and the actual problem-solving logic."
- url: https://huggingface.co/blog/structured-codeagent
- source_type: primary
- published: May 28, 2025
- confidence: high

### [4] Structured code generation improves capable models (32B+) by 2-7 percentage points
- quote: "Across most capable models, the structured approach consistently outperformed the regular CodeAgent approach by 2-7 percentage points on average... models need sufficient instruction-following ability and JSON coverage in their pre-training data to benefit from structured generation."
- url: https://huggingface.co/blog/structured-codeagent
- source_type: primary
- published: May 28, 2025
- confidence: high

### [5] Code agents significantly outperform JSON-based tool calling agents
- quote: "Multiple research papers have shown that having the tool calling LLMs in code is much better... we crafted our code languages specifically to be the best possible way to express actions performed by a computer."
- url: https://huggingface.co/blog/smolagents
- source_type: primary
- published: December 31, 2024
- confidence: high

### [6] Outlines guarantees structured outputs at generation time using finite-state machines, with near-zero overhead
- quote: "The approach is model agnostic, allows one to enforce domain-specific knowledge and constraints, and enables the construction of reliable interfaces by guaranteeing the structure of the generated text. It adds little overhead to the token sequence generation process and significantly outperforms existing solutions."
- url: https://arxiv.org/abs/2307.09702
- source_type: primary (peer-reviewed paper)
- published: August 19, 2023
- confidence: high

### [7] Qwen2.5-7B specifically improved structured output generation and JSON handling over predecessors
- quote: "Significant improvements in instruction following, generating long texts (over 8K tokens), understanding structured data (e.g, tables), and generating structured outputs especially JSON. More resilient to the diversity of system prompts."
- url: https://huggingface.co/Qwen/Qwen2.5-7B-Instruct
- source_type: primary
- published: September 2024
- confidence: high

### [8] Grammar-constrained generation in llama.cpp via Jinja templates enables local small-model tool calling
- quote: "Tool calling is automatically setup when you use Unsloth Studio... Unsloth also has self-healing tool-calling ensuring you always have working tool calls." llama-server supports `--jinja` flag for function calling templates with Qwen, DeepSeek, and Mistral models.
- url: https://unsloth.ai/docs/basics/tool-calling-guide-for-local-llms.md
- source_type: primary
- published: 2025
- confidence: medium

### [9] Code-based actions offer composability, object management, and generality advantages over JSON tool calls
- quote: "Writing actions in code rather than JSON-like snippets provides better composability... object management... generality... representation in LLM training data: plenty of quality code actions is already included in LLMs' training data."
- url: https://huggingface.co/blog/smolagents
- source_type: primary
- published: December 31, 2024
- confidence: high

### [10] Outlines is trusted in production by NVIDIA, Cohere, HuggingFace, and vLLM for constrained generation
- quote: "Trusted by NVIDIA, Cohere, HuggingFace, vLLM, etc." Supports regex, JSON schemas, Pydantic models, function calling, and context-free grammars as constraint types.
- url: https://github.com/dottxt-ai/outlines
- source_type: primary
- published: 2026 (v1.3.1)
- confidence: high

# F1: Prompt Engineering for Small Models

## Findings

### [1] Qwen2.5 models are specifically noted as "more resilient to diverse system prompts" compared to prior versions, improving role-play and condition-setting for chatbots
- quote: "It is also more resilient to diverse system prompts, improving role-play and condition-setting for chatbots."
- url: https://qwenlm.github.io/blog/qwen2.5/
- source_type: primary
- published: 2024-09-19
- confidence: high

### [2] Small models benefit disproportionately from instruction tuning over standard pre-training, making fine-tuned small models far more prompt-sensitive than fine-tuned large models
- quote: "MoE models benefit more from instruction tuning than dense models. ... FLAN-MOE-32B surpasses the performance of FLAN-PALM-62B on four benchmark tasks, while using only a third of the FLOPs."
- url: https://arxiv.org/abs/2305.14705
- source_type: primary (peer-reviewed)
- published: 2023-05-24
- confidence: high

### [3] DSPy compilation optimized for open small models (llama2-13b-chat) outperforms standard few-shot prompting by over 65%, and expert-created demonstrations by 16-40%
- quote: "DSPy programs compiled to open and relatively small LMs like 770M-parameter T5 and llama2-13b-chat are competitive with approaches that rely on expert-written prompt chains for proprietary GPT-3.5."
- url: https://arxiv.org/abs/2310.03714
- source_type: primary (peer-reviewed)
- published: 2023-10-05
- confidence: high

### [4] Incorrect chat templates cause "drastically worse performance" on 7B models like Mistral-7B-Instruct, demonstrating that prompt format correctness is critical for small models
- quote: "There are many possible chat formats, and different models may use different formats or control tokens, even if they were fine-tuned from the same base model! ... with the wrong control tokens, these models would have drastically worse performance."
- url: https://huggingface.co/docs/transformers/main/en/chat_templating
- source_type: primary
- published: unknown
- confidence: high

### [5] Qwen2.5-7B-Instruct tool calling uses a template inspired by Nous' Hermes, and vLLM tool calling requires the `hermes` tool-call-parser — tool definitions should follow OpenAI-compatible JSON schema format with name, description, parameters.type, parameters.properties, and required fields
- quote: "The vllm / Ollama / transformers tool calling support uses a tool calling template inspired by Nous' Hermes."
- url: https://qwenlm.github.io/blog/qwen2.5/
- source_type: primary
- published: 2024-09-19
- confidence: high

### [6] Qwen3 8B models support both thinking and non-thinking modes controllable via `enable_thinking=False` parameter or `/think` and `/no_think` instructions in system or user messages, with the latest instruction taking precedence in multi-turn conversations
- quote: "By default, Qwen3 models will think before response. This could be controlled by enable_thinking=False: Passing enable_thinking=False to tokenizer.apply_chat_template will strictly prevent the model from generating thinking content."
- url: https://github.com/QwenLM/Qwen3/blob/main/README.md
- source_type: primary
- published: 2025-04-29
- confidence: high

### [7] Mistral's function calling protocol uses a 5-step flow (developer specifies tools → user queries → model generates function arguments → developer executes → model generates answer) with tool_choice options of "auto", "any", or "none" and parallel_tool_calls boolean
- quote: "system* → user → assistant function call 1 → tool result 1 → assistant → user → ..."
- url: https://docs.mistral.ai/capabilities/function_calling/
- source_type: primary
- published: unknown
- confidence: high

### [8] Gemma 2 9B model was trained with knowledge distillation rather than next token prediction, achieving competitive performance to models 2-3 times larger, suggesting small model architecture choice matters as much as prompt engineering
- quote: "We also train the 2B and 9B models with knowledge distillation (Hinton et al., 2015) instead of next token prediction. The resulting models deliver the best performance for their size, and even offer competitive alternatives to models that are 2-3 times bigger."
- url: https://arxiv.org/abs/2408.00118
- source_type: primary (peer-reviewed)
- published: 2024-07-31
- confidence: high

### [9] Pre-filling model responses via continue_final_message with a partial JSON string (e.g., '{"name": "') improves instruction-following accuracy for small models, as they can continue structured outputs more reliably than generating them from scratch
- quote: "This is useful for 'prefilling' a model response. In the example below, the model generates text that continues the JSON string rather than starting a new message. It can be very useful for improving the accuracy of instruction following when you know how to start its replies."
- url: https://huggingface.co/docs/transformers/main/en/chat_templating
- source_type: primary
- published: unknown
- confidence: medium

### [10] Qwen2.5 models support up to 128K context windows with 8K generation length, and Qwen2.5-Coder-7B-Instruct is trained on 5.5 trillion tokens of code-related data, making specialized small coding models competitive against larger general models
- quote: "Qwen2.5-Coder has been trained on 5.5 trillion tokens of code-related data, enabling even smaller coding-specific models to deliver competitive performance against larger language models on coding evaluation benchmarks."
- url: https://qwenlm.github.io/blog/qwen2.5/
- source_type: primary
- published: 2024-09-19
- confidence: high

### [11] For Qwen3 thinking models with tool use, the SGLang and vLLM preprocessing drops `reasoning_content` fields which can make "multi-step tool use with Qwen3 thinking models may be suboptimal" — workarounds include passing thinking content as-is without extraction
- quote: "the quality of multi-step tool use with Qwen3 thinking models may be suboptimal, which requires the existence of the related thinking content. While the fixes are being worked on, as a workdaround, we recommend passing the content as it is, without extracting thinking content"
- url: https://github.com/QwenLM/Qwen3/blob/main/README.md
- source_type: primary
- published: 2025-04-29
- confidence: high

### [12] Qwen2.5 small models (3B parameters) achieve MMLU scores above 65, with the overall trend showing that newer models are getting smaller while maintaining or improving knowledge density
- quote: "Even models with just 3 billion parameters are now delivering highly competitive results. The accompanying figure illustrates a significant trend: newer models achieving scores above 65 in MMLU are increasingly smaller."
- url: https://qwenlm.github.io/blog/qwen2.5/
- source_type: primary
- published: 2024-09-19
- confidence: medium

# F5: Fine-tuning and Prompt Caching for Small Models

## Findings

### [1] QLoRA enables fine-tuning 65B models on a single 48GB GPU with no performance loss vs full 16-bit training
- quote: "QLoRA backpropagates gradients through a frozen, 4-bit quantized pretrained language model into Low Rank Adapters. Our best model family, which we name Guanaco, outperforms all previous openly released models on the Vicuna benchmark, reaching 99.3% of the performance level of ChatGPT while only requiring 24 hours of finetuning on a single GPU."
- url: https://arxiv.org/abs/2305.14314
- source_type: primary
- published: 2023-05-23
- confidence: high

### [2] Gorilla (LLaMA-7B fine-tuned for API calls) surpasses GPT-4 on API call generation by combining fine-tuning with retrieval augmentation
- quote: "We release Gorilla, a finetuned LLaMA-based model that surpasses the performance of GPT-4 on writing API calls. When combined with a document retriever, Gorilla demonstrates a strong capability to adapt to test-time document changes."
- url: https://arxiv.org/abs/2305.15334
- source_type: primary
- published: 2023-05-24
- confidence: high

### [3] ToolLLM/ToolBench generates synthetic tool-use training data via ChatGPT covering 16,464 real-world APIs across 49 categories, then fine-tunes LLaMA to achieve comparable tool-use performance to ChatGPT
- quote: "We first present ToolBench, an instruction-tuning dataset for tool use, which is constructed automatically using ChatGPT... We fine-tune LLaMA to obtain an LLM ToolLLaMA... ToolLLaMA demonstrates a remarkable ability to execute complex instructions and generalize to unseen APIs."
- url: https://arxiv.org/abs/2307.16789
- source_type: primary
- published: 2023-07-31
- confidence: high

### [4] vLLM's Automatic Prefix Caching (APC) reuses KV cache for shared prompt prefixes — enabling instant system prompt reuse across requests with `enable_prefix_caching=True`
- quote: "Automatic Prefix Caching (APC) allows the vLLM engine to reuse cached KV (key-value) pairs from previous prompts if a new query shares the same prefix. This reduces redundant computation and improves inference speed."
- url: https://docs.vllm.ai/en/stable/examples/features/automatic_prefix_caching.html
- source_type: primary
- published: unknown
- confidence: high

### [5] vLLM supports LoRA adapters served on a per-request basis with minimal overhead, enabling multiple task-specific adapters on a single base model
- quote: "LoRA adapters can be used with any vLLM model that implements SupportsLoRA. Adapters can be efficiently served on a per-request basis with minimal overhead."
- url: https://docs.vllm.ai/en/stable/features/lora.html
- source_type: primary
- published: 2026-05-18
- confidence: high

### [6] TRL's SFTTrainer natively supports fine-tuning models with tool-calling capabilities, requiring dataset examples with tool_calls messages and a tools column with JSON schemas
- quote: "The SFTTrainer fully supports fine-tuning models with tool calling capabilities. In this case, each dataset example should include: the conversation messages, including any tool calls (tool_calls) and tool responses (tool role messages), the list of available tools in the tools column, typically provided as JSON schemas."
- url: https://huggingface.co/docs/trl/main/en/sft_trainer
- source_type: primary
- published: unknown
- confidence: high

### [7] LATM (LLMs As Tool Makers) shows small models can serve as tool-users if a larger model pre-generates reusable tool functions — reducing per-request cost while maintaining GPT-4-level performance
- quote: "Tool-making requires more sophisticated capabilities, so we assign this task to a powerful, albeit resource-intensive, model. Conversely, the simpler tool-using phase is delegated to a lightweight model. This strategic division of labor allows the once-off cost of tool-making to be spread over multiple instances of tool-using."
- url: https://arxiv.org/abs/2305.17126
- source_type: primary
- published: 2023-05-26
- confidence: high

### [8] QLoRA introduces three memory-saving innovations: 4-bit NormalFloat (NF4) data type, double quantization of quantization constants, and paged optimizers for memory spike management
- quote: "QLoRA introduces a number of innovations to save memory without sacrificing performance: (a) 4-bit NormalFloat (NF4), a new data type that is information theoretically optimal for normally distributed weights (b) double quantization to reduce the average memory footprint by quantizing the quantization constants, and (c) paged optimizers to manage memory spikes."
- url: https://arxiv.org/abs/2305.14314
- source_type: primary
- published: 2023-05-23
- confidence: high

### [9] TRL SFTTrainer supports assistant_only_loss and completion_only_loss modes, allowing fine-tuning to ignore loss on system/user tokens — critical for tool-use fine-tuning where system prompts are repeated
- quote: "When the model argument of the SFTTrainer is provided as a string, the trainer will automatically apply the chat template... assistant_only_loss=True: loss is computed only on the assistant responses, ignoring user or system messages."
- url: https://huggingface.co/docs/trl/main/en/sft_trainer
- source_type: primary
- published: unknown
- confidence: high

### [10] vLLM LoRA allows restricting which model modules have LoRA applied via --lora-target-modules, and dynamically loading/unloading adapters at runtime via API endpoints
- quote: "The --lora-target-modules parameter allows you to restrict which model modules have LoRA applied at deployment time. vLLM supports dynamically configuring LoRA adapters at runtime through dedicated API endpoints and plugins."
- url: https://docs.vllm.ai/en/stable/features/lora.html
- source_type: primary
- published: 2026-05-18
- confidence: high

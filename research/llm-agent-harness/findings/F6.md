# F6: OpenAI-Compatible API Patterns

## Findings

### [1] All major small model providers expose OpenAI-compatible APIs with consistent base URL patterns
- quote: "To invoke Ollama's OpenAI compatible API endpoint, use the same OpenAI format and change the hostname to `http://localhost:11434/v1`"
- url: https://ollama.com/blog/openai-compatibility
- source_type: primary
- published: 2024-02-08
- confidence: high

### [2] API key requirement varies: Ollama requires dummy key, cloud providers require real keys
- quote: "api_key='ollama', # required, but unused"
- url: https://ollama.com/blog/openai-compatibility
- source_type: primary
- published: 2024-02-08
- confidence: high

### [3] Groq and Together AI provide full OpenAI API compatibility with identical endpoint structure
- quote: "OpenAI base URL: https://api.groq.com/openai/v1"
- url: https://docs.groq.com/docs/openai
- source_type: primary
- published: unknown
- confidence: high

### [4] Chat Completions API is the universal interface across all providers
- quote: "The primary API for interacting with OpenAI models is the Responses API" (Note: Chat Completions is the previous standard that's still widely used)
- url: https://github.com/openai/openai-node/blob/main/README.md
- source_type: primary
- published: unknown
- confidence: high

### [5] Non-standard fields in responses can break OpenAI SDK clients
- quote: "Bug: /v1 compatibility endpoint injects non-standard 'reasoning' field, breaking OpenAI clients"
- url: https://github.com/ollama/ollama/issues/16853
- source_type: community
- published: 2026-06-22
- confidence: high

### [6] Tool call arguments field has escaped double-quotes converted to single-quotes by jiter
- quote: "Tool call arguments field has escaped double-quotes converted to single-quotes by jiter"
- url: https://github.com/openai/openai-python/issues/2958
- source_type: community
- published: 2026-03-10
- confidence: high

### [7] Streaming can have issues with chunked terminator not being drained
- quote: "Streaming: connection force-closed (TCP FIN) after `[DONE]` SSE event because chunked terminator is not drained"
- url: https://github.com/openai/openai-python/issues/3440
- source_type: community
- published: 2026-06-25
- confidence: high

### [8] Empty api_key breaks local server compatibility
- quote: "AsyncOpenAI(api_key=\"\") raises OpenAIError in v2.34.0, breaking OpenAI-compatible local servers"
- url: https://github.com/openai/openai-python/issues/3224

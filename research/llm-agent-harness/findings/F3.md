# F3: MCP (Model Context Protocol)

## Findings

### [1] MCP is an open JSON-RPC 2.0 protocol with a client-server architecture connecting AI hosts to external tool/resource servers
- quote: "MCP is an open-source standard for connecting AI applications to external systems... Think of MCP like a USB-C port for AI applications."
- url: https://modelcontextprotocol.io/introduction
- source_type: primary
- published: unknown
- confidence: high

### [2] Three core server primitives: Tools (executable functions), Resources (data sources), and Prompts (interaction templates)
- quote: "MCP defines three core primitives that servers can expose: Tools: Executable functions that AI applications can invoke to perform actions; Resources: Data sources that provide contextual information to AI applications; Prompts: Reusable templates that help structure interactions with language models"
- url: https://modelcontextprotocol.io/docs/concepts/architecture
- source_type: primary
- published: unknown
- confidence: high

### [3] Tools are model-controlled (LLM discovers and invokes them automatically) with JSON Schema input definitions
- quote: "Tools in MCP are designed to be model-controlled, meaning that the language model can discover and invoke tools automatically based on its contextual understanding and the user's prompts."
- url: https://modelcontextprotocol.io/docs/concepts/tools
- source_type: primary
- published: unknown
- confidence: high

### [4] Two transport mechanisms: STDIO (local process communication) and Streamable HTTP (remote with optional SSE streaming)
- quote: "MCP supports two transport mechanisms: Stdio transport: Uses standard input/output streams for direct process communication between local processes on the same machine... Streamable HTTP transport: Uses HTTP POST for client-to-server messages with optional Server-Sent Events for streaming capabilities."
- url: https://modelcontextprotocol.io/docs/concepts/architecture
- source_type: primary
- published: unknown
- confidence: high

### [5] The TypeScript SDK is a monorepo publishing @modelcontextprotocol/server and @modelcontextprotocol/client as separate packages
- quote: "This monorepo publishes split packages: @modelcontextprotocol/server: build MCP servers; @modelcontextprotocol/client: build MCP clients. Tool and prompt schemas use Standard Schema — bring Zod v4, Valibot, ArkType, or any compatible library."
- url: https://github.com/modelcontextprotocol/typescript-sdk
- source_type: primary
- published: unknown
- confidence: high

### [6] Minimal TypeScript MCP server requires only McpServer + StdioServerTransport + registerTool call
- quote: "import { McpServer } from '@modelcontextprotocol/server'; import { StdioServerTransport } from '@modelcontextprotocol/server/stdio'; const server = new McpServer({ name: 'greeting-server', version: '1.0.0' }); server.registerTool('greet', { description: 'Greet someone by name', inputSchema: z.object({ name: z.string() }) }, async ({ name }) => ({ content: [{ type: 'text', text: `Hello, ${name}!` }] }));"
- url: https://github.com/modelcontextprotocol/typescript-sdk
- source_type: primary
- published: unknown
- confidence: high

### [7] Lifecycle management negotiates capabilities via initialize handshake before any tool/resource interaction
- quote: "MCP begins with lifecycle management through a capability negotiation handshake. The client sends an initialize request to establish the connection and negotiate supported features."
- url: https://modelcontextprotocol.io/docs/concepts/architecture
- source_type: primary
- published: unknown
- confidence: high

### [8] Tool responses return content arrays supporting text, image, audio, resource links, and embedded resources
- quote: "Tool responses return an array of content objects, allowing for rich, multi-format responses (text, images, resources, etc.). Each content object has a type field."
- url: https://modelcontextprotocol.io/docs/concepts/tools
- source_type: primary
- published: unknown
- confidence: high

### [9] Client primitives include Sampling (server requests LLM completions), Elicitation (server requests user input), and Logging
- quote: "MCP also defines primitives that clients can expose: Sampling: Allows servers to request language model completions from the client's AI application; Elicitation: Allows servers to request additional information from users."
- url: https://modelcontextprotocol.io/docs/concepts/architecture
- source_type: primary
- published: unknown
- confidence: high

### [10] TypeScript SDK v2 is in beta targeting the 2026-07-28 spec; v1.x remains production-supported
- quote: "This is the main branch — v2 of the SDK, now in beta (@modelcontextprotocol/server, @modelcontextprotocol/client), implementing the 2026-07-28 MCP spec. We expect a stable release alongside the full release of the 2026-07-28 spec on July 28, 2026."
- url: https://github.com/modelcontextprotocol/typescript-sdk
- source_type: primary
- published: 2026-07-16
- confidence: high

### [11] Resources are application-driven (not model-controlled) and identified by URIs with subscribe and listChanged capabilities
- quote: "Resources in MCP are designed to be application-driven, with host applications determining how to incorporate context based on their needs. Each resource is uniquely identified by a URI."
- url: https://modelcontextprotocol.io/docs/concepts/resources
- source_type: primary
- published: unknown
- confidence: high

### [12] Prompts are user-controlled, typically exposed as slash commands, with arguments for customization
- quote: "Prompts are designed to be user-controlled, meaning they are exposed from servers to clients with the intention of the user being able to explicitly select them for use. Typically, prompts would be triggered through user-initiated commands in the user interface."
- url: https://modelcontextprotocol.io/docs/concepts/prompts
- source_type: primary
- published: unknown
- confidence: high

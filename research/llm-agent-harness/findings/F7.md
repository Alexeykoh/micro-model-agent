# F7: Context Management for Small Models

## Findings

### [1] Context management is the primary bottleneck for long-horizon LLM agents, not model capability — naive plan eviction cuts success by 34.7pp while the plan is context-resident rather than persistent state
- quote: "standard LLM agents do not carry plans forward as persistent state, and instead depend on the plan remaining in context... naive plan eviction cuts ALFWorld success by 34.7pp"
- url: https://arxiv.org/abs/2606.22953
- source_type: primary
- published: 2026-06-22
- confidence: high

### [2] Reversible elastic context management (ACE) outperforms both truncation and summarization by maintaining raw+compressed copies and adaptively assigning raw/abstract/drop per step based on current task state
- quote: "ACE maintains a lossless message maintenance layer that stores both raw messages and compressed abstractions for each historical step, while a context orchestration layer adaptively assigns each step an elastic type as raw, abstract, or drop... this reversible design ensures that the main LLM always receives a compact yet information-rich context"
- url: https://arxiv.org/abs/2606.31564
- source_type: primary
- published: 2026-06-30
- confidence: high

### [3] Deterministic LLM-free eviction using dependency-linked typed episodes achieves effectively unbounded working horizons — single session completed 89 tasks across 80M tokens with no accuracy degradation
- quote: "a deterministic, LLM-free policy evicts content in priority order within that structure when a token budget is exceeded... a single agent session completing 89 sequential tasks across 80 million tokens with no measurable degradation in task accuracy"
- url: https://arxiv.org/abs/2606.11213
- source_type: primary
- published: 2026-05-01
- confidence: high

### [4] VISTA's training-free "proprioceptive dashboard" lifts small models dramatically — Gemini-3-Flash goes from 22.7% to 50.7% by exposing per-block token usage, recency, and access history so the model can self-manage context
- quote: "Frontier language models are proprioceptively blind to their own context. From the prompt alone they cannot see how large, how old, or how used each block is... lifts Gemini-3-Flash from 22.7 to 50.7%"
- url: https://arxiv.org/abs/2606.30005
- source_type: primary
- published: 2026-06-29
- confidence: high

### [5] Dependency-structured memory (ContextWeaver) outperforms sliding-window baselines while reducing both reasoning steps and token usage — modeling logical dependencies provides a stable, scalable memory mechanism
- quote: "ContextWeaver improves performance over a sliding-window baseline in pass@1, while reducing reasoning steps and token usage... modeling logical dependencies provides a stable and scalable memory mechanism"
- url: https://arxiv.org/abs/2604.23069
- source_type: primary
- published: 2026-04-24
- confidence: high

### [6] HYVE achieves 50-90% token reduction through preprocessing/postprocessing around model calls using columnar/row hybrid views and a request-scoped datastore — an "effectively unbounded context window" for data-heavy prompts
- quote: "HYVE reduces token usage by 50-90% while maintaining or improving output quality... offers a practical approximation to an effectively unbounded context window for prompts dominated by large machine-data payloads"
- url: https://arxiv.org/abs/2604.05400
- source_type: primary
- published: 2026-04-06
- confidence: high

### [7] Tool result truncation is critical — DADL reduces tool advertisement cost from ~142K tokens to ~1K tokens (142x) by using a fixed-size Code Mode interface independent of catalog size
- quote: "Code Mode reduces the context cost of tool advertisement from approximately 142,000 tokens to approximately 1,000, a 142x reduction"
- url: https://arxiv.org/abs/2605.05247
- source_type: primary
- published: 2026-05-04
- confidence: medium

### [8] Giving agents active control over their own memory storage (via tool calls to flat files) outperforms passive memory stores behind fixed pipelines — AutoMEM achieves best cross-scenario generality
- quote: "the harness, which self-manages flat text-file storage via tool calls, achieves the best cross-task ranking, suggesting that memory performance hinges on giving the agent active control over storage and retrieval rather than on a passive store behind a fixed pipeline"
- url: https://arxiv.org/abs/2606.04315
- source_type: primary
- published: 2026-06-02
- confidence: high

### [9] ClawVM treats context management like OS virtual memory with typed pages, minimum-fidelity invariants, and multi-resolution representations — eliminates all policy-controllable faults with <50μs overhead per turn
- quote: "a virtual memory layer that manages state as typed pages with minimum-fidelity invariants, multi-resolution representations under a token budget... eliminates all policy-controllable faults"
- url: https://arxiv.org/abs/2604.10352
- source_type: primary
- published: 2026-04-11
- confidence: medium

### [10] Episodic-semantic dual process memory maintains 70-85% accuracy with 62% fewer tokens (45K vs 120K+) using a constant 10-message episodic window plus growing semantic consolidation at ~3 tokens/message
- quote: "full-context models fail at 10,000 messages due to context overflow, our system maintains 70-85% accuracy with 1-2 second latency using 62% fewer tokens (45,434 vs 120,000+ limit)"
- url: https://arxiv.org/abs/2605.17625
- source_type: primary
- published: 2026-05-17
- confidence: high

### [11] The "lost in the middle" phenomenon means LLMs systematically under-attend to information in the middle of long inputs — hierarchical progressive disclosure (A2X) achieves 6.2-point Hit Rate gain at 1/9th the prompt-token cost
- quote: "LLMs face a structural mismatch with this regime: effective context is a scarce resource that does not scale with the number of services... models systematically under-attend to information in the middle of long inputs"
- url: https://arxiv.org/abs/2605.29270
- source_type: primary
- published: 2026-05-27
- confidence: high

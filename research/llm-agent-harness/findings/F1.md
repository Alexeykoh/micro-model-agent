# F1: OpenCode Architecture

## Findings

### [1] OpenCode has TWO distinct incarnations: an archived Go project and a current TypeScript/Node.js project
- The original `opencode-ai/opencode` (Go, 13.5k stars, archived Sep 2025) was renamed to Crush under `charmbracelet/crush` (26.6k stars, actively developed). The current `opencode.ai` (by Anomaly) is a separate TypeScript/Node.js project with 160k+ GitHub stars, installable via npm/bun/pnpm.
- url: https://github.com/opencode-ai/opencode
- source_type: primary
- published: 2025-09-18 (archive date)
- confidence: high

### [2] The original Go-based OpenCode used a modular internal architecture with clear separation of concerns
- Architecture directories: `cmd` (Cobra CLI), `internal/app` (core services), `internal/config`, `internal/db` (SQLite + sqlc), `internal/llm` (providers, tools, agent, models, prompt), `internal/tui` (Bubble Tea), `internal/message`, `internal/session`, `internal/lsp`.
- quote: "OpenCode is built with a modular architecture: cmd, internal/app, internal/config, internal/db, internal/llm, internal/tui, internal/logging, internal/message, internal/session, internal/lsp"
- url: https://github.com/opencode-ai/opencode
- source_type: primary
- published: unknown
- confidence: high

### [3] The Go version supported 8 provider implementations as separate files with a common provider interface
- Each provider (Anthropic, OpenAI, Azure, Bedrock, Copilot, Gemini, VertexAI, Groq) was a separate `.go` file under `internal/llm/provider/`, suggesting a common `Provider` interface or abstract type that each implements. This is the core multi-provider abstraction.
- url: https://github.com/opencode-ai/opencode/tree/main/internal/llm/provider
- source_type: primary
- published: unknown
- confidence: high

### [4] Tool calling uses a registry pattern with each tool as a separate file
- 12 built-in tools: bash, diagnostics, edit, fetch, glob, grep, ls, patch, sourcegraph, view, write, plus an `agent` tool for sub-tasks. Each is a separate `.go` file under `internal/llm/tools/` with a shared `tools.go` registry. MCP tools are merged into the same tool list at runtime.
- quote: "Tool Integration: AI can execute commands, search files, and modify code"
- url: https://github.com/opencode-ai/opencode/tree/main/internal/llm/tools
- source_type: primary
- published: unknown
- confidence: high

### [5] OpenCode uses a three-agent architecture: coder, task, and title
- The config defines three agent roles, each with its own model and maxTokens: `coder` (main coding agent), `task` (sub-task agent, the `agent` tool), and `title` (generates session titles, capped at 80 tokens). This is a lightweight multi-agent pattern.
- quote: "\"agents\": { \"coder\": { \"model\": \"claude-3.7-sonnet\", \"maxTokens\": 5000 }, \"task\": { \"model\": \"claude-3.7-sonnet\", \"maxTokens\": 5000 }, \"title\": { \"model\": \"claude-3.7-sonnet\", \"maxTokens\": 80 } }"
- url: https://github.com/opencode-ai/opencode
- source_type: primary
- published: unknown
- confidence: high

### [6] Auto-compact feature handles context window limits by summarizing at 95% usage
- OpenCode monitors token usage and automatically triggers summarization when usage reaches 95% of the model's context window, creating a new session with the summary to continue work without losing context. This is critical for small-context models.
- quote: "Automatically triggers summarization when usage reaches 95% of the model's context window. Creates a new session with the summary, allowing you to continue your work without losing context."
- url: https://github.com/opencode-ai/opencode
- source_type: primary
- published: unknown
- confidence: high

### [7] The Crush successor uses a provider type system with openai, openai-compat, anthropic, llamacpp, omlx, lmstudio, litellm, ollama
- Crush distinguishes `openai` (proxy/routing through OpenAI) from `openai-compat` (non-OpenAI providers with OpenAI-compatible APIs). Custom providers define models with cost_per_1m_in/out, context_window, default_max_tokens, can_reason, supports_attachments fields.
- quote: "openai should be used when proxying or routing requests through OpenAI. openai-compat should be used when using non-OpenAI providers that have OpenAI-compatible APIs."
- url: https://github.com/charmbracelet/crush
- source_type: primary
- published: unknown
- confidence: high

### [8] MCP support enables extensibility via stdio, SSE, and HTTP transports
- Both the Go version and Crush support MCP (Model Context Protocol) with three transport types: stdio (local process), SSE, and HTTP. MCP tools are automatically discovered and merged with built-in tools under the same permission model. Crush adds shell-style value expansion in config for secrets.
- quote: "Once configured, MCP tools are automatically available to the AI assistant alongside built-in tools. They follow the same permission model as other tools, requiring user approval before execution."
- url: https://github.com/opencode-ai/opencode
- source_type: primary
- published: unknown
- confidence: high

### [9] Session persistence uses SQLite via sqlc for type-safe database access
- The Go version uses SQLite for persistent storage of conversations and sessions, with sqlc for type-safe Go code generation from SQL queries. This provides conversation history, session management, and file change tracking across sessions.
- quote: "Persistent Storage: SQLite database for storing conversations and sessions"
- url: https://github.com/opencode-ai/opencode
- source_type: primary
- published: unknown
- confidence: high

### [10] LSP integration provides diagnostics-as-context for the AI agent
- OpenCode connects to Language Server Protocol servers (gopls, typescript-language-server, etc.) to get diagnostics (errors, warnings) and inject them into the AI's context. Currently only diagnostics are exposed to the AI, though the LSP client supports the full protocol.
- quote: "While the LSP client implementation supports the full LSP protocol (including completions, hover, definition, etc.), currently only diagnostics are exposed to the AI assistant."
- url: https://github.com/opencode-ai/opencode
- source_type: primary
- published: unknown
- confidence: high

### [11] The current opencode.ai (Anomaly) is TypeScript-based with npm distribution
- The active OpenCode project at opencode.ai by Anomaly is distributed via npm (`npm install -g opencode-ai`), supporting bun, pnpm, yarn. It offers TUI, desktop app, and IDE extension. It supports 75+ LLM providers through Models.dev integration.
- quote: "npm install -g opencode-ai ... 75+ LLM providers through Models.dev, including local models"
- url: https://opencode.ai/docs/
- source_type: primary
- published: 2026-07-14
- confidence: high

### [12] Crush supports auto-discovery of local models from ollama, llama.cpp, lmstudio, litellm
- Local model providers auto-discover available models by querying the provider's API endpoint. Users can also manually configure models which take precedence over discovered ones. The `discover_models` flag enables merging.
- quote: "Crush auto-discovers models from local providers. Add a custom provider with type set to llamacpp, omlx, lmstudio, litellm, or ollama and leave out the models list."
- url: https://github.com/charmbracelet/crush
- source_type: primary
- published: unknown
- confidence: high

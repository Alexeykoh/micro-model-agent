# F8: Tool Calling with Small Models

## Findings

### [1] Code-based actions (CodeAct) outperform JSON tool calling by up to 20% success rate across 17 LLMs
- quote: "CodeAct outperforms widely used alternatives (up to 20% higher success rate)"
- url: https://arxiv.org/abs/2402.01030
- source_type: primary
- published: 2024-02-01
- confidence: high

### [2] Structured JSON output creates a "structure tax" on small models — smaller models break when forced to simultaneously handle JSON formatting + Python syntax + problem-solving
- quote: "Smaller models struggle to simultaneously handle JSON formatting, Python syntax, and the actual problem-solving logic. The cognitive overhead of structured generation can overwhelm models that would otherwise perform reasonably well with simpler markdown-based code generation."
- url: https://huggingface.co/blog/structured-codeagent
- source_type: primary
- published: 2025-05-28
- confidence: high

### [3] Traces with first-call parsing errors succeed 21.3% less often — parsing reliability is critical for small models that error-recover poorly
- quote: "Traces with first call parsing errors: 42.3% success rate. Traces without first call parsing errors: 51.3% success rate. Agent traces without parsing errors succeed 21.3% more often."
- url: https://huggingface.co/blog/structured-codeagent
- source_type: primary
- published: 2025-05-28
- confidence: high

### [4] For small models (<32B params), plain code generation (markdown code blocks) outperforms structured JSON output — the "structure tax" threshold is ~32B
- quote: "Qwen models: Generally improve with structure, though 'structure tax' creeps in for smaller models." / "Use Structured CodeAgents when: Working with capable models (32B+ parameters or frontier models)"
- url: https://huggingface.co/blog/structured-codeagent
- source_type: primary
- published: 2025-05-28
- confidence: high

### [5] Anthropic's tool design principle: "poka-yoke" your tools — change arguments to make mistakes harder; use absolute paths, restrict valid values
- quote: "Poka-yoke your tools. Change the arguments so that it is harder to make mistakes. For example, we found that the model would make mistakes with tools using relative filepaths... we changed the tool to always require absolute filepaths—and we found that the model used this method flawlessly."
- url: https://www.anthropic.com/research/building-effective-agents
- source_type: primary
- published: 2024-12-19
- confidence: high

### [6] Tool definitions need prompt-engineering at the same depth as system prompts — include examples, edge cases, and boundaries in tool descriptions
- quote: "A good tool definition often includes example usage, edge cases, input format requirements, and clear boundaries from other tools. Put yourself in the model's shoes. Is it obvious how to use this tool... if so, then it's probably also true for the model."
- url: https://www.anthropic.com/research/building-effective-agents
- source_type: primary
- published: 2024-12-19
- confidence: high

### [7] Keep tool/action formats close to natural text the model saw in training — avoid formats requiring escape characters, exact counts, or complex nesting
- quote: "Keep the format close to what the model has seen naturally occurring in text on the internet. Make sure there's no formatting 'overhead' such as having to keep an accurate count of thousands of lines of code, or string-escaping any code it writes."
- url: https://www.anthropic.com/research/building-effective-agents
- source_type: primary
- published: 2024-12-19
- confidence: high

### [8] Open-source models can rival closed models on agentic tasks when using code-based action patterns rather than JSON tool calling
- quote: "This comparison shows that open source models can now take on the best closed models!"
- url: https://huggingface.co/blog/smolagents
- source_type: primary
- published: 2024-12-31
- confidence: medium

### [9] For small models, prefer fewer tools with simpler schemas — the structure tax means complex parameter nesting and many tool choices degrade performance
- quote: "Models need sufficient instruction-following ability and JSON coverage in their pre-training data to benefit from structured generation. This suggests that structured approaches work best with: Large, well-trained models, Models with strong instruction-following capabilities, Models fine-tuned on structured generation."
- url: https://huggingface.co/blog/structured-codeagent
- source_type: primary
- published: 2025-05-28
- confidence: high

### [10] Anthropic recommends starting with simplest patterns (single LLM call + retrieval + in-context examples) and only adding agentic complexity when measurably needed
- quote: "We recommend finding the simplest solution possible, and only increasing complexity when needed. For many applications, however, optimizing single LLM calls with retrieval and in-context examples is usually enough."
- url: https://www.anthropic.com/research/building-effective-agents
- source_type: primary
- published: 2024-12-19
- confidence: high

### [11] When using structured output for code agents, enforce a "thoughts" field before "code" — this forces explicit reasoning that catches errors early
- quote: "The use of structured generation and explicit thoughts not just prompts, but forces agents to articulate their reasoning before acting. This leads to: Better planning, Enhanced reliability."
- url: https://huggingface.co/blog/structured-codeagent
- source_type: primary
- published: 2025-05-28
- confidence: medium

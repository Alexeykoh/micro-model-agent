# Анализ лога: Parfum Landing SPA

## Почему модель остановилась

Последний вызов — `npm run dev`. Dev server запускается навсегда и не завершается. Tool timeout (120 сек) сработал, модель получила пустой/обрезанный вывод и застряла в пустых ответах.

---

## Что пошло не так

### 1. Пустые ответы — катастрофа

Из ~25 ходов модели — **15+ пустых ответов** (reasoning chunks без content). Emergency retry с temperature=0.1 помогал в ~60% случаев, но тратил 2-3 прогона на каждый ход. Модель буквально половину времени генерировала thinking но не могла выдать ответ.

### 2. Синтаксическая ошибка — застряла

```
main.jsx: Line 1: Unexpected token
```

Модель писала TypeScript (`import App from './App.tsx'`) в `.jsx` файл. Syntax checker блокировал запись. Модель **3 раза** пыталась перезаписать тот же файл с той же ошибкой, не анализируя为什么 блокируется. Specialist не сработал (ошибка была "trivial" — < 15 символов в stderr).

### 3. Хаос в файлах

```
src/
  App.tsx          ← от vite template
  App.tsx          ← от subagent (дубликат!)
  components/
    App.tsx        ← ЕЩЁ один App.tsx!
    AppWrapper.tsx ← зачем?
  index.ts         ← от subagent (лишний)
  utils.ts         ← от subagent (пустой, зачем?)
  main.jsx         ← с ошибкой
```

4 файла `App.tsx` в разных местах. Суб-агент создавал файлы не глядя на существующие.

### 4. Суб-агенты работали плохо

- Первый суб-агент: создал `Navbar.tsx`, `Footer.tsx`, `ProductCard.tsx` — нормально
- Второй: создал `ProductDetail.tsx` + `ProductDetail.css` + `index.ts` (лишний)
- Третий: создал `AppWrapper.tsx` + ЕЩЁ `App.tsx` + `index.ts` + `utils.ts` — наплодил мусора
- Четвёртый: "Исправить main.jsx" — **не сделал ничего** (0 файлов, прочитал и ушёл)

### 5. Нет tsconfig.json

Vite template создаёт `tsconfig.json` и `tsconfig.app.json`. Но модель не нашла их (видимо, subagent изменил структуру). Без tsconfig — TypeScript не работает.

---

## Общая оценка

| Аспект | Оценка |
|--------|--------|
| Пустые ответы | Критично — 60% ходов в пустую |
| Понимание ошибок | Плохо — повторяет одни и те же ошибки |
| Работа с файлами | Плохо — создаёт дубликаты, не проверяет существование |
| Суб-агенты | Смешанно — иногда помогают, иногда плодят мусор |
| Планирование | Нет — модель прыгает между задачами без плана |

---

## Что нужно улучшить

### Быстрые фиксы

1. **isTrivialError**: синтаксические ошибки ("Unexpected token", "SyntaxError") не должны быть trivial — specialist должен их разбирать
2. **Syntax checker + main.jsx**: модель не понимает что `.jsx` ≠ `.tsx`. Добавить в system prompt: "Use .tsx for TypeScript, .jsx for plain JavaScript"
3. **Dev server detection**: если bash команда содержит `npm run dev`, `vite`, `webpack serve` — не ждать завершения, а вернуть "Server started" после 5 секунд
4. **File duplicate detection**: перед write_file проверять существует ли файл, и если да — использовать edit_file

### Средние фиксы

5. **Subagent context**: суб-агент должен получать список УЖЕ созданных файлов чтобы не дублировать
6. **Plan enforcement**: модель должна завершить текущий шаг перед переходом к следующему
7. **Empty response escalation**: после 5+ пустых ответов — предложить пользователю сменить модель или уменьшить контекст

### Долгосрочные

8. **Two-model pipeline**: маленькая модель для планирования, большая для execution
9. **File system state tracking**: отслеживать какие файлы уже созданы в сессии
10. **Dev server wrapper**: автоматически детектить long-running commands и обрабатывать их

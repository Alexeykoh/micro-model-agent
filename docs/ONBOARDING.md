# Онбординг: как устроен MMA

Карта проекта для нового разработчика: как работает агент, из чего состоит и что уже
умеет. Без деталей — детали в [AGENTS.md](../AGENTS.md) и
[architecture v2](./specs/2026-10-12-architecture-v2-design.md). Установка и процесс —
в [CONTRIBUTING.md](../CONTRIBUTING.md).

## Что это

MMA — каркас (harness) для LLM-агента под небольшие модели: 32K–64K контекста.
Модель внешняя, общается по OpenAI-совместимому API. Каркас даёт ей тулы, память,
сессии, проверки и несколько поверхностей: терминал, браузер, HTTP-сервис.
Проект в бете: версии только `0.x.y`.

Агент не привязан к разработке кода: код — один из сценариев наравне с погодой,
API и умным домом.

## Термины

| Слово          | Что это                                                                                                    |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| Агент          | Объект `Agent`, который ведёт диалог: думает, зовёт тулы, проверяет себя.                                  |
| Поверхность    | Интерфейс к агенту: терминал (`mma`), браузер (`mma web`), HTTP (`mma serve`), разовый запуск (`mma "…"`). |
| Ядро           | `src/core` — код, без которого агент не работает.                                                          |
| Модуль         | Подсистема, которую можно отключить и продолжить работать.                                                 |
| Тул            | Функция, которую модель просит выполнить: прочитать файл, запустить команду, открыть сайт.                 |
| Провайдер      | Сервер с моделью по OpenAI-совместимому API: llama.cpp, LM Studio, облако.                                 |
| Сессия         | Один диалог с историей на диске.                                                                           |
| Контекст       | То, что реально уходит модели в запросе.                                                                   |
| Бюджет токенов | Сколько места в контексте отведено под инструкции, запас и историю.                                        |
| Компакция      | Сжатие старой истории в резюме, когда контекст заполнен.                                                   |
| Гейт           | Автоматическая проверка хода перед показом ответа.                                                         |
| Критик         | Вторая модель, которая ревьюит ход по фактам из тулов.                                                     |
| План           | Чеклист шагов задачи; лежит на диске, а не в контексте.                                                    |
| Субагент       | Отдельный агент, которому делегируют подзадачу.                                                            |
| Скилл          | Набор инструкций, который агент подгружает по необходимости.                                               |
| Плагин         | Внешний код, подписанный на события жизненного цикла.                                                      |
| MCP            | Протокол для внешних серверов с тулами.                                                                    |
| Пайплайн       | Многошаговый сценарий из YAML.                                                                             |
| Артефакт       | Файл с результатом (например, полный ответ субагента), на который ссылаются вместо пересказа.              |

## Один ход агента

Ход состоит из шести фаз: `INIT → THINK → OBSERVE → VERIFY → OUTPUT → ERROR`.

- **INIT** — собрать контекст: системный промпт, история, память, карта проекта, план.
- **THINK** — запрос к модели: текст или просьба вызвать тулы.
- **OBSERVE** — тулы исполняются через `ToolExecutor`, результаты уходят в контекст.
- **VERIFY** — гейты: галлюцинации, критик, аудит плана.
- **OUTPUT** — ответ пользователю и запись в `session.jsonl`.
- **ERROR** — восстановление после сбоя провайдера или обрыва генерации.

THINK ⇄ OBSERVE крутится, пока модель не ответит без тулов. Все гейты стоят **внутри**
одной петли `Agent.run` — второго пути исполнения нет.

## Слои

Запрос идёт сверху вниз: поверхность → ядро → модули.

| Слой        | Где                                                   | Что внутри                                                                              |
| ----------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Поверхности | `src/cli`, `src/modules/webui`, `src/modules/service` | REPL, `mma web`, `mma serve`, one-shot — все зовут один `Agent.run`                     |
| Ядро        | `src/core`                                            | петля, промпт, `ToolExecutor`, контекст, конфиг, наблюдаемость, `ModuleHost`            |
| Модули      | `src/modules`                                         | всё отключаемое: провайдеры, LSP, браузер, память, скиллы, MCP, индексатор, веб, сервис |

Граница простая: **можно ли отключить и продолжить работать?** Да — модуль, нет — ядро.
Модуль видит ядро только через `src/core/api/`; импорт `core/agent/*` ему запрещён.
Рядом два самостоятельных слоя: `src/llm/` (общение с моделью) и `src/output/`
(события вывода; в терминал печатает только `OutputChannel`).

## Путь одного сообщения

1. Поверхность вызывает `Agent.run()`.
2. `PromptAssembler` собирает системный промпт из блоков ядра и модулей.
3. `ContextManager` добавляет историю и следит за бюджетом токенов.
4. `LLMProvider` шлёт запрос: стрим, при пустом ответе — повтор без стрима.
5. Модель просит тул → `ToolExecutor.execute()` проверяет политику и вызывает хендлер.
6. Результат возвращается в контекст; шаги 4–6 повторяются.
7. Ответ уходит событиями в `OutputBus`: `OutputChannel` печатает его, `SessionLogger`
   пишет в `session.jsonl`.

## Что агент умеет

**Тулы.** Модель просит их по имени; всё, что меняет файлы или ходит в сеть, проходит
проверки.

| Группа        | Тулы                                                                                                                      | Что делают                                              |
| ------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| Файлы         | `read_file`, `write_file`, `edit_file`, `list_dir`, `glob`, `grep`, `file_info`, `move_file`, `delete_file`, `create_dir` | читают, ищут, меняют файлы                              |
| Команды       | `bash`                                                                                                                    | запускает команды; долгий процесс уходит в фон          |
| Процессы      | `process_list`, `process_log`, `process_wait`, `process_kill`                                                             | следят за фоновыми процессами и гасят их                |
| Интернет      | `web_search`, `web_fetch`, `web_browse`, `download_file`                                                                  | ищут, читают страницы, качают файлы                     |
| Браузер       | `browser`                                                                                                                 | кликает и заполняет формы, элементы пронумерованы       |
| Картинки      | `attach_image`                                                                                                            | прикрепляет изображение к сообщению                     |
| Делегирование | `subagent`                                                                                                                | отдельный агент на подзадачу, со своей зоной файлов     |
| Текст         | `chunk_query`                                                                                                             | режет большой текст на куски и обрабатывает параллельно |
| Документы     | `document_map`, `document_read`, `document_index`, `document_find`                                                        | PDF, офисные файлы, таблицы, картинки                   |
| Память        | `remember`, `recall`, `search_history`, `session_info`                                                                    | запоминает, вспоминает, ищет по истории сессий          |
| Работа        | `plan`, `plan_step`, `todo`, `verify`, `project_map`, `lsp_check`, `set_thinking`                                         | план, проверки, карта проекта, диагностика кода         |
| Вопросы       | `question`, `approve`                                                                                                     | спрашивает пользователя, просит подтверждение           |
| Расширения    | `mcp_call`, `pipeline_run`, `load_skill`, `enable_tools`                                                                  | MCP-сервер, пайплайн, скилл, включение скрытых тулов    |

**Экономия контекста.** Набор тулов сужается по типу задачи (`enable_tools` включает
скрытые) · бюджет токенов считается от окна модели · компакция запускается при
заполнении истории, свежие 6 обменов остаются целиком · после компакции якоря
`[Task:]`, `[Plan:]`, `[Files:]`, `[Errors:]` восстанавливаются из диска.

**Память.** Три горизонта: контекст хода → сессия на диске (`history.jsonl`,
`session.jsonl`) → постоянная память проекта (`conventions.md`, `decisions.md`,
`errors.md`). Плюс карта проекта с кэшем и артефакты субагентов.

**Гарантии работы.** План лежит на диске у каждой сессии; шаг закрывается только по
факту: `file-exists`, `command`, `http` или `manual` · детектор застревания ·
финальный аудит перед ответом · проверка синтаксиса и типов сразу после записи ·
LSP-диагностика после правки.

**Надёжность связи.** Повторы с бэкоффом на 429/5xx · fallback со стрима на обычный
запрос · восстановление после обрыва генерации · failover между провайдерами ·
переключение модели «на горячую» · кэш промпта и подсчёт реальных токенов · стоимость
сессии и баланс провайдера.

**Честность.** Гейт галлюцинаций (пути, артефакты, консистентность, ложное «готово») ·
критик с evidence — фактами из тулов · honest-stop при серии провалов · бюджет
повторов тула · всё это видно в `session.jsonl`.

**Безопасность.** Валидаторы команд, путей, сети и содержимого · защищённые пути
(`.git/`, `.env*`, ключи) работают всегда · зоны субагентов · пресеты `strict` /
`balanced` / `permissive` · аудит-журнал и уведомления · шифрование сессий ·
SSRF-guard · **DLP**: маскировка путей, секретов и персональных данных перед отправкой
провайдеру (E1) и в ответах API (E2), с бейджем за ход.

**Расширения.** Скиллы с прогрессивной загрузкой · плагины с хуками жизненного цикла
и изоляцией ошибок · MCP-серверы с ленивым подключением · пайплайны из YAML.

**Поверхности.** REPL со своим редактором строки · `mma web` (SSE + REST, параллельные
сессии, вкладки files/LSP/trace/plugins/map) · `mma serve` (HTTP API) · `mma setup`,
`mma meet`, `mma agents init` · сессии: список, поиск, экспорт · автообновление из
GitHub Releases · сертификация моделей · миграция с v1 · краш-логи.

## Модули

| Группа      | Модули                                                         | Что дают                                                      |
| ----------- | -------------------------------------------------------------- | ------------------------------------------------------------- |
| Модель      | `providers`, `reasoning`, `pricing`, `certification`           | провайдеры, стратегия reasoning, стоимость, проверка модели   |
| Контекст    | `session`, `memory`, `skills`, `documents`, `indexer`          | сессии, память, скиллы, документы, карта репозитория          |
| Действия    | `execution`, `processes`, `browser`, `lsp`, `mcp`, `pipelines` | план и аудит, процессы, браузер, диагностика, MCP, DAG        |
| Защита      | `security`, `critic`                                           | политики, DLP и аудит; LLM-ревью хода                         |
| Поверхности | `webui`, `service`, `setup`, `onboarding`, `updater`           | веб-UI, HTTP API, мастер настройки, первый запуск, обновления |
| Расширения  | `plugins`, `artifacts`, `user-profile`                         | сторонние плагины, артефакты, профиль пользователя            |

Модуль объявляет себя через `ModuleDef` на `ModuleHost`: жизненный цикл, тулы, блоки
промпта, хуки. Подключение — в фазах `src/core/bootstrap/`.

## Куда класть изменения

| Задача               | Куда                                                                      |
| -------------------- | ------------------------------------------------------------------------- |
| Новый тул            | `src/tools/<name>.ts` + регистрация в `src/tools/index.ts`                |
| Новый ключ конфига   | `src/config/registry-extra.ts`                                            |
| Новая slash-команда  | каталог `src/core/commands/` + хендлер в `src/cli/repl-commands*.ts`      |
| Новый модуль         | `src/modules/<name>/` + фаза bootstrap, решение `critical?` / `teardown?` |
| Новое событие в логе | тип в `src/core/types.ts` + запись через `SessionLogger` (+ `module`)     |

## Пять инвариантов

1. **Одна точка политики** — проверки в `ToolExecutor.execute()`, не в хендлерах.
   Новый тул обязан объявить `security: { caps, … }`.
2. **Один писатель терминала** — в `src/` нет `console.*`, только `OutputBus`.
3. **Один путь конфига** — запись через `ConfigStore.set`, возвращающий эффекты.
4. **Один источник правды** — конфиг `registry-extra.ts`, тулы `tools/index.ts`,
   провайдеры `BUILTIN_PROVIDERS`, состояние веба — SSE-событие.
5. **Инвариант без проверки не существует** — новое правило сразу получает тест или
   гвард в `tests/arch/`.

Плюс стиль: TypeScript strict без `as any`, строки пользователю только через `t()`
(ключи `en`/`ru` симметричны), файл больше 300 строк — режем.

## Цикл разработки

```bash
bun install
bun run mma setup        # провайдер, ключ, модель
bun run mma              # REPL; bun run web:dev — веб с watch
bun test                 # тесты
bun run quality          # typecheck + фронтенд + арх-гейты + lint + fallow
```

- Ветка от `dev`: `<type>/<краткое>`; `master` — только релиз.
- Изменение поведения = тест, который падал бы без правки.
- Меняется контракт (данные, граница модуля, событие, конфиг) — сначала спека в
  `docs/specs/`, потом код.
- Отложенный костыль — запись в [debt.md](./agents/debt.md), а не «потом».

## Аббревиатуры

| Сокращение | Расшифровка                         | Что значит в проекте                                                                     |
| ---------- | ----------------------------------- | ---------------------------------------------------------------------------------------- |
| MMA        | Micro Models Agent                  | Название проекта и бинаря (`mma`)                                                        |
| LLM        | Large Language Model                | Большая языковая модель — внешний «мозг» агента                                          |
| API        | Application Programming Interface   | Программный интерфейс: провайдера, `mma serve`, модулей                                  |
| CLI        | Command Line Interface              | Запуск из терминала: `mma …`, `mma web`, `mma serve`                                     |
| REPL       | Read–Eval–Print Loop                | Интерактивный режим: ввод → ответ → приглашение                                          |
| TUI        | Terminal User Interface             | Полноэкранный интерфейс; в MMA **запрещён**                                              |
| SSE        | Server-Sent Events                  | Поток событий сервер → браузер, на нём веб-UI                                            |
| REST       | Representational State Transfer     | Обычный HTTP-API: методы и пути                                                          |
| JSONL      | JSON Lines                          | Файл, где каждая строка — отдельный JSON; так пишется `session.jsonl`                    |
| MCP        | Model Context Protocol              | Протокол подключения внешних серверов с тулами                                           |
| LSP        | Language Server Protocol            | Протокол языковых серверов; даёт диагностику кода                                        |
| DLP        | Data Loss Prevention                | Защита от утечки данных: маскировка секретов, путей, PII перед отправкой                 |
| PII        | Personally Identifiable Information | Персональные данные: телефон, e-mail, СНИЛС, ИНН и т.п.                                  |
| NER        | Named Entity Recognition            | Распознавание сущностей в тексте (нужно поиску PII)                                      |
| egress     | Исходящий трафик                    | Всё, что уходит с машины: запросы к провайдеру и API                                     |
| SSRF       | Server-Side Request Forgery         | Атака запросом сервера во внутреннюю сеть; от неё стоит guard                            |
| RLM        | Recursive Language Model            | Приём: результат по ссылке в файл и чанкирование вместо таскания в контекст              |
| MoE        | Mixture of Experts                  | Удалён: давал второй путь исполнения в обход гейтов                                      |
| DAG        | Directed Acyclic Graph              | Граф без циклов; так задаются шаги пайплайна                                             |
| i18n       | Internationalization                | Локализация: строки через `t()`, файлы `en.json` / `ru.json`                             |
| INV-N      | Invariant N                         | Нормативный инвариант из [architecture v2](./specs/2026-10-12-architecture-v2-design.md) |
| E2E        | End-to-End                          | Сквозной тест через реальный интерфейс (только по команде)                               |
| fallback   | Запасной путь                       | Если основной способ не сработал — пробуем следующий                                     |
| failover   | Переключение при отказе             | Основной провайдер лёг — работаем через следующий                                        |
| evidence   | Доказательство                      | Факты из тулов, на которые опирается критик                                              |

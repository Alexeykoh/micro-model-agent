Строка статуса — единственное место индикатора: он появляется при phase: thinking и исчезает на text/tool_start/turn_end (как сейчас). Претензия текущего UI: во время долгого выполнения тула строка исчезает вовсе — только спиннер в .busy мигает между фазами. Предлагаю держать индикатор видимым всё время busy, меняя фазу (thinking → tool → composing).

Над строкой ввода — крупный индикатор общей занятости — вариант activity rail

12Activity rail
CSS/DOMполная ширинабез выдуманных %

Толстая (12px) полоса во всю ширину композера. Без плана — индeterminate: светящийся сегмент сканирует всю длину, скорость зависит от фазы; каждое реальное событие (tool_start, text, plan) даёт вспышку и счётчик в мета-строке. С планом — полоса честно заполняется по done/total, засечки = шаги. Никаких «занятость N%» — мы не знаем, сколько осталось.

Что показывает полоса: процента занятости не существует — мы не знаем, сколько осталось. Режимы: без плана — индeterminate-сканер + вспышка на каждое реальное событие (tool_start, text, plan), живость = «агент работает»; с планом — честный done/total. Мета-строка: фаза (phase), таймер с POST /api/message, счётчик тулов (tool_start/end), последнее событие. Всё есть у клиента уже сейчас — новый бэкенд не нужен.

Рекомендация
  1. Безопасный выбор — №05 Equalizer bars: CSS, фазо-зависимый (первая фазо-зависимость в UI), живой, но дешёвый и совместимый с STYLE.md (обновление на месте, без новых глифов).
  2. Максимальная «интересность» — №08 Thought-orb: единственный вариант, который на бегу показывает что делает агент (orb/searching/solving), + плавный фолбэк на №01 при prefers-reduced-motion.
  3. Гибрид: строка статуса всегда (№05 или №01) + orb как отдельный «аватар» в шапке хода для длинных прогонов.
  4. Над композером — №12 Activity rail (выбрано): индeterminate-сканер + вспышки от реальных событий (tool_start/text/plan), честный done/total только при наличии плана; мета-строка = фаза · таймер · тулы · последнее событие. Без выдуманных процентов — точной «занятости» не существует.
Стоимость: №01/02/04/05/07 — до 20 строк CSS; №03/06/10 — <60 строк JS; №08/09/11 — 80–140 строк JS на canvas (rAF, отключается при reduced-motion). Большие индикаторы (№12–14) добавляют ещё ~60–120 строк и используют только уже существующие данные клиента (busy, phase, plan, tool_start/end).

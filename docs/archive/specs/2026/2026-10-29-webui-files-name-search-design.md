# Поиск по имени файла во вкладке «Файлы»

_Дата: 2026-10-29. Ветка: `feat/webui-files-name-search`. Расширяет
[поиск по содержимому](./2026-10-29-webui-files-content-search-design.md)
(C-01)._

**Статус:** реализовано.

## Проблема

Поле поиска во вкладке «Файлы» искало только по содержимому. Ввод имени файла
(например, `search.ts`) давал пустой список, если в текстах проекта эта строка не
встречалась: найти файл по названию было невозможно, хотя именно это первое, что
делает пользователь.

## Решение

Тот же `GET /api/search` ищет совпадения по двум каналам:

1. **имя/путь** — `path` файла (workspace-relative, posix) содержит запрос без
   учёта регистра; файл читать не нужно, поэтому попадают и большие, и бинарные
   файлы;
2. **содержимое** — прежнее поведение (строка + 1-based номер).

Совпадения по имени идут первыми: если запрос — имя файла, он оказывается вверху
даже когда в проекте много текстовых совпадений. Внутри каждого канала порядок —
обход в алфавитном порядке (как раньше).

Клик по совпадению имени открывает файл с начала (`openFile(path)`); клик по
совпадению содержимого — на строке (`openFile(path, line)`). Новых путей
навигации нет.

## API

```
GET /api/search?q=<подстрока>
→ 200 {"results":[
         {"kind":"path","path":"src/search.ts"},
         {"kind":"content","path":"src/a.ts","line":12,"text":"const x = 1"}
       ],
       "truncated":false,"ms":18,"scanned":42}
```

- `kind` — `path` (совпало имя/путь) или `content` (совпала строка).
- `path` — всегда workspace-относительный posix-путь.
- `line`/`text` — только у `content`: 1-based строка после `trim()`, ≤200 символов.
- `truncated` — упёрлись в кап результатов/файлов/байт/времени.
- `scanned` — сколько файлов прочитано (для диагностики, не для UI).

Запрос нормализуется: `\` → `/`, срезается ведущий `./`. Спецсимволы не
интерпретируются — это подстрока, не glob.

## Границы

Капы прежние; совпадения имени и содержимого делят общий лимит результатов (50).
Если имён набралось на весь лимит, обход останавливается и `truncated: true`.

## Безопасность

Не меняется относительно исходной спеки: путь не принимается параметром, симлинки
не разворачиваются, действуют `IGNORE_DIRS`/`IGNORE_FILE_NAMES`, `.gitignore` /
`.mmaignore`, `apiHiddenGlobs` и `matchProtectedPath`. Совпадение по имени не
обходит игноры и защиту: `.env` и `node_modules/...` в выдачу не попадают.

## Инварианты

- **INV-S5.** Запрос ищет и по имени/пути, и по содержимому; совпадения имени
  стоят перед совпадениями содержимого.
- **INV-S6.** Совпадение по имени не требует чтения файла, но подчиняется тем же
  игнорам, защите путей и общему капу результатов; имя `<file>` не открывает
  доступ к содержимому защищённого файла.
- **INV-S7.** `kind` различает два вида совпадения; строка и номер строки есть
  только у `content`.

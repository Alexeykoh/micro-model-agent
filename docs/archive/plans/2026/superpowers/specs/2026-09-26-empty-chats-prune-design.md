# 2026-09-26 — Чистка пустых чатов (empty sessions prune)

## Контекст

Сессии (`~/.mma/sessions/<id>/`) копятся без дела: каждый `/new`, заход в web или one-shot без продолжения оставляет сессию с нулем или без единого user-сообщения. `SessionManager.enforceMaxSessions` режет только по лимиту 50, пустые специально не чистятся. Пользователь хочет авточистку + ручную страховку.

## Решение (подход A + ручной prune)

Авточистка при создании сессии + ручная команда на том же методе. Без sweep при старте (bootstrap не трогаем), без конфиг-флагов, без web-кнопки — YAGNI.

## 1. Что такое «пустой»

Сессия пустая, если в `SessionManager.getHistory(id)` (живая история + ротированный `.jsonl.gz`) нет ни одного сообщения `role=user` с непустым текстом (строка или `ContentPart[]` с текстом после trim).

Fast-path: `meta.messageCount === 0` → пустая без чтения истории. `messageCount` считает все роли, поэтому сам по себе критерием не является.

Fail-open: ошибка чтения истории (`getHistory` кидает или возвращает мусор) → сессия НЕ пустая, не удаляем.

## 2. Авточистка в `create()`

Новый метод `SessionManager`:

```ts
pruneEmpty(excludeId?: string): string[] // возвращает удалённые id
```

Логика: `list()` → пропустить `excludeId` → для каждой: fast-path по `messageCount`, иначе `getHistory` + проверка `role=user` → `delete(id)` в try/catch (ошибка одной сессии не останавливает проход).

Вызов: в конце `SessionManager.create()`, после `enforceMaxSessions()`, с `excludeId` = id только что созданной сессии. Только что созданная (активная) никогда не удаляется — даже если она сама пустая. Никакого вывода в чат; результат виден исчезновением из `session list`.

Производительность: проход только по мета + истории кандидатов; лимит сессий 50 делает это дешёвым. Дополнительного кэша нет.

## 3. Ручная страховка

- CLI: `mma session prune [--dry-run]` — тот же `pruneEmpty()` с `excludeId` = текущая активная (`getActive()`). `--dry-run` только печатает кандидатов, ничего не удаляет.
- REPL: `/sessions prune [--dry-run]` — тот же путь, handler-map (правило #17), рядом с существующими `list/use`.
- Вывод: удалено → `session.pruned {n}` + список id (по одному на строку); кандидатов нет → `session.prune_empty`; dry-run → `session.prune_dry {n}` + список.
- i18n: `session.pruned`, `session.prune_dry`, `session.prune_empty` в `en.json` + `ru.json`.

## 4. Тесты

- Юнит `pruneEmpty`: `messageCount=0` удаляется; есть история без user — удаляется; есть user-текст — остаётся; активная (excludeId) не трогается; битая история (throw) — не удаляется; возвращает id удалённых.
- CLI/REPL: dry-run не удаляет, реальный удаляет; пустой список → `prune_empty`.

## Вне скоупа

- Sweep в `bootstrap()`, чистка по возрасту/размеру, web-кнопка, конфиг-флаг `session.autoPrune`, удаление активной сессии, подтверждение перед авточисткой.

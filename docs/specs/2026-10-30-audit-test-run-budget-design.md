# Бюджет тест-прогона финального аудита

**Дата:** 2026-10-30 · **Статус:** реализовано · **Долг:** платит `audit-final-gate-full-test-run`
(остаток вынесен в `audit-typecheck-inconclusive`, см. §7).

## 1. Проблема и замеры

Финальный аудит (`AuditGate` → `runFinalAudit` → `Auditor.audit`) на каждом ходе,
где существует хотя бы один тестовый файл, синхронно запускал **полный** тест-сьют
проекта с капом 90 с (`audit-runners.ts::runTests`). Факты:

| Факт                                | Значение       | Источник                                                                |
| ----------------------------------- | -------------- | ----------------------------------------------------------------------- |
| Ход `ses_mvv7n4e9…`                 | 27 с           | `gate_timing`                                                           |
| Из них critic                       | 12 с           | `gate_timing`                                                           |
| Из них audit                        | 3 мс           | `gate_timing` (тестов в рабочей папке не было)                          |
| Аудит в другой сессии               | 90+ с          | живой замер (тестовый файл есть)                                        |
| Полный `bun test` этого репозитория | 242 с          | живой замер                                                             |
| Кап раннера                         | 90 с           | `runTests` (до правки)                                                  |
| Вердикт при таймауте                | `passed: true` | `runTests` (до правки): «don't block completion on an inconclusive run» |
| Отпечаток дерева этого репозитория  | 59 мс / 116 КБ | `testTreeFingerprint(process.cwd())`, замер 2026-10-30                  |

Итог: на большом репозитории 90 с тратились гарантированно впустую — прогон не
укладывался в кап, а «inconclusive» выглядел как «тесты прошли». На чат-ходе без
правок файлов прогон не мог ничего сломать, но запускался всё равно.

## 2. Контракт: когда гоняем тесты

Тестовый прогон выполняется, только если одновременно:

1. в дереве есть тестовый файл (`findTestFile` — evidence-based, без классификации
   прозы шагов по слову «тест», правило #10);
2. вызывающий не заявил, что за ход **не было файловых мутаций**;
3. нет свежего результата в кэше для текущего состояния дерева.

Ветки вердикта (`TestRunCheck.status`):

| status         | когда                                                   | блокирует завершение | кэшируется |
| -------------- | ------------------------------------------------------- | -------------------- | ---------- |
| `passed`       | раннер отработал, сводка распознана, упавших нет        | нет                  | да         |
| `failed`       | раннер отработал, сводка распознана, есть упавшие       | **да**               | да         |
| `inconclusive` | таймаут бюджета, раннер не стартовал, exit 0 без сводки | нет                  | **нет**    |
| `skipped`      | за ход не было файловых мутаций                         | нет                  | нет        |

`passed` теперь означает ровно «тесты прошли» и больше не используется как
«не блокировать». Блокировка решается по `status === "failed"` — так «не знаем»
и «прошло» перестали быть одним значением.

## 3. Скип: «сломать тесты нечем»

`Auditor.audit(plan, { mutated })` — опция вызывающего. `AuditOptions.mutated`:

- `false` — за ход не было успешных файл-мутирующих вызовов → прогон **не
  запускается**, результат:
  `{ status: "skipped", checked: false, detail: "skipped: no file mutations this turn" }`;
- `undefined` — вызывающий не знает (юнит-вызовы) → проверяем, как раньше;
- `true` — мутации были → проверяем.

Мутации считает execution-плагин (`onAfterTool`): успешный вызов из
`FS_MUTATING_TOOLS` — `write_file`/`append_file`/`edit_file`/`delete_file`/
`move_file`/`create_dir`/`download_file`/`bash`/`subagent`/`mcp_call`/`pipeline_run`/
`browser`. Список консервативный: `bash`/`browser`/MCP считаются мутацией при
любом успехе (могли писать на диск) — цена ошибки в эту сторону лишь
«прогон был не нужен, но состоялся». Read-only тулы (`read_file`, `glob`,
`grep`, `project_map`, `lsp_check`) мутацией не считаются, поэтому чат-ход без
записи файлов прогон не запускает. Флаг `mutatedThisTurn` сбрасывается на границе
хода (`onTurnEnd`), а не на итерации: мутации до финального ответа обязаны дожить
до аудита.

Ограничение по построению: «тихая» мутация вне тулов харнесса (другой процесс,
пользователь правит файл) скип не увидит. Цена ошибки — пропущенный прогон этого
хода, а не ложный провал; следующий ход с мутацией проверит дерево.

## 4. Кэш по состоянию дерева

Повторный аудит на неизменном дереве не платит раннер второй раз (типовой случай:
audit-gate отклонил ответ, модель переответила без правок).

- Отпечаток `testTreeFingerprint(baseDir)` = по каждому файлу дерева (кроме
  `SKIP_DIRS`) `относительный путь + mtimeMs + size` + stamp `package.json` +
  резолвленная тестовая команда (`resolveTestCommand`). Пути сортируются.
- В отпечаток входит **всё дерево**, а не только тестовые файлы: изменение
  исходника под тестом обязано инвалидировать кэш, иначе аудит вернул бы прошлое
  `passed` на сломанном коде. Тестовый набор — подмножество, так что требование
  «набор тестовых файлов + package.json» выполнено с запасом по строгости.
- Хранение — один слот на проект в памяти процесса (`audit-test-cache.ts`).
  `inconclusive`/`skipped` не кэшируются: таймаут не должен «залипнуть» успехом,
  скип не должен подменять прогон хода, где мутации есть.
- Отпечаток недостоверен (ошибка ФС, > 20 000 файлов) → `null` → кэш выключен,
  раннер работает как обычно. Честный откат, а не «примерный» ключ.
- Попадание отдаётся как копия с `cached: true`, `durationMs: 0` и `detail +
" · cached"`.

## 5. Честный таймаут

Бюджет вынесен в `src/config/timeouts.ts`:

- `AUDIT_TEST_RUN_BUDGET_MS = 90_000` — полный тест-прогон;
- `AUDIT_TYPECHECK_BUDGET_MS = 90_000` — `tsc --noEmit` (без изменения поведения,
  см. §7).

Нового ключа конфига нет: это не пользовательская настройка, а политика гейта.
Число 90 с сохранено — меняется не терпение, а **вердикт**: истечение бюджета даёт
`status: "inconclusive"`, `passed: false`, `detail: "inconclusive: runner did not
finish within 90s — result unknown, not a pass"` и `durationMs`. Тот же статус у
раннера, который не стартовал, и у exit 0 без распознанной сводки (раньше это
считалось успехом).

## 6. Наблюдаемость (INV-15)

- `AuditResult.testNote` (и `FinalAuditResult.testNote`) — пометка прогона:
  `skipped: …` / `inconclusive: … (Nms)` / `cached: …`; `null` для обычного прогона.
- `AuditGate` пишет `audit`-запись в `session.jsonl` **и при вердикте «принят»**,
  если пометка есть; поле `tests` аддитивно к `content`/`iteration`/`duration`
  (читатели не ломаются, `webui`-маппинг его игнорирует).
- Видимых строк в чат не добавлено — i18n не требуется (STYLE: quiet by default).

## 7. Что осталось (новый долг)

`tsc --noEmit` всё ещё возвращает `string | null`: таймаут и «ошибок нет»
неразличимы, проверка может стоить до 90 с. Оплата — `DEBT(audit-typecheck-inconclusive)`
в `audit-runners.ts` (тип результата вместо `string|null`, пометка в `audit`-записи).

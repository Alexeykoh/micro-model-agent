# Локальный провайдер и taint: производный текст не должен утекать наружу

## 1. Проблема

Сейчас содержимое защищённого файла помечается sentinel'ом в результате тула
(`FILE_CONTENT_SENTINEL`, `src/tools/file-content-tag.ts`). Guard на egress:

- **доверенному** провайдеру (loopback/LAN/allowlist) снимает тег и отдаёт
  содержимое как есть — это осознанно: локальная модель нужна для работы с кодом;
- **внешнему** провайдеру и API-клиенту заменяет всё содержимое на `[FILE]`.

Дыра начинается сразу после ответа локальной модели:

1. Ассистентский ответ, сгенерированный по незамаскированному содержимому,
   **не несёт sentinel**. Если в том же диалоге переключить провайдера на
   внешний (или запустить субагента на внешней модели), этот текст уходит наружу
   без тега — утечка производных данных.
2. Сводка компакции, построенная по такому ответу, тоже не тегируется, зато
   живёт в контексте долго и переживает переключение провайдера.
3. Рассуждения (reasoning) локальной модели попадают в журнал и могут быть
   прочитаны внешней моделью как часть истории.

То есть защищён ровно один слой — «сырой» вывод тула — а производный текст
(`assistant`, `reasoning`, `compaction`, ответы субагентов на локальной модели)
не защищён никак. Это дефект **границы**, а не отдельный баг: признак «здесь были
защищённые данные» сейчас живёт в строке, а не в записи контекста.

## 2. Цели

| ID | Цель | Проверка |
|---|---|---|
| **G1** | Контекст знает, какие сообщения производны от `file-content` | тест состояния контекста |
| **G2** | При egress к **внешней** цели производные сообщения маскируются так же, как сырой тег | canary-тест через `SanitizingProvider` |
| **G3** | При egress к **доверенной** цели ничего не меняется (локальная работа не деградирует) | существующие тесты + новый |
| **G4** | Taint переживает `repairToolCallPairing`, resume из `session.jsonl` и компакцию; при вытеснении всех tainted-сообщений флаг снимается | тест на компакцию/resume |

## 3. Модель угроз (что считаем производным)

| Источник | Tainted? | Почему |
|---|---|---|
| Результат тула с `pathArgs` под `providerBlockGlobs` | **да** (уже помечен sentinel'ом) | сырое содержимое файла |
| Ответ `bash`/MCP/плагинов на защищённом пути | да, если включён тег содержимого (волна B) | сырое содержимое без `pathArgs` |
| `assistant`/`reasoning`, сгенерированные при наличии tainted-ввода **на доверенной модели** | **да** | модель видела незамаскированный текст |
| `assistant` при наличии tainted-ввода на **внешней** модели | нет | модель видела `[FILE]`, ответ не производный |
| Сводка компакции, если в сжатом диапазоне был tainted-ввод | **да**, если суммаризатор доверенный; **нет**, если внешний | тот же принцип |
| Ответ субагента: наследует taint своего ввода | да | отдельный контекст, но тот же принцип |

Консервативная деградация: если источник taint неизвестен (старая сессия без
метаданных, плагин вернул текст без тега), **не** помечаем — иначе после первого
чтения `.env` вся история станет невидимой для внешней модели. Неизвестное —
не tainted, но и не доверенное: это остаточный риск, зафиксированный в §7.

## 4. Инварианты (нормативно)

- **INV-T1** — taint — свойство **записи контекста**, а не строки: держится в
  метаданных сообщения, а не только в sentinel'е.
- **INV-T2** — tainted-сообщение при egress к внешней цели заменяется `[FILE]`
  (или `[FILE: hidden N chars]`), независимо от PII-паттернов и `minConfidence`.
- **INV-T3** — доверенная цель получает tainted-содержимое без маски; sentinel
  снимается ровно в одной точке (`projectText`), как сейчас.
- **INV-T4** — taint не «размножается» бесконечно: сообщение, чей ввод был
  полностью вытеснен компакцией, перестаёт быть tainted; флаг снимается, когда
  в контексте не осталось tainted-записей.
- **INV-T5** — taint переживает сериализацию: resume из `session.jsonl`
  восстанавливает флаг (или консервативно считает историю tainted, если запись
  старше схемы — решение в §6).
- **INV-T6** — fail-open не молчит: снятие/потеря taint пишет диагностику
  (`taint_degraded`), иначе дыра неотличима от «чисто».

## 5. Контракт данных

### 5.1 Запись контекста

Каждая запись истории получает поле:

```ts
interface ContextMessageMeta {
  /** Производное от защищённого содержимого. */
  taint?: "file-content";
  /** Источник taint — для разбора: тул/ассистент/компакция/субагент. */
  taintOrigin?: string;
}
```

Носитель — `ContextManager`: сообщения `Message` не расширяем (это контракт
провайдеров), поэтому метаданные живут в параллельной карте по стабильному id
записи (id присваивается при `append`, переживает `repairToolCallPairing`).

### 5.2 Точки записи

| Точка | Действие |
|---|---|
| `tagBlockedFileContent` (`src/tools/file-content-tag.ts`) | помечает запись тула tainted (уже знает glob и путь) |
| Завершение хода на доверенной модели | если ввод хода содержал tainted-запись → `assistant`-ответ и его `reasoning` помечаются tainted |
| Компакция | если сжатый диапазон содержал tainted-записи → сводка tainted (источник `compaction`) |
| Субагент | ответ наследует taint ввода; при внешней модели субагента — не наследует |

### 5.3 Точка чтения

E1 (`sanitizeChat`) получает от контекста не только `Message[]`, но и
`taintedIndexes` (через `SanitizingProvider`/`ProviderManager`). Для внешней цели
эти сообщения заменяются на `MASK["file-content"]`. Для доверенной — как сейчас
(снятие sentinel'а).

## 6. Сериализация и совместимость

- `session.jsonl` получает аддитивные поля записи (`taint`, `taintOrigin`).
  Старые записи без полей: **не tainted** (консервативно не раздуваем), но
  диагностика `taint_degraded` с причиной `legacy_log` пишется один раз на сессию.
- Resume: карта taint восстанавливается из журнала; `repairToolCallPairing`
  сохраняет id/флаг (пары чинятся, метаданные переносятся).
- Компакция: сохраняет taint выжившего хвоста; сводка получает флаг по правилу
  §3. При вытеснении всех tainted-записей флаг снимается (INV-T4).

## 7. Не-цели и остаточные риски

- **Не** шифруем at-rest (`at-rest-pii` — отдельный контракт).
- **Не** делаем NER и семантическую классификацию: taint — про происхождение, не
  про содержимое.
- **Не** покрываем инструменты без тега содержимого (bash/MCP/плагины) в этой
  волне: они станут источниками taint после волны B (`file-content-bypass-non-path-tools`).
- Остаточный риск: текст, попавший в контекст иначе (вставка пользователем,
  ошибка тула), не tainted. Это осознанная граница: taint не «детектор ПДн», а
  «происхождение из защищённого файла».

## 8. Волны реализации

| Волна | Что | Результат |
|---|---|---|
| **T1** | метаданные taint в `ContextManager`, пометка в `tagBlockedFileContent` | тест: после чтения защищённого файла запись помечена; `getActiveHistory` даёт `taintedIndexes` |
| **T2** | пометка производного `assistant`/`reasoning` на доверенной модели | тест: ответ локальной модели tainted, внешней — нет |
| **T3** | egress-маска для внешней цели по `taintedIndexes` | canary-тест: локальный ход → переключение провайдера → canary не уходит |
| **T4** | компакция и resume | тест: taint переживает компакцию; снимается при вытеснении всех записей |
| **T5** | диагностика `taint_degraded`, docs, реестр долгов | гейт наблюдаемости |

Каждая волна — отдельная ветка от `master`, зелёные `bun test` + `bun run quality`.

## 10. Риски

| Риск | Смягчение |
|---|---|
| Ложный taint делает контекст «слепым» для внешней модели | taint только при доказанном происхождении; внешняя модель не наследует |
| Потеря флага при компакции = тихая утечка | INV-T4 + диагностика `taint_degraded` |
| Метaданные расходятся с сообщениями после `repairToolCallPairing` | id-адресация вместо индексов, тест на починку пар |
| Разрастание `session.jsonl` | аддитивные поля, два скаляра на запись |

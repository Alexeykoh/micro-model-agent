# Скорость веб-поверхности: загрузка, переключения, индикация

_Дата: 2026-11-04. Ветка: `docs/webui-latency-design`. Статус: предложение._
_Заменяет план волн из сессии аудита; правки в код — только после утверждения._

## 1. Симптомы и замеры

| Симптом (со слов пользователя)                                                | Факт                                                                                                                                                      |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| «долго грузится»                                                              | `loadAssets()` на **каждый** статический запрос: dev ≈ 90 мс; 174 запроса статики = 16.8 с (холодный) / 22.6 с (прогретый) через реальный `handleRequest` |
| «вкладки грузятся долго»                                                      | `listSessions()` ≈ 150 мс: `readdirSync` + `loadMeta` на 3 874 каталога, из них реальных сессий 33                                                        |
| «очень долго переключается провайдер и модель»                                | `POST /api/config` ждёт до 5 последовательных сетевых проб по 3 с, затем то же для **каждого** из 8 раннеров, затем `listModels()` **без таймаута**       |
| «лодеры не анимированные»                                                     | при `prefers-reduced-motion: reduce` rAF-цикл не стартует, а CSS глушит все анимации; boot-полоса замирает на 40 %                                        |
| «при переключении вкладок не блокируется интерфейс и не понятно что грузится» | `setSessionLoading(true)` только приглушает секцию Session в сайдбаре, лента и composer остаются живыми; `bootCap` — одна неизменная строка               |

## 2. Что не так (с адресами)

### 2.1 Статика собирается на каждый запрос

`serveStatic` вызывает `s.assetSource()` безусловно (`src/modules/webui/static-assets.ts:56`),
а `assetSource` — это `loadAssets` (`src/modules/webui/module.ts:284`). `loadAssets`
каждый раз читает и транспилирует **все** 167 TS-файлов фронта плюс CSS/HTML
(`src/modules/webui/assets.ts:26-89`). 174 запроса × 174 файла чтения.

### 2.2 Неизвестный `*.js` не получает ответа

`src/modules/webui/static-assets.ts:66-75`: если ключа нет в `jsModules`, функция
возвращает `true`, но `res.end()` не вызывается. Запрос висит до таймаута браузера.
Один битый импорт подвешивает boot-граф.

### 2.3 Реестр сессий — O(каталогов), а не O(сессий)

`SessionStore.listSessions()` (`src/modules/session/store.ts:234-246`) обходит все
каталоги и на каждый зовёт `loadMeta`, который для несуществующей меты делает
`existsSync` (`:102-116`). Каталогов 3 874, сессий 33: 3 841 бесполезный `stat`.
Вызывается на каждый `activate` и на каждый пункт меню.

Сироты появились из-за `createSessionContext`: при `isolateTempFiles: true` (дефолт)
каталог `~/.mma/sessions/<id>/temp` создаётся **сразу** (`src/modules/security/session-isolation.ts:55-61`),
даже если сессия потом не сохранилась. `cleanupSessionTempDir` — пустая заглушка
(`:103-105`).

### 2.4 Переключение провайдера/модели ждёт сеть

`POST /api/config` (`src/modules/webui/settings/config-api.ts:194`) → `persistAndReconfigure`
(`src/modules/webui/http/persist.ts:49`) → `makeReconfigure`
(`src/modules/webui/settings/reconfigure.ts:26-53`), который **последовательно** ждёт:

1. `agent.reconfigure` → `reprobeActiveProvider` (`src/core/agent/provider-phase.ts:95-129`):
   `probeModel` (3 с) **плюс** `probeProviderContext`, где те же пробы идут ещё раз
   цепочкой `probeOllama` (`/api/ps` + `/api/show`), `probeLlamaCpp`, `probeOpenAICompat`,
   `probeModelsDev` — до 5 × 3 с = **15 с** (`src/llm/provider-context.ts:143-164`).
2. `for (const id of state.pool.runnerIds())` — до `RUNNER_LRU_MAX = 8` раннеров
   (`src/modules/webui/session/session-pool.ts:36`), у каждого свой `lastProbeIdentity`,
   поэтому проба повторяется целиком, **по одному** → до 120 с.
3. `after()` → `modelCache.refresh()` → `provider.listModels()` (`src/llm/openai-models.ts:26-29`)
   **без `AbortSignal`**: недоступный хост висит до TCP-таймаута ОС.

Затем клиент делает ещё `GET /api/config` и `GET /api/models`
(`src/modules/webui/assets/js/settings/write.ts:132`).

### 2.5 Индикация не показывает происходящее

- Ожидание записи конфига — статичный `?` через `::after`
  (`src/modules/webui/assets/styles.css:636`), без спиннера и без времени.
- `setSessionLoading` только приглушает секцию Session (`src/modules/webui/assets/js/sidebar/trace.ts:92-97`,
  `styles.css:1084-1087`); лента, composer и кнопка отправки живы — можно писать в
  ещё не активированную сессию.
- `openTab` запускает `activate` + `loadSessions` + `loadHistory` без отмены
  (`src/modules/webui/assets/js/session/tabs.ts:162-176`): быстрое A→B→A оставляет
  три конкурирующих запроса.
- `prefers-reduced-motion` глушит всё: `mascot-canvas.ts:22-24` не запускает rAF,
  `styles.css:2109-2115` и `2643-2645` обнуляют анимации, `bs-prog` стоит на 40 %
  (`styles.css:2660`), `bootCap` — одна строка «connecting…» (`app-i18n.ts:30`).

## 3. Целевой контракт (нормативно)

**INV-W1. Статика — снапшот, а не сборка на запрос.**
`assetSource()` возвращает закешированный снапшот. Валидность проверяется по
отпечатку дерева (`путь + mtimeMs + size`) не чаще одного раза в `ASSET_TTL_MS`
(dev — 500 мс, prod — бесконечно: ассеты бандла неизменны). Стоимость запроса
не зависит от числа файлов фронта.

**INV-W2. Статический ответ всегда завершается.**
Ветка «ключа нет в карте» отвечает `404` с телом и закрывает соединение.
Ответ без `res.end()` запрещён.

**INV-W3. Реестр сессий — кеш с явной инвалидацией.**
`listSessions()` отдаёт закешированный список; инвалидация — на `saveMeta`,
`deleteSession`, `create` и по TTL `SESSIONS_TTL_MS = 1 000`. Стоимость вызова
не зависит от числа каталогов в `~/.mma/sessions`.

**INV-W4. Каталог сессии создаётся при первом использовании.**
`createSessionContext` не пишет на диск. `getSessionTempDir` создаёт `temp`
при первом обращении. `cleanupSessionTempDir` удаляет каталог. Сирота — каталог
содержит ровно один пустой `temp` (нет меты, логов и посторонних файлов);
такой каталог удаляет `pruneOrphanSessionDirs`. Пустой каталог не трогаем:
так выглядит `create()` между `mkdirSync` и записью меты.

**INV-W5. Сеть не входит в путь ответа `POST /api/config`.**
Ответ уходит после персиста и локального применения конфига. Обновление списка
моделей — фон; результат сообщается событием `models`.

**INV-W6. Одна проба контекста на переключение.**
Проба выполняется один раз на операцию (не на раннер) и кешируется по
идентичности `baseUrl + model + type`. Повторное переключение на ту же
идентичность сети не касается.

**INV-W7. У каждого сетевого вызова есть таймаут.**
`listProviderModels` получает `AbortSignal.timeout(LIST_MODELS_TIMEOUT_MS = 4 000)`.
Вызов без таймаута в пути, который ждёт HTTP-ответ, запрещён.

**INV-W8. Переключение вкладки блокирует ровно тот ввод, чьи данные не пришли.**
Пока `historyLoading` — лента показывает скелетон с `aria-busy="true"` и composer
заблокирован. Результат запроса применяется, только если вкладка всё ещё активна
и её порядковый номер загрузки не изменился.

**INV-W9. Индикация не зависит от `prefers-reduced-motion`.**
Режим пониженной анимации замедляет и упрощает движение, но не отменяет признак
прогресса. Индикатор прогресса либо обновляет текст/число, либо остаётся
анимированным замедленно. Boot показывает реальную стадию и заполнение, а не
статичную полосу на 40 %.

## 4. Волны

Порядок — по соотношению «эффект / риск». A и C не меняют контракт API; B меняет
контракт `POST /api/config` и добавляет SSE-событие `models`.

### Волна C — серверный P0 (без изменения API)

| Шаг | Файлы                                                                           | Что делается                                                                                        |
| --- | ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| C1  | `webui/assets.ts`, `webui/asset-cache.ts` (новый), `webui/module.ts`            | `createAssetSource()`: снапшот + отпечаток дерева + TTL; `module.ts` ставит его вместо `loadAssets` |
| C2  | `webui/static-assets.ts`, `webui/state-contracts.ts`                            | `404` вместо «висящего» ответа; `ETag` + `Cache-Control: no-cache` на статике                       |
| C3  | `session/store.ts`, `session/list-cache.ts` (новый)                             | кеш `listSessions` + кеш отрицательных мет; инвалидация на `saveMeta` / `deleteSession`             |
| C4  | `security/session-isolation.ts`, `session/prune.ts`, `session/manager-state.ts` | ленивый `temp`, рабочий `cleanupSessionTempDir`, `pruneOrphanSessionDirs`                           |

`store.ts` после C3/C4 разрезан по правилу 6 (≤300 строк): чтение истории
переехало в `session/history-io.ts`, TTL-кеш реестра — в `session/list-cache.ts`.
Публичный контракт `SessionStore` не изменился; добавлен только `baseDirPath()`
(нужен прунингу сирот).

Ожидаемый эффект: загрузка страницы — с секунд до сотен миллисекунд (168 из
174 запросов становятся `304` без тела); меню сессий — с 150 мс до < 1 мс.

### Волна B — провайдер/модель (меняет контракт)

| Шаг | Файлы                                                           | Что делается                                                                                           |
| --- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| B1  | `llm/openai-models.ts`                                          | `AbortSignal.timeout(4 000)` в `listProviderModels`                                                    |
| B2  | `llm/provider-context.ts`, `llm/native-context.ts`              | пробы внутри `probeProviderContext` — `Promise.all`, выбор по прежнему приоритету: max 3 с вместо 15 с |
| B3  | `core/agent/provider-phase.ts`                                  | кеш `identity → contextWindow`; `reconfigure(config, { probe?: boolean })`                             |
| B4  | `webui/settings/reconfigure.ts`                                 | проба один раз (основной агент), раннеры пула — `{ probe: false }`                                     |
| B5  | `webui/settings/reconfigure.ts`, `webui/settings/config-api.ts` | `modelCache.refresh()` — без `await`; по завершении `models` + `config` события                        |
| B6  | `webui/assets/js/settings/write.ts`                             | для `provider.active`/`model` — только `loadModels()`; конфиг приходит событием `config`               |
| B7  | `webui/assets/js/sse.ts`                                        | обработчик события `models`                                                                            |

Ожидаемый эффект: первое переключение на новую идентичность ≤ 3 с, повторное —
десятки миллисекунд; ответ `POST /api/config` не зависит от доступности провайдера.

### Волна A — индикация и отзывчивость (без изменения API)

| Шаг | Файлы                                                                         | Что делается                                                                                                                                |
| --- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | `assets/js/session/tabs.ts`, `assets/js/feed/history.ts`, `assets/styles.css` | скелетон ленты + `aria-busy`; composer блокируется, пока `historyLoading`                                                                   |
| A2  | `assets/js/session/tabs.ts`                                                   | `tab.loadSeq` — результат применяется только к актуальной загрузке активной вкладки                                                         |
| A3  | `assets/app.ts`, `assets/index.html`, `assets/app-i18n.ts`                    | стадии boot: `bootCap` и заполнение `bs-prog` из реального прогресса (`--p`)                                                                |
| A4  | `assets/styles.css`, `assets/js/mascot-canvas.ts`                             | `prefers-reduced-motion` замедляет индикаторы (whitelist `.anim-essential`) вместо их отключения; rAF продолжает рисовать фазу, без пружины |
| A5  | `assets/js/settings/write.ts`, `assets/styles.css`                            | `pending` — спиннер + прошедшее время после 1 с вместо статичного `?`; `aria-busy` на селекторах                                            |

## 5. Зависимости и порядок

```
C1 → C2                 (без API, снимает «зависание»)
C3 → C4                 (без API, снимает «долгие вкладки»)
B1 → B2 → B3 → B4 → B5 → B6/B7
A1 → A2; A3; A4; A5     (независимы друг от друга)
```

A честно показывает загрузку, но «подвисание» пропадает только с C. Поэтому C
идёт первым, A — вторым: индикатор на медленном сервере маскирует дефект.

## 7. Риски и открытые вопросы

1. **Кеш `listSessions` и внешние процессы.** Второй процесс `mma` может создать
   сессию в обход кеша. TTL 1 000 мс ограничивает расхождение; запись из UI
   инвалидирует кеш явно.
2. **Фоновый `models` и первый запрос.** Пока список грузится, `GET /api/models`
   отвечает прежним списком. UI уже имеет признак `loading` — используем его.
3. **Кеш пробы по идентичности.** Если контекст модели меняется на стороне
   бэкенда без смены идентичности, кеш протухает только при рестарте процесса.
   Это осознанный обмен: текущее поведение (15 с на каждое переключение) хуже.
4. **`ETag` vs правки на лету.** В dev `no-cache` заставляет браузер перепроверять
   каждый ассет; при совпадении отпечатка это `304` без тела — дешевле, чем сейчас.
5. **Прунинг сирот необратим.** Удаляется только каталог с одним пустым `temp`
   (мета, логи и посторонние файлы — барьер). Существующие 3 856 сирот чистятся
   в фоне: на первом `create()` (фон автоочистки) либо по `session prune`;
   старт и HTTP-ответы удаление не ждут.
6. **A4 и доступность.** Замедленная анимация — компромисс; для пользователей с
   вестибулярными расстройствами безопаснее текстовый прогресс (A3, A5), анимация
   остаётся вторичным признаком.

## 8. Что не входит

- Бандлинг и минификация 174 ES-модулей, отложенная загрузка `hljs.js` (128 КБ)
  и `themes.css`.
- `session.jsonl` до 2.2 МБ и `GET /log?limit=100` — отдельная волна.
- Bootstrap-блокировки (`buildIndex`, MCP discovery 5 с, `probeModel`, 4 × `spawnSync`).
- Правки `src/modules/providers/` сверх B1–B2.

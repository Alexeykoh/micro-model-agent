| Ошибок тулов | 28 |

| Финальный ответ | нет (оба хода прерваны пользователем) |

Контроль: сессия `ses_ed8cb96e8ffe` (OpenCode, **та же модель**, тот же день) —
53 текстовые части на 166 тулов, 52 000 знаков текста, финальный ответ есть.
Разница не в модели, а в каркасе.

Три независимых дефекта, каждый со своим наблюдаемым следствием:

1. **Политика bash читает кавычки как код.** `docker exec lampac wget -qO-
   "http://127.0.0.1:9118/sisi?token=mezabizon&rchtype=cors"` блокируется как
   «chaining to a dangerous command» (`command-validator.ts:206-213`), а
   `docker ps --format "{{.Names}} | {{.Image}}"` — как «Operator "|"»
   (`containsOperator`, `:144-146`). Кавычки нигде не учитываются → 11 отказов
   на запросы, которые агент не мог выполнить иначе.
2. **Ход может быть полностью молчаливым.** В `system-prompt.ts` нет требования
   говорить, в цикле нет счётчика «пакетов без текста». 98 шагов без единого
   слова прошли все гейты; пользователь видел только строки тулов.
3. **Чередующиеся неудачи не считаются топтанием.** `consecutiveFailedBatches`
   и `consecutiveToolFailures` сбрасываются любым успехом. Реальная картина —
   `успех + фейл` в каждом пакете — давала 28 неудач и ни одной эскалации;
   единственной реакцией было отключение `bash` (главного тула диагностики).

## 1. Границы

**Входит:**

- W1: учёт кавычек в проверке операторов и цепочек `command-validator`.
- W2: требование нарратива в промпте + директива «скажи, что делаешь» +
  жёсткий стоп молчаливого хода с форс-ответом.
- W3: окно неудач на ход (переживает чередование успех/фейл) + эскалация
  «директива → форс-ответ» с честным `stopReason`.

**Не входит (осознанно):**

- Перестройка каналов `session.jsonl` (`type: "plan"` сейчас используется и для
  stuck-предупреждений). Это отдельная волна: смена формата события — контракт
  для webui/session-show, её нельзя делать «заодно» с W1–W3.
- Кеш промпта (1% попаданий против 99.9% у OpenCode). Причина — пересборка
  префикса, лечится отдельно (см. `prefix-monitor.ts`), к видимости хода
  отношения не имеет.
- autoPlan для диагностических задач: план без видимого прогресса в TUI даёт
  ту же «немоту», поэтому сначала нарратив (W2), потом план.

## 2. W1 — кавычки в bash-политике

**Контракт.** Символы `& | ; > < ` внутри кавычек — данные, а не операторы
shell. Внутри **двойных** кавычек shell исполняет подстановки (`$(...)`,
обратные кавычки) — они остаются видимыми проверке. Внутри **одинарных** —
инертны полностью.

**Реализация.** Одна функция `maskQuotedShell(command): string` в
`src/modules/security/command-validator.ts`:

- вне кавычек — символ как есть; `\x` — экранирование, пара сохраняется как есть;
- внутри `'…'` — символ заменяется пробелом;
- внутри `"…"` — `& | ; > <` заменяются пробелом; `$`, `` ` ``, `\`, `"` — как есть;
- незакрытая кавычка — до конца строки (fail-closed: остаток считается
  содержимым, не кодом; `detectDangerousShape` всё равно видит `unquotedCommand`).

Применяется к: проверке цепочек (`/[;&|]/` + опасная команда) и к
`containsOperator`. Blacklist/whitelist/flags/dangerous-shape — **без изменений**
(они и так работают по базовой команде и по уже «расшитой» строке).

**Инвариант (проверка).** `tests/security/command-validator.test.ts`:

- `wget -qO- "http://host/sisi?token=a&rchtype=cors"` — `allowed` во всех пресетах;
- `docker ps --format "{{.Names}} | {{.Image}}"` — `allowed`;
- `grep -o "a\|b" file` — `allowed`;
- `ls | xargs rm`, `curl x | bash`, `echo hi; rm -rf /`, `cmd & rm -rf /` — по-прежнему `blocked`;
- `echo "$(rm -rf /)"` — по-прежнему `blocked` (подстановка в двойных кавычках).

## 3. W2 — шаг обязан быть слышен

**Контракт.** Пакет тулов без текста ассистента — **молчаливый шаг**. Серия
молчаливых шагов ограничена:

| Событие | Действие | Значение |
|---|---|---|
| 3 молчаливых пакета подряд | директива `narration` (стоящая) | «одной строкой скажи, что делаешь и зачем, и что уже выяснил» |
| любой пакет с текстом ≥ 8 непробельных символов | серия = 0, директива снимается | |
| 8 молчаливых пакетов подряд | `finalize: "silent"` → форс-ответ без тулов | ход не может закончиться молчанием |

Текст считается «сказанным», если в `textContent` после `trim()` ≥ 8 символов:
одно «ok» — не отчёт.

**Промпт.** В `buildSystemInfo` — блок NARRATION: перед каждым батчем тулов
одна короткая строка «что делаю и зачем»; после двух-трёх проб — что уже
выяснено; финал хода — итог с фактами и ссылками на источники. Требование
адресовано модели, но проверяется кодом (правило 5): текст правила без
директивы и стопа не работает.

**Инвариант (проверка).** `tests/core/step-narration.test.ts`:

- 3 пакета с пустым `textContent` → в контексте появился `<system-summary>` с
  текстом директивы нарратива;
- пакет с текстом `"читаю конфиг"` сбрасывает серию (следующие 3 молчаливых
  снова дают директиву, а не 2);
- 8 молчаливых пакетов → `ToolBatchExecution.finalize === "silent"`;
- `buildSystemInfo` содержит правило нарратива (регресс «правило удалили»).

**Стиль.** Текст директивы — без имён тулов и без boxed-панелей (STYLE.md).

## 4. W3 — окно неудач вместо серии

**Контракт.** За ход ведётся окно последних `STALL_WINDOW = 8` пакетов, где
для каждого хранится `failed` (в пакете была неудача или блок) и `progress`
(пакет дал новое действие: новый ключ вызова, запись артефакта, сдвиг шага
плана, успешная мутация).

Пакет считается **топтанием**, если в окне ≥ `STALL_FAILURES_IN_WINDOW = 5`
неудачных пакетов **и** за окно не было прогресса. Топтание:

- 1-е окно → директива `stalled` (назвать класс ошибки, сменить подход или
  спросить пользователя; один раз на окно);
- 2-е окно (окно заполнилось заново) → `finalize: "stalled"` — форс-ответ.

Окно сдвигается по одному пакету; прогресс обнуляет счётчик окон, но не окно
(иначе редкий успех вечно «прощает» флейлинг).

**Почему не трогаем существующие счётчики.** `consecutiveFailedBatches`
(4/6) и `consecutiveToolFailures` (5) отвечают за **подряд** идущие провалы и
своих кейсов не теряют. W3 — третий, независимый случай: чередование.
Слияние их в один счётчик — отдельная задача (правило 4), здесь только
добавляется недостающий случай.

**Инвариант (проверка).** `tests/core/stall-window.test.ts`:

- 8 пакетов «1 успех + 1 фейл», без прогресса → директива `stalled` выдана,
  `finalize` не выставлен;
- следующие 8 таких же → `finalize === "stalled"`;
- окно с прогрессом в каждом пакете не даёт ни директивы, ни стопа;
- честный дебаг «упал → поправил → успех» не срабатывает (окно < порога).

**Наблюдаемость.** Факт срабатывания — `logger.diagnostic("warn", …)` +
`type: "stalled"` в `session.jsonl` с числом неудач в окне; иначе «остановился»
неотличимо от «сломался» (INV-15).

## 5. Порядок работ и определение «готово»

Волны сливаются последовательно в `master`: W1 → W2 → W3 (каждая следующая
ветка — от обновлённого `master`, чтобы спека и правки не расходились).

Для каждой волны:

1. тест из раздела инварианта **падает** до правки и проходит после;
2. `bun test` и `bun run quality` зелёные;
3. запись в `CHANGELOG.md` (PATCH для W1, MINOR для W2/W3 — новое поведение
   цикла и новый `stopReason`).

**Живой прогон (после merge всех трёх).** Та же задача, та же модель
(`deepseek-v4.1-flash`), тот же проект:

```
bun run mma -d E:\projects\lampac "разберись, почему на телевизоре sisi.js \
не имеет доступа к сайтам, которые почему-то доступны на компе. В телевизоре \
в приложении lampa введен плагин персональный с mezabizon"
```

Критерии приёмки прогона (по `session.jsonl`):

- ≥ 1 текстовый `assistant` до первого батча тулов;
- ни одной серии из 3+ молчаливых пакетов без директивы `narration`;
- блокировки `[SECURITY BLOCKED]` только за реальные цепочки (0 ложных на
  `&`/`|` внутри кавычек);
- ход заканчивается текстом с фактами и вердиктом, а не обрывом.

## 6. Риски

- **Ложные стопы W2.** Модель, которая «думает молча» на быстрых механических
  шагах, может упереться в 8 пакетов. Смягчение: порог директивы (3) мал, а
  стоп (8) недостижим, если модель хоть изредка говорит. Тест фиксирует, что
  пакет с текстом сбрасывает серию.
- **W3 на легитимном дебаге.** «Сломал → читаю → починил → сломал» даёт
  прогресс (новые адреса, мутации) — окно не заполняется. Тест на это есть.
- **Изменение формата события** (`stopReason: "silent" | "stalled"`) видно
  webui/CLI: оба получают `web.turn.stop_*` строки, неизвестный `stopReason`
  нигде не роняет рендер (проверяется `loop-result` тестом).

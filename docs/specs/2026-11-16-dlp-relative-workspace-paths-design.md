## 1. Проблема

Сессия `ses_mwj3mhgc_wvjnycpnxjzjdzdi` (Docker-стенд, внешний `llama.cpp` на
`host.docker.internal`) показала три дефекта проекции путей:

1. **Префиксный токен несамодостаточен.** `pathMode:"prefix"` заменял только
   корень: `/workspace` → `<PATH:abc>`, остаток `/src/a.ts` оставался. Модель
   копировала голый токен, и `read_file`/`list_dir` получали каталог вместо
   файла. В логе: `list_dir("<PATH:905047a556a0>")` → «каталог не найден».
2. **Value-based детектор резал по подстроке.** Литерал `/config` находился
   внутри `/app/src/config/env.ts`; путь превращался в
   `/app/src<PATH:866f…>/env.ts`, а `/config/config/provider.json` — в два
   токена подряд. Модель «достраивала» это до `/configconfig` и
   `/configprovider.json`.
3. **Workspace-корень маскировался в системном промпте.** `Workspace: ‹PATH›`
   не давал агенту точки отсчёта; он пробовал использовать сам placeholder как
   путь.

Спека §5.3 уже требует другого: «префикс корня заменить, workspace-относительный
остаток сохранить (модель видит `src/core/agent.ts`)». Код реализовал замену
префикса **токеном**, а не относительным путём.

## 2. Решение

Для внешнего egress **провайдера** (`kind:"provider"`, `trusted:false`) проекция
путей делится на три случая:

| Путь | `pathMode:"prefix"` (default) | `pathMode:"full"` |
|---|---|---|
| Под `baseDir` | **относительный** (`src/a.ts`, для корня — `.`) | токен всего абсолютного пути |
| Под `home`/`workspaceRoots` | токен **всего** пути | токен всего пути |
| Скрыт `providerBlockGlobs`/`apiHiddenGlobs` | маска `[PATH]` всего пути | маска `[PATH]` всего пути |

API-клиент (`kind:"api"`) сохраняет прежний контракт: префиксный токен плюс
относительный остаток (токены разделяют workspace разных тенантов). Для него
меняется только маскирование: hidden/full/`pseudonymize:false` теперь закрывают
путь целиком, без хвоста.

- Workspace-relative путь **не токенизируется**: модель получает путь, который
  сразу может передать в `read_file`/`bash` (они резолвят его от `baseDir`).
- Для не-workspace корней токен покрывает **весь** путь, а не только корень:
  голый токен самодостаточен и ре-гидратируется в полный путь.
- `pseudonymize:false` маскирует путь целиком (`[PATH]`), не оставляя хвоста.
- Совпадение корня — только на **границе пути**: `/config` не матчит
  `/app/src/config`, `/workspace` не матчит `/workspace-other`.

`trusted:true` (loopback/allowlist) не меняется: путь уходит как есть.

## 3. Инварианты

- **INV-DLP-P1.** Путь под `baseDir` в prefix-режиме **провайдера** не содержит
  токена и не содержит абсолютного префикса; для самого корня выдаётся `.`.
- **INV-DLP-P2.** Value-based корень матчится только на границе пути; подстрока
  внутри более длинного пути не редактируется.
- **INV-DLP-P3.** Токен не-workspace пути покрывает весь путь; `rehydrate`
  голого токена возвращает полный путь.
- **INV-DLP-P4.** Hidden-glob по-прежнему маскирует путь целиком, без хвоста.
- **INV-DLP-P5.** Существующие токены в истории ре-гидратируются как раньше:
  меняется только то, что создаётся для новых проекций; карта и формат
  `<LABEL:hex>` не меняются.
- **INV-DLP-P6.** `trusted:true` не редактирует пути.

## 4. Алгоритм

### 4.1 Границы (`detectors/paths.ts`)

Для value-based вхождений (`baseDir`, `home`, `workspaceRoots`) и POSIX-корней
проверяется соседний символ:

- перед началом — не путь (`[A-Za-z0-9._~@+\-\\/]`), иначе это середина пути;
- после конца — `/`, `\` или не путь, иначе это более длинный сегмент
  (`/workspace-other`, `/config.json`).

### 4.2 Проекция (`project.ts`)

Для каждой path-находки:

1. `fullEnd = pathEnd(text, f.end)` — весь путь до пробела/кавычки/разделителя.
2. `hidden = pathHiddenByPolicy(fullPath, …)`.
3. Если `hidden` → `[PATH]`, `end = fullEnd`.
4. Иначе если `pathMode:"full"` → токен/маска полного пути.
5. Иначе если `target.kind === "provider"`, `fullPath` под `baseDir` и
   `pseudonymize:true` → относительный путь (`.` для корня), без токена.
6. Иначе → токен/маска: для провайдера — полного пути, для API — префикса
   (кроме hidden/full/`pseudonymize:false`, где путь закрывается целиком).

`relativeToBase` сравнивает нормализованные (`/`, lower-case на Windows) строки;
возвращает `null`, если путь не внутри `baseDir`.

## 5. Контракт и совместимость

- Меняется **outbound-представление** путей (сообщения, tool-output, дефиниции
  тулов). Каноническая история, `session.jsonl`, тулы и ре-гидратация не меняются.
- `EgressHit.replacement` остаётся меткой (`‹PATH›`), не относительным путём:
  позиционный журнал не должен становиться вторым каналом путей.
- `pathMode:"full"` сохраняет прежнюю семантику «маскировать весь путь»; это
  режим регулируемого контура, где модель не обязана править файлы.
- Токены, уже лежащие в истории, продолжают разворачиваться: формат и карта не
  менялись.

## 7. Вне рамок

- Маскирование `OS`/platform и текущей даты как PII — отдельная политика
  (дата не является датой рождения; `Linux` не является machine-identity).
- Изоляция `/config` (другие сессии, ключи) — отдельная задача про права и
  sandbox, не про DLP-проекцию.
- Смена доверия `host.docker.internal` — конфигурация стенда, уже сделана
  отдельной веткой `fix/dlp-local-provider-trust`.

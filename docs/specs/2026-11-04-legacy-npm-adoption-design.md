# Переход с legacy npm-сборки на GitHub-Releases — дизайн

Дата: 2026-11-04. Ветка: `feat/legacy-npm-adoption`. Статус: реализуется.

## Проблема

Пользователь, ставивший MMA через `npm i -g micro-models-agent`, остаётся на старом
npm-канале. Его updater умеет только `npm install -g`, релизы в npm заморожены, а
установщик из GitHub Releases кладёт новую сборку в `~/.mma` и **дописывает**
`~/.mma/bin` в конец `PATH` — поэтому `mma` продолжает резолвиться в npm-шим.
Механизма перевода на новую установку нет: ни в `src/modules/updater/`, ни в
`scripts/install.*`, ни в `mma doctor`.

Данные при переходе не теряются: конфиг, сессии, память и плагины живут в общем
`~/.mma`, а формат конфига v1 → v2 уже мигрируется (`src/migration/`,
`mma config migrate`).

## Цель

Сделать новую установку **безусловно выигрывающей** у legacy npm-сборки, не
полагаясь на код старой версии:

- установщик находит legacy npm-шим и выводит его из игры обратимым переименованием;
- `~/.mma/bin` ставится в начало `PATH`, а не в конец;
- факт резолва проверяется, а не предполагается;
- новая сборка сообщает о теневом `mma` на `PATH` (рантайм + `mma doctor`).

## Не цели

- Публикация миграционного релиза в npm (противоречит решению «npm не используем»).
- Автоматическое удаление npm-пакета. Только переименование шима + печать команды
  `npm rm -g micro-models-agent`.
- Перенос пользовательских данных: каталог `~/.mma` общий.

## Контракт

### Переменные установщика

| Переменная              | Смысл                                                                                                 |
| ----------------------- | ----------------------------------------------------------------------------------------------------- |
| `MMA_INSTALL_NO_PATH=1` | Не менять `PATH` (реестр/rc). Для CI, корпоративных машин и тестов.                                   |
| `MMA_NPM_PREFIX`        | Явный npm-prefix для детекта legacy-шима. По умолчанию `npm prefix -g`. Нужен для герметичных тестов. |

Обе переменные действуют в `install.ps1` и `install.sh`; dry-run печатает
`legacy=` и `path=` строки, чтобы план проверялся без сети и записи.

### Установщик (`scripts/install.ps1`, `scripts/install.sh`)

1. **Preflight.** Найти `mma` в `PATH` (`Get-Command` / `command -v`). Если путь вне
   `$MMA_HOME/bin`, а npm-prefix известен (`MMA_NPM_PREFIX` или `npm prefix -g`) и
   путь под ним — это legacy npm-сборка.
2. **Retire legacy shim.** Переименовать только шимы в npm-prefix
   (`mma`, `mma.cmd`, `mma.ps1`; POSIX — `prefix/bin/mma`) в
   `<name>.legacy-npm.bak`. Не удалять. Ошибку переименования — warn, не fail.
   Напечатать команду окончательной уборки: `npm rm -g micro-models-agent`.
3. **PATH — в начало.** Windows: убрать дубли `$binDir`, поставить первым в
   user-PATH. POSIX: строка `export PATH="$MMA_HOME/bin:$PATH"` в конец найденного
   rc (выполняется последней → bin первый). При `MMA_INSTALL_NO_PATH=1` — только
   печать инструкции и сессионный `PATH` для проверки.
4. **Verify.** В текущем процессе выставить `$env:Path`/`PATH` с bin первым,
   разрешить `mma` и сравнить с `$MMA_HOME/bin/mma` (`mma.cmd`). Не совпало —
   явный warn с командой исправления. Затем, если `runtime/bun` и `app/main.js`
   существуют, выполнить `--version` (как сейчас).
5. **Идемпотентность.** Повторный запуск не дублирует PATH, не переименовывает
   уже переименованное, не трогает `~/.mma` за пределами версии/шима.

### Рантайм

- `src/core/install-path.ts` — чистые функции:
  `resolveOnPath(command, envPath, platform, pathExt?)`, `classifyInstall(entry,
installRoot, npmPrefix?)`, `checkPathShadowing(entry, installRoot, envPath)`.
- `mma doctor` получает секцию `Install`: откуда запущено (release / dev / npm /
  other), куда указывает `mma` в `PATH`, статус `warn` при теневом резолве и
  подсказка `npm rm -g micro-models-agent`.
- Новая сборка при старте (через `createUpdater`) пишет warn, если `mma` на `PATH`
  резолвится не в текущую установку. Ключ i18n `updater.path_shadowed` (en+ru).
- Проверки: `tests/core/install-path.test.ts` (чистые функции + doctor),
  расширение `tests/install-retry.test.ts` (dry-run и legacy-шим).

## Почему так

Старый npm-код изменить нельзя — он уже стоит у пользователя. Единственный
контролируемый рычаг — какой бинарь резолвится по имени `mma`, и проверяемый факт
этого резолва. Переименование шима детерминированно даже когда npm-prefix попал в
машинный `PATH` (user-PATH его не перебьёт), и при этом обратимо.

## Откат

- Вернуть шим: переименовать `*.legacy-npm.bak` обратно.
- `PATH`: удалить `~/.mma/bin` из user-PATH / rc.
- Установка: `current` указывает на прошлую версию (`docs/install.md`, Rollback).

# WebUI Files Tab: постоянный сплит, история, управление раскрытием — Design

Дата: 2026-10-08
Статус: draft (brainstorming применён, решение пользователя)
Ветка: `feat/webui-files-split`
Тип релиза: MINOR (новое поведение вкладки Files, только клиент)

Предыдущая спека: [2026-10-07-webui-files-tab-design.md](./2026-10-07-webui-files-tab-design.md)
(backend, дерево, attach). Здесь — **только** переработка вкладки Files во фронтенде.

## 0. Цель и метод

Пользовательская жалоба на текущую вкладку Files: «очень неудобно управление касательно
открытия и закрытия файла, кнопка мелкая, расположена неудобно, может есть смысл разделить
экран».

Разбор кода показал три дефекта, а не «мелочь вёрстки»:

1. **Дерево исчезает при открытии файла.** `styles.css:918` —
   `#pane-files:has(.files-detail:not([hidden])) .files-tree { display: none; }`.
   Открыл файл → дерево скрыто; чтобы посмотреть второй файл, надо закрыть (`✕`), заново
   найти его в дереве и развернуть папки. Переключение файла = полная навигация заново.
2. **Кнопки мелкие и нечитаемые.** `index.html:177-178` — глифы `◧`/`✕` классами
   `linkbtn` (~11px зона клика) с хардкодными `title="attach path"` / `title="close"` по-английски
   (ключи `web.files.attach/close` в словарях есть и не используются). Глиф `◧` для «прикрепить
   путь» ничего не сообщает.
3. **Attach-кнопка в строках дерева вредит.** `files.ts:151-161` + `styles.css:933-939` —
   paperclip 13px, `visibility: hidden` до ховера, у правого края строки; сама строка кликается
   для открытия файла → ложные клики открывают не тот файл.

Плюс отсутствуют: история переходов, навигация с клавиатуры, кросс-ссылка «откуда открыт файл».

## 1. Решение

Выбран **вариант A + D** из разбора (пользователь подтвердил):

- **A — постоянный сплит** (master–detail): дерево слева, просмотр справа, дерево **никогда**
  не прячется. Канонический паттерн: «In side-by-side mode, selection can update detail without
  hiding the master list» ([UX Patterns — master-detail](https://uxpatternsguide.com/patterns/master-detail/)).
  Тот же приём уже реализован во вкладке Trace (`#pane-trace` + `.trc-detail`), т.е. решение
  согласуется с существующим UI, а не вводит третье поведение.
- **D — история переходов**: стек последних файлов + кнопки `←`/`→` и `Alt+←/→`. Даёт самый
  большой выигрыш в сценарии «листаю 10 файлов подряд» (прогрессивное раскрытие
  preview → close, как в [twin-commander](https://github.com/jonathanleahy/twin-commander)).
- **Плюс (запрос пользователя) — управление раскрытием**: кнопки «свернуть всё» / «развернуть
  всё» / «обновить» в шапке дерева.

Отклонённые варианты (обоснование в разделе 11): preview/pinned-табы VS Code, drawer поверх
чата, «зритель во весь сайдбар» как единственный режим.

## 2. Инварианты (ломать нельзя)

1. **Backend не трогаем.** Ни одного нового REST-роута/SSE-события/поля снапшота: `GET /api/files`
   и `GET /api/file` уже дают всё нужное. Изменение строго фронтендовое (плюс новые i18n-ключи).
2. **Read-only.** Как и раньше: листинг + чтение, ни одной write-операции.
3. **Attach-контракт прежний** — вставка `` `relpath` `` в черновик, без новых каналов вложений.
4. **Frontend-модуль остаётся leaf.** `sidebar/files.ts` импортирует только
   `dom/i18n/api/store/state/md`; guard `tests/webui-frontend-graph.test.ts` должен остаться зелёным.
   Новая логика (сплит, история, клавиатура) живёт в этом же leaf-модуле, а не в `core.ts`,
   чтобы файл не растолстел: при >300 строк выносим в `sidebar/files/{split,history,keys}.ts`.
5. **i18n-паритет.** Все подписи (`title`/`aria-label`) через `t()`, ключи в `en.json` И `ru.json`.
6. **STYLE.md.** Никаких boxed-панелей: строки, отступы, глифы. Иконки — только Lucide
   (`dom.ts` `ICONS`), как у остального chrome.
7. **A11y.** Настоящие `<button>`, зона клика ≥ 24px, `aria-label` у всех иконочных кнопок,
   дерево навигируемо с клавиатуры, фокус видим (`:focus-visible` уже есть в теме).
8. **Сайдбар не прыгает.** Фиксированные 679px (решение 2.26.0) сохраняются: ширина дерева
   меняется внутри `#pane-files`, `.sb` не трогаем.
9. **Панель не остаётся пустой.** Закрытие просмотра (`✕`, `Escape`, смена workspace) всегда
   возвращает дерево: режим «только просмотр» живёт только пока открыт файл. Иначе «скрытое
   дерево + закрытый просмотр» = пустая вкладка без видимого выхода.

## 3. Раскладка

```
#pane-files (row, flex:1)
├ .files-body (row, flex:1, min-width:0)
│  ├ .files-side (col, width = var(--files-tree-w), min 200 / max 480)
│  │  ├ .files-bar — [свернуть всё] [развернуть всё] [обновить]
│  │  └ .files-tree (col, flex:1, overflow-y:auto)
│  ├ .files-splitter (col, width 6px, cursor: col-resize, role=separator)
│  └ .files-detail (col, flex:1, min-width:0)
│     ├ .detail-h — [←] [→] ‹хлебные крошки› [attach] [развернуть] [✕]
│     └ .detail-b (flex:1, overflow-y:auto)
```

- `#pane-files` перестаёт быть row-контейнером с `:has()`-хаком: `.files-tree` больше не
  прячется по CSS, всё регулируется только состоянием (`viewerFull`).
- **Ширина дерева** персистится в `localStorage["mma-files-tree-w"]`, кламп 200–480px;
  дефолт 240px. Двойной клик по сплиттеру → дефолт 240px (сброс).
- **`.viewerFull` (развернуть просмотр)** — пользовательский переключатель, возвращает прежнее
  поведение «дерево уступает место», но теперь по выбору, а не как побочный эффект открытия
  файла. Кнопка в шапке просмотра (`panel` / `panel-left`), `disabled` без открытого файла;
  закрытие просмотра сбрасывает режим (`setViewerFull(false)`).
- Мобильный ≤760px: сайдбар скрыт — разметка не трогает.

## 4. Функциональные блоки

### 4.1 Панель управления деревом

| Кнопка | Иконка | Действие |
|---|---|---|
| Свернуть всё | `chevrons-down-up` | `expanded.clear()`, дерево ререндерится на корень |
| Развернуть всё | `chevrons-up-down` | раскрытие по каталогам до `EXPAND_ALL_DEPTH = 4`, кап `EXPAND_ALL_MAX_DIRS = 200` запросов |
| Обновить | `refresh` | сброс кэша листингов + перечитывание текущих раскрытых + переоткрытие файла |

«Развернуть всё» на ленивом дереве — батчевая загрузка: обход в ширину по уже полученным
листингам, `Promise` пачкой, ререндер после каждой завершённой пачки (`requestAnimationFrame` не
используем — `markDirty` + рендер, как сейчас). При достижении капа показывается строка
`web.files.expand_capped` («развёрнуто до лимита N папок») — молчаливого обрыва нет.
Повторное нажатие «свернуть всё» мгновенно откатывает даже недозагруженное состояние
(`expanding` прерывается).

### 4.2 История просмотра

- Стек `files.history: string[]` + `files.histIndex: number` (последний открытый).
- Клик по файлу: если путь уже в истории **после** `histIndex` — переиспользуем позицию
  (back/forward-семантика), иначе обрезаем хвост и добавляем. Кап 50 записей.
- `←`/`→` — переходы (перерисовка шапки и тела), `Alt+←`/`Alt+→` — те же переходы
  (документный слушатель, игнорируется при фокусе в input/textarea композера).
- Кнопки `disabled`, когда перехода нет.
- Смена workspace (`sidebarFilesState` с новым `workspace`) очищает историю и `histIndex`.

### 4.3 Хлебные крошки

Вместо полного пути одной строкой — сегменты по `›`: имя файла ярко, каталоги приглушены
(`var(--dim-c)`), последний сегмент не кликабелен. Клик по каталогу: раскрыть его в дереве,
снять выделение вьюера и перевести фокус на строку дерева (это и есть «откуда открыт файл»).
Длинный путь: сегменты после третьего с конца схлопываются в `…` (кликабельный — раскрывает
список сегментов по клику, без модалки).

### 4.4 Клавиатура в дереве

Строки получают `tabindex="-1"`; курсор — `files.cursor: string | null` (путь). Роулинг не нужен,
фокус = `row.focus()`.

| Клавиша | Действие |
|---|---|
| `↑` / `↓` | предыдущая/следующая видимая строка |
| `→` | папка свёрнута → раскрыть; раскрыта → курсор на первый ребёнок |
| `←` | файл → курсор на родителя; папка раскрыта → свернуть |
| `Enter` | папка →toggle, файл → открыть |
| `Home` / `End` | первая/последняя видимая строка |
| `*` | развернуть все до текущей глубины (дешёвый subset «развернуть всё») |

`tree.addEventListener("keydown")` c `stopPropagation()`, чтобы не конфликтовать с глобальными
`Alt+1..6` (переключение вкладок) и `Escape` сайдбара.

### 4.5 Кнопки: размер и подписи

- Иконочные кнопки в шапке просмотра и в панели дерева: 24×24px, иконка 14px,
  `border-radius: 4px`, `background: transparent`, цвет `var(--dim-b)` → `var(--accent)` на hover.
  Это вместо нынешних глифов `◧`/`✕`.
- Attach-кнопка в строке дерева: цель **на всю высоту строки** (24px), иконка 13px, hover/focus
  (текущий контракт сохранён — не засоряем постоянный вид), `title`/`aria-label` из i18n.
  Клик по ней **не** открывает файл (`stopPropagation`, как сейчас).
- Все `title` — через `t()` (хардкод `attach path`/`close` из HTML убирается: разметка
  создаётся в `files.ts`, ключи проставляются там).

## 5. Frontend: раскладка модулей

`sidebar/files.ts` (leaf) растёт с 316 строк. Целевая раскладка:

| Файл | Ответственность |
|---|---|
| `sidebar/files.ts` | публичный API (`initFiles`, `sidebarFilesState`, `sidebarFilesChanged`, `refreshFilesTree`, `openFile`, `closeFile`), рендер дерева и вьюера |
| `sidebar/files/split.ts` | ширина дерева, drag-сплиттер, `viewerFull`, персист в localStorage |
| `sidebar/files/history.ts` | стек истории, `←`/`→`, `Alt` хоткеи |
| `sidebar/files/keys.ts` | клавиатурная навигация по дереву (курсор, видимые строки) |

Скоупы пересекаются (`openFile` нужен истории, `sidebarFilesState` чистит историю) — общение
через явные функции параметров, без новых взаимных импортов (DAG остаётся ацикличным:
`files.ts` → `files/*.ts`, между `files/*.ts` импортов нет).

`index.html`: `#pane-files` переписывается (`.files-body`, `.files-side`, `.files-bar`,
`.files-splitter`, шапка просмотра с кнопками и крошками). Статические глифы `◧/✕` уходят,
иконки ставятся из `dom.ts`.

`sidebar/state.ts`: `FilesView` += `bodyEl`, `sideEl`, `splitterEl`, `barEl`, `crumbEl`,
`backEl`, `fwdEl`, `maximizeEl`, `expandAllEl`, `collapseAllEl`, `refreshEl`; состояние
`history`, `histIndex`, `cursor`, `expanding`, `treeWidth`, `viewerFull`.

`dom.ts`: `ICONS` += `arrow-left`, `arrow-right`, `chevrons-down-up`, `chevrons-up-down`,
`panel-left` (`panel` уже есть и переиспользуется).

`styles.css`: блок «sidebar Files tab» переписывается; удаляются правила
`:has(.files-detail…)`-хаки (918–919) и `.files-detail { flex: 0 0 360px }`.

## 7. Edge cases

- **Пустой workspace / нет `workspace` в снапшоте** — дерево не фетчится, панель кнопок
  `disabled` (свернуть/развернуть/обновить), локаль i18n не ломает рендер.
- **`expand all` на огромном проекте** — кап 200 папок/4 уровня + явная строка о капе.
- **Файл удалён между кликом и фетчем** — `404` → `web.files.open_failed`, дерево обновляется
  по событию (как сейчас).
- **Перетаскивание сплиттера мышью за пределы панели** — клемп 200–480px, на `pointerup`
  ширина пишется в localStorage; `dblclick` — сброс к дефолту.
- **Тач без hover** — attach-кнопки в дереве на тач-устройствах (`@media (hover: none)`)
  видны всегда; в шапке просмотра кнопки видны всегда.
- **`prefers-reduced-motion`** — переходов ширины не добавляем вовсе.
- **Смена вкладки сайдбара** — ширина дерева и `viewerFull` переживают переключение
  (состояние в `sb.files`, не в DOM).
- **История не должна расти от повторного клика по тому же файлу** — дедуп.
- **Событие `files` (watcher)** — переоткрывает файл из истории, если он текущий;
  перерисовывает дерево; позиция курсора сохраняется, если путь ещё существует.

## 8. i18n (en + ru)

Новые: `web.files.collapse_all` («Collapse all» / «Свернуть всё»), `web.files.expand_all`
(«Expand all» / «Развернуть всё»), `web.files.refresh` («Refresh» / «Обновить»),
`web.files.back` («Back» / «Назад»), `web.files.forward` («Forward» / «Вперёд»),
`web.files.wide` («Hide the tree» / «Скрыть дерево»), `web.files.narrow`
(«Show the tree» / «Показать дерево»), `web.files.expand_capped`
(«Expanded up to the limit of {n} folders.» / «Развёрнуто до лимита в {n} папок.»),
`web.files.tree_width` (aria-label сплиттера: «Tree width» / «Ширина дерева»).

Параметр `{n}` — через существующий механизм подстановки в `i18n.ts` (проверяется в тестах).

## 9. Тестирование

- **DOM (`tests/webui-files-dom.test.ts`, расширяется):** фикстура HTML обновляется под новую
  разметку. Кейсы: дерево **остаётся видимым** при открытом файле (регрессия на исходный баг —
  проверяем, что `treeEl.hidden === false` и в DOM есть `.files-splitter`); кнопки панели
  (свернуть/развернуть/обновить) реально меняют `expanded`; кап развёртки даёт строку;
  история: 3 клика → `←` → `→` возвращают нужный файл, кнопки `disabled` на концах;
  `Alt+←`; крошка каталога раскрывает папку; клавиатура `↓`+`Enter` открывает файл,
  `←` поднимает к родителю; attach-кнопка в строке не открывает файл при клике по ней.
- **Гарды:** `tests/webui-assets.test.ts` — наличие новой разметки (`.files-splitter`,
  `.files-bar`) и отсутствие старых хардкод-`title` (`attach path`); `webui-frontend-graph.test.ts`
  (DAG) и `webui-boundaries.test.ts` (бэкенд не тронут — тривиально).
- **Ворота:** `bun test` + `tsc --noEmit` + `bun run quality` (включая `typecheck:frontend`).

## 10. Вне scope (YAGNI)

Редактирование файлов; git-декорации; фильтр/поиск по дереву; drag-and-drop файла в чат;
мультивыбор; «закрепить файл» (pinned tabs из варианта B) — отдельная задача, если понадобится
сравнивать два файла; перенос просмотра в область чата.

## 11. Отклонённые варианты

- **B. Preview/pinned-табы (VS Code).** Даёт «закреплённые» файлы и сравнение двух файлов, но
  требует полноценной полосы вкладок и воспроизводит ровно ту боль, из-за которой VS Code
  собирает жалобы: preview-вкладка исчезает при следующем открытии
  ([issue #9388](https://github.com/microsoft/vscode/issues/9388)). Сплит решает исходную
  жалобу дешевле; табы можно добавить поверх сплита позже.
- **C. Drawer/оверлей поверх ленты.** Ломает «сайдбар = контекст», перекрывает чат, хуже на
  узких окнах (master-detail прямо требует стек-режима с «Back to list», это лишняя работа).
- **«Зритель во весь сайдбар» как единственный режим.** Ровно текущее поведение, с которого
  начали; осталось доступно как переключатель «развернуть просмотр».

# Спека: персист темы веб-UI в конфиге

_Дата: 2026-10-30 · Ветка: `feat/webui-theme-persistence` · Тип: MINOR (новые ключи конфига)_

## 1. Проблема

**Репро.** `mma web` → Settings → UI & Theme → выбрать тему (скин) или режим
(dark/light/auto) → перезапустить `mma web` (в т.ч. `bun run web:dev`, где процесс
перезапускает `--watch`) → тема снова `console`/`auto`.

**Причина.** Тема живёт только в `localStorage` (`mma-theme`, `mma-ui-theme`), а
`mma web` по умолчанию слушает **порт 0** — «любой свободный»:

- `src/cli/web-command.ts:37-44` — пустой `--port` → `undefined`;
- `src/modules/webui/server.ts:242` — `Number(readEnv("WEBUI_PORT")) || 0` → `listen(0)`;
- `src/modules/webui/server.ts:253` — origin = `http://<host>:<фактический порт>`.

`localStorage` привязан к origin (схема + хост + **порт**). Новый процесс → новый
порт → новое хранилище. Вместе с темой теряются и остальные браузерные ключи
(открытые табы сессий, ширина дерева файлов, активная вкладка сайдбара) — но эта
спека чинит **только тему**: остальные ключи остаются browser-local (см. §5).

**Почему не стабильный порт.** Порт — тоже контракт: два экземпляра `mma web`
конфликтуют, а тихий откат на рандом возвращает ту же потерю. Хранение темы в
конфиге снимает зависимость от origin целиком, в отличие от фиксации порта.

## 2. Решение

Тема становится **серверной настройкой** конфига (`config.json`):

| Ключ | Тип | Значения | Дефолт |
|---|---|---|---|
| `ui.theme` | enum | `console` · `groovebox` · `flat` · `neon` · `paper` · `contrast` · `winter` · `spring` · `summer` · `autumn` | `console` |
| `ui.themeMode` | enum | `dark` · `light` · `auto` | `auto` |

`localStorage` остаётся **проекцией** (кэш), а не источником правды:

- inline-скрипт в `index.html` читает кэш **до первой отрисовки** (анти-вспышка) —
  поведение не меняется;
- после `GET /api/config` клиент применяет значения из конфига и переписывает кэш.

**Почему конфиг, а не отдельный `webui-prefs.json`.** Запись идёт уже существующим
единым путём `POST /api/config` (валидация реестром, атомарный `saveConfig`,
broadcast `config`, i18n-лейблы, гейт занятости). Отдельный файл — второе хранилище
рядом с конфигом, со своим парсером, миграцией и точкой записи. Прецедент —
`ui.fontSize` (`src/config/registry-extra.ts:332`): веб-настройка в общем конфиге.

**Цена решения (осознанная).** Тема — установки, а не браузера: два браузера на одном
`mma web` делят одну тему, последняя запись побеждает. `1 тенант = 1 процесс`, так
что это соответствует модели развёртывания.

## 3. Контракт и инварианты

- **INV-T1. Источник правды — конфиг.** На каждом `loadConfig()` клиент применяет
  `ui.themeMode`/`ui.theme` и обновляет кэш. Пикер показывает значение из конфига.
- **INV-T2. Кэш — только для pre-paint.** Inline-скрипт `index.html` читает
  исключительно `localStorage` (синхронности ради). Следствие: на **новом** origin
  (первый кадр после перезапуска) возможна короткая вспышка дефолтной темы до
  прихода `/api/config`. Это принято: правка pre-paint потребовала бы шаблонизации
  статики или cookie.
- **INV-T3. Запись темы не ждёт `turn_end`.** `ui.theme`/`ui.themeMode` имеют
  `effects: []` и не трогают раннер, поэтому `POST /api/config` для них проходит и
  при `busy`; остальные ключи по-прежнему получают `409 busy`. Иначе переключение
  темы во время ответа модели молча терялось бы.
- **INV-T4. Один список скинов на слой.** Каталог `UI_THEMES` во фронтенде
  (`assets/js/settings/themes.ts`) — единственный источник id для пикера; реестр
  конфига обязан совпадать с ним, это держит гвард.
- **INV-T5. Миграция кэша — один раз.** Если сервер держит **дефолт**, а кэш этого
  origin содержит **другое** валидное значение — значение кэша один раз
  доливается в конфиг (иначе апгрейд вернул бы всем `console`/`auto`). После записи
  конфиг и кэш совпадают, повторной миграции нет. Риск «затрём дефолт, выбранный
  в другом браузере», принят как следствие модели «тема на установку».

## 4. Точки изменения

| Слой | Файл | Что |
|---|---|---|
| Каталог id | `src/config/theme-ids.ts` (новый) | `UI_THEME_IDS`, `ThemeMode` — валидация и типы бэкенда |
| Типы | `src/config/types.ts` | `UiConfig.theme?`, `UiConfig.themeMode?` |
| Дефолты | `src/config/defaults.ts` | `theme: "console"`, `themeMode: "auto"` |
| Реестр | `src/config/registry-extra.ts` | два `enumOf(..., reconfigure=false)` |
| i18n | `src/i18n/en.json`, `ru.json` | `config.key/desc.ui.theme*` + правка описания секции |
| Гейт занятости | `src/modules/webui/settings/config-api.ts` | исключение для `ui.theme*` |
| Фронт: состояние | `assets/js/settings/theme-state.ts` (новый) | чистые функции: валидация, резолв, миграция |
| Фронт: применение | `assets/js/settings/theme.ts` (новый) | apply/sync + кэш + `syncThemeFromConfig` |
| Фронт: карточка | `assets/js/settings/theme-panel.ts` (новый) | режим + пикер, POST и откат при ошибке |
| Фронт: панель | `assets/js/settings/panels.ts` | тема вынесена отсюда (файл у ceiling 880) |
| Фронт: загрузка | `assets/js/settings/write.ts` | `loadConfig()` синхронизирует тему |
| Фронт: boot | `assets/app.ts` | миграция кэша после первого `loadConfig()` |

## 5. Вне рамок

- Открытые табы, ширина сплиттера, вкладка сайдбара остаются browser-local.
- Тема не переносится в терминал (`mma`, REPL): там своей системы тем нет.
- UX первого кадра на новом origin (INV-T2) не оптимизируется.
- Настройка темы не появляется в поиске настроек (известный B-12, отдельная задача).

## 6. Проверки (гейты)

- `tests/config-registry-extra.test.ts` — дефолты и round-trip `ui.theme`/`ui.themeMode`,
  отказ невалидному значению.
- `tests/webui-themes.test.ts` — реестр `ui.theme` совпадает с `UI_THEMES`
  (INV-T4), `ui.themeMode` = `dark|light|auto`, лейблы en/ru.
- `tests/webui-theme-state.test.ts` (новый) — резолв «конфиг → кэш → дефолт»,
  миграция (дефолт+кэш → долив; не дефолт → нет; невалидный кэш → нет), идемпотентность.
- `tests/webui-busy-guard.test.ts` — `ui.theme` пишется при `busy`, `contextWindow` — нет
  (INV-T3).
- `tests/i18n.test.ts` — новые ключи реестра имеют лейблы (существующий гвард).
- `tests/arch/file-size.test.ts` — `panels.ts` уходит из-под ceiling (потолок снижается).

## 7. Откат

Откат ветки. Старый билд игнорирует незнакомые ключи `ui.theme*` (реестр их не
знает), конфиг остаётся валидным; тема просто снова станет browser-local.

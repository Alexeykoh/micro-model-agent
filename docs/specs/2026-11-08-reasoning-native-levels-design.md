# Нативные уровни reasoning вместо канонических алиасов

**Дата:** 2026-11-08 · **Ветка:** `feat/reasoning-native-levels` · **Статус:** реализация

## Проблема

UI показывал `high` для уровней, которых сервер не объявлял: llama.cpp
заявляет `["low","medium","xhigh"]`, а селектор показывал `["none","low","medium","high"]`
через алиас `xhigh → high` (`reasoning-view.ts:34`). Это нарушает честность
(INV-R7): показываются уровни, которых сервер не отдаёт.

## Что правильно

1. **UI показывает только объявленные сервером уровни — своими именами,
   в серверном порядке** (+ `none`, если есть off-switch; + режимные
   `auto`/`default`, это не уровни, а режимы политики).
2. **Канонический набор расширяется** на `minimal` и `xhigh` как
   первоклассные значения (`ReasoningLevel`, `REASONING_LEVELS`,
   `REASONING_BOUNDS`, `set_thinking`, `config-mutations`, `chunk-query`).
   Старые значения остаются валидны (обратная совместимость конфигов).
3. **Auto-политика клампится на объявленные уровни.** Резолвер получает
   `reasoningLevels` активного эндпоинта (тот же трёхслойный резолв, что
   `reasoningStrategy`: override → probe → preset) и проецирует канонический
   выход политики на серверный список (ближайший не ниже, иначе высший —
   та же проекция, что на проводе в `request-body.ts`). Диагностика
   (`logReasoningControl`) и `thinkingLevel` честно показывают то, что
   реально уйдёт на сервер, а не формальное `high`.
4. **Fallback при неизвестных уровнях — честный:** селектор показывает
   только `auto`/`default`, а не выдуманные `low/medium/high/max`.

## Инварианты

- INV-R7 усилен: видимый список = объявленный сервером список (кроме
  режимных `auto`/`default` и off-switch `none`).
- INV-R2: уровни резолвятся тем же трёхслойным путём, что и стратегия.
- Проекция политики и проекция на проводе используют один алгоритм
  (`projectLevel` в `request-body.ts`, реэкспорт для резолвера).

## Вне скоупа

- Менять пресеты провайдеров или порядок `reasoning_effort_levels` на сервере.
- `high`/`max` для llama.cpp: проекция в `xhigh` остаётся на проводе
  (страховка от strict-400), но в UI их больше нет.

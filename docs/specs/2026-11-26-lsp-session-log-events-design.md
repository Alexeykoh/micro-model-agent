# LSP-события жизненного цикла в session.jsonl

**Дата:** 2026-11-26 · **Статус:** accepted · **Ветка:** `feat/lsp-session-log-events`
**Оплачивает:** долг `lsp-session-log-events` из `docs/agents/debt.md`.

## 1. Проблема

События `warm_project`, `warm_start`, `ready`, `warm_failed`, `check`, `check_cold`,
`write_check` и их варианты `*failed` пишутся только в `app.jsonl` через
`LspModule.log()`. В `session.jsonl` их нет: разбор сессии не видит, был ли сервер
тёплым и сколько заняла проверка. У `LspModule` нет сессионного стока, а новый
тип записи расширяет публичный контракт журнала.

## 2. Решение

1. В `SessionLogEntry.type` добавляется аддитивный тип `"lsp"`. Поля — уже
   существующие: `module: "lsp"`, `op` (фаза), `duration` (мс, когда известна),
   `content` (человекочитаемое сообщение). Новых обязательных полей нет. Формат
   строк журнала (JSONL) не меняется.
2. `SessionLogger.logLsp(op, message, meta?)` — единственная точка записи;
   `ts` и `source` проставляются существующим механизмом `log()` (INV-13).
3. `LspModule` получает опциональный sink `setSessionSink((op, msg, meta) => void)`
   и вызывает его из того же `log()`, где сегодня пишется `app.jsonl`. Оба лога
   получают одно и то же событие; падение sink'а не роняет модуль (fail-open как
   у обычного логгера).
4. На границе хода `turn-run.ts` после создания `SessionLogger` из
   `deps.moduleRegistry` берётся модуль `lsp` и подключается sink. Для тестов и
   headless-контуров без реестра модуль работает как раньше (только app-лог).

## 3. Что не меняется

- REST/SSE-контракт веба и схема `ModuleDef` — без изменений.
- Причины ошибок остаются в `content`; ни один текст не попадает в `op`.
- Старые записи `session.jsonl` читаются как раньше: новый тип просто добавляется.

## 4. Критерий выхода

1. В `session.jsonl` видны LSP-события с фазой (`op`) и длительностью, если она
   была в метаданных.
2. Тест подключает sink к `LspModule`, вызывает `log()` и читает запись из
   сессионного лога; без sink'а запись не создаётся.
3. `bun test` и `bun run quality` зелёные; гейд `tests/arch/debt-register.test.ts`
   проходит после снятия якоря долга.

# Звуки в `mma web` — дизайн

**Дата:** 2026-10-31 · **Статус:** принято · **Ветка:** `feat/webui-sounds`

## Задача

Веб-UI не подаёт звуковой сигнал о событиях агента: если пользователь ушёл в
другую вкладку, он узнаёт о завершении хода, вопросе модели или падении только
после возврата. Нужны три коротких сигнала, которые можно выключить, и
настройка, которая живёт в конфиге профиля, а не в одном браузере.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Чем играть | WebAudio-синтез, без аудиофайлов | нет ассетов, лицензий и веса бандла; три сигнала — это ~60 строк |
| Когда играть | всегда, независимо от фокуса вкладки | выбрано пользователем: простое и предсказуемое поведение без магии `visibilityState` |
| Где настройка | конфиг (`ui.sounds.*`), Settings → UI | переживает перезапуск, общая для браузеров, попадает в поиск настроек |
| События | конец хода, вопрос, ошибка | выбрано пользователем |
| По умолчанию | мастер выключен, события включены | «quiet by default» (STYLE.md): звук не появляется сам после апгрейда |

## Инварианты

- **INV-S1 (единственная точка решения).** Какой сигнал играть, решает чистая
  функция по паре `(предыдущий статус, новый статус)`. Отрисовка, SSE и DOM
  на решение не влияют.
- **INV-S2 (только реальный переход).** Сигнал допустим лишь при смене статуса
  вкладки. Гидратация, восстановление вкладок после F5, повтор того же статуса,
  `dead` и первый синк состояния молчат.
- **INV-S3 (мастер главнее).** `ui.sounds.enabled = false` выключает все сигналы
  независимо от значений `ui.sounds.done|question|failed`.
- **INV-S4 (fail-open без шума).** Если браузер не разрешил автовоспроизведение
  (`AudioContext` не `running`), сигнал тихо пропускается: без исключений,
  без сообщений в консоль, без влияния на ленту и статусы.
- **INV-S5 (настройка — в реестре).** Ключи объявлены в
  `src/config/registry-extra.ts` и имеют i18n-метки в `en`/`ru`; отдельного
  `localStorage`-хранилища для звука нет.

## Триггеры

Звук вешается на переходы статуса вкладки, а не на отдельные SSE-события:
`setTabStatus()` (из SSE `question`/`turn_end`/`error`) и
`reconcileTabStatuses()` (сверка с серверным `state`). Оба пути проходят через
одну функцию уведомления.

| Новый статус | Условие | Сигнал |
|---|---|---|
| `idle` | предыдущий — `working` | `done` |
| `waiting` | предыдущий — не `waiting` | `question` |
| `failed` | предыдущий — не `failed` | `failed` |
| прочее | — | тишина |

Звук играет и для неактивной вкладки: у пользователя может быть открыто
несколько сессий, и завершение любой из них — полезная новость.

## Сигналы

Все — тихие (gain ≈ 0.05), короткие (≤ 250 мс), различимые по контуру:

- `done` — две восходящие ноты (660 → 880 Гц);
- `question` — двойной тон одной высоты (520 Гц);
- `failed` — две нисходящие ноты (330 → 240 Гц).

Троттлинг: не чаще одного сигнала в 150 мс; одинаковый сигнал — не чаще раза в
600 мс. Это гасит «кашу», когда несколько вкладок завершаются одновременно.

## Реализация

```
assets/js/sounds.ts        резолв настроек, cueForTransition, shouldEmit,
                           playCue (WebAudio), разблокировка по первому жесту
session/tabs.ts            вызов notifyTabStatus(prev, next) на переходах
settings/controls.ts       секция ui.sounds в PANEL_SECTIONS
config/{types,defaults,registry-extra}.ts   ключи и дефолты
i18n/{en,ru}.json          config.key/desc.* + web.settings.sec.ui.sounds*
tests/webui-sounds.test.ts чистые правила (INV-S1…S3)
```

### Настройки

| Ключ | Тип | Дефолт | Смысл |
|---|---|---|---|
| `ui.sounds.enabled` | bool | `false` | мастер-выключатель |
| `ui.sounds.done` | bool | `true` | конец хода |
| `ui.sounds.question` | bool | `true` | агент ждёт ответа |
| `ui.sounds.failed` | bool | `true` | ход упал |

Фронтенд читает их из `settings.config.ui.sounds` в момент сигнала, поэтому
переключатель срабатывает без перезагрузки страницы. Невалидные/отсутствующие
значения трактуются как дефолты.

### Автовоспроизведение

`AudioContext` создаётся лениво при первом сигнале. Браузерная политика
разрешает звук только после жеста пользователя, поэтому контекст дополнительно
возобновляется на первых `pointerdown`/`keydown` (once-слушатели). До
разблокировки `playCue` проверяет `state === "running"` и молча выходит
(INV-S4).

## Не входит в задачу

Свои звуковые файлы и импорт, регулировка громкости, звуки кликов/тулов,
системные уведомления ОС, звуки в терминале, история/политика «не беспокоить».

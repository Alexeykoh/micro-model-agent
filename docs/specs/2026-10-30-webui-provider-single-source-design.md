# Один источник правды для активного провайдера (2026-10-30)

## Дефект

Живой скриншот 0.18.6: в настройках «Модель и провайдер» бейдж **активен**
стоял на `opencode-go`, а чип композера показывал `провайдер: lmstudio`.
Пользователь не мог понять, какой провайдер реально используется.

Причина — два разных снимка состояния:

- чип композера (`settings/write.ts`) читал `settings.config.provider` —
  живой конфиг, обновляемый после каждого переключения;
- список провайдеров (`settings/providers.ts`) сначала брал
  `settings.providers.active` — снимок `GET /api/providers`, загруженный при
  открытии формы и не обновляемый при переключении.

Плюс серверный вью-слой (`buildProviderViews`) отдавал `active` как
`provider.active || provider.type`: легаси-`type` (например `lmstudio`) мог не
совпадать ни с одной записью `entries` (`opencode-go`/`lmstudio`), и UI
показывал «ни одного активного» либо чужое имя.

## Контракт

1. **Активный провайдер — всегда `config.provider`.** Любая поверхность
   (чип, список, стартовый баннер, меню выбора) читает его; снимок
   `/api/providers` — только метаданные записей, не авторитет.
2. `GET /api/providers` возвращает `active` только если это имя реально есть
   среди `entries`; иначе — первая запись, а при пустых `entries` — легаси
   `provider.type`.
3. Переключение (`POST /api/config {key:"provider.active"}`) обновляет живой
   конфиг до перерисовки: чип и список меняются одним действием.
4. Стартовый баннер хода показывает провайдера из конфига, а `session.host`
   остаётся фолбэком (исторические сессии без свежего конфига).

## Проверка

- `tests/webui-provider-active-consistency.test.ts`:
  - `buildProviderViews` сохраняет активное имя, совпадающее с записью;
  - легаси/чужое имя → первая запись;
  - пустые `entries` → легаси `type`;
  - при устаревшем `settings.providers.active` список помечает провайдера из
    живого конфига (ровно один `.provider-item.active`).
- Живой прогон: переключение `lmstudio → opencode-go → lmstudio` через
  `POST /api/config`; чип и бейдж совпадают на каждом шаге.

Ни одно исправление не должно быть выведено из «как было бы хорошо для лендинга» — только из
обобщённых инвариантов.

## 1. Инварианты (ломать нельзя)

Ни один пункт спеки не считается готовым, пока не выполнены все инварианты:

1. **Публичные контракты неизменны.** SSE/REST, `session.jsonl`, plugin API, `LLMProvider`,
   формат `Plan` — только аддитивные поля. Существующие потребители не переписываются.
2. **Behavior-parity по умолчанию там, где рискованно.** Изменения ядра (компакция, план)
   закрыты конфиг-флагами с сохранением легаси-пути (`contextBudget.policy`,
   `execution.autoAdvance`). Флаг `legacy` воспроизводит поведение 2.18.2.
3. **Degrade gracefully.** Отсутствие `usage` от провайдера, недоступность LLM-суммаризатора,
   отсутствующий `rg`/`grep`, `ENOENT` — не блокируют ход и не роняют агента; всегда есть
   безопасный фолбэк.
4. **Fail-open на неопределённости.** Неуверенное определение (обрезка провайдером, класс
   ошибки, fuzzy-match) ведёт к консервативному поведению, а не к агрессивному.
5. **Никаких новых hard-зависимостей без отдельного решения.** Пакет намеренно лёгкий
   (см. 2.17.1). Опциональные движки — только опционально.
6. **Никакой task/language-специфики.** Код не знает про велосипеды, React, CSS, конкретный
   язык. Любая эвристика формулируется на общих понятиях (файл, команда, артефакт, план).
7. **Обсервабельность.** Каждое новое решение (калибровка, выбор стратегии компакции, отказ)
   видно в `session.jsonl`/`session show`, чтобы валидировать в бою.

### 1.1 Generality checklist (прогоняется для каждой фазы)

- Задача не про код: «забронируй отель, пришли письмо, узнай погоду, разбери JSON с URL» —
  пайплайн не деградирует и не создаёт ложных файловых проверок.
- Другой язык/экосистема: Rust (`cargo`), Go (`go test`), Python (`pytest`), документы и
  конфиги — ни один путь не завязан на JS-специфику.
- Пустой/минимальный проект, проект-сирота, не-UTF8 имена, Windows и Posix.

## 2. Проблемы

### P0 — Токенный эстиматор оторван от реальности (первопричина каскада)

- `getEstimatedTokens()` (`src/modules/context/manager.ts:610-615`) считает сумму сообщений +
  `toolTokens`; для порогов компакции используется как есть.
- `estimateMessageTokensCached` (`manager.ts:351-363`) кэширует значение в `WeakMap` по
  идентичности объекта под допущением «сообщение иммутабельно после добавления». Наблюдался
  скачок оценки **11.5K → 55.6K при добавлении 2 сообщений** на границе хода (20:15:18), при
  фактическом промпте 10 799. Суммарный объём всей истории сессии — 185 087 символов (~50K
  токенов на 235 сообщений), т.е. 23 маленьких сообщения физически не могут быть 55K токенов.
- `cl100k`-оценка кириллицы/кода систематически завышает фактические токены Qwen (медиана
  после прогрева 0.9×, но на «раздутых» состояниях до 4.85×).
- Рассинхрон формул тул-токенов: `agent.ts:886-889` (`estimateTokens`, script-aware) и
  `agent.ts:902-906` (`Math.ceil(len/4)`).

**Последствия:** ложные overflow-компакции, обход guard'а `resetUserTurn` (`manager.ts:246-253`),
изъятие 12 сообщений на старте нового хода пользователя, потеря рабочего состояния.

> **Честно:** скачок +44K до конца не доказан (WeakMap — гипотеза). Поэтому фаза 0 начинается
> с *диагностики и доказательной починки кэша*, а не со слепого патча, и добавляет safety-clamp.

### P1 — Политика компакции без cooldown и без гарантии прогресса

- `compactOnOverflow` (`src/core/agent/compaction.ts:89-106`) сравнивает **весь** контекст
  (system + tools + history) с `budget.history` (75% окна **минус** system/tools) — категориальная
  ошибка порога.
- У overflow нет cooldown (в отличие от quality, `FORCED_COMPACTION_COOLDOWN = 3`,
  `constants.ts:34`), поэтому он срабатывает каждую итерацию.
- `compact()` (`manager.ts:427-526`) сохраняет `KEEP_LAST_N*2 = 12` сообщений; если их
  «оценка» уже выше порога, функция возвращает результат, но объём не падает → no-op,
  который всё равно логируется и инкрементит `compactionCount`.
- За одну итерацию срабатывают `compactAfterTool` + `compactIfNeeded` (interval + quality +
  overflow) → до 3 записей компакции на шаг.
- Нет реактивной компакции на recoverable-ошибку провайдера «context length exceeded» с
  circuit-breaker.

### P2 — Рассинхрон плана и шагов

- `advancePlanIfStepComplete` (`src/modules/execution/module.ts:750-884`), вызываемый после
  каждого FS-мутирующего тула (`execution-plugin.ts:551`), **молча** помечает шаг `done` по
  факту существования файлов из описания шага; затем план авто-архивируется
  (`module.ts:877-884`).
- Модель продолжает звать `plan_step`/`re-plan` → **«Нет активного плана»** (5 раз), `plan_step
  step=1` по завершённому плану (2 раза).
- `checks` обязателен 1:1 со `steps` (`module.ts:956-980`, `plan-tool.ts:98,122`), но ошибка
  `plan.checks_mismatch` (`ru.json:235`) не сообщает числа → **13 провалов `plan`**, из них 8
  подряд на одном сообщении. Топ-категория провалов сессии.
- `autoCloseEvidenceSteps` (`module.ts:478-517`) закрывает шаги по существованию файлов при
  финальном аудите.

### P3 — Портируемость и окружение тулов

- `grep` падает на Windows: fallback на системный `grep`, которого нет →
  `Executable not found in $PATH: "grep"` (`src/tools/grep-tool.ts:137-153`). 2 провала,
  поиск по содержимому фактически недоступен.
- bash: 15 security-блоков на `&&`/`>`/`|`; модель не переходит на `workdir`; изобретает
  флаги (`bun run build --cwd`) — 5 раз.
- Модель вызывает тулы как shell-команды (`process_log id=...`, `process_list`,
  `process_wait`, `lsp_check path=...`, `browser open`). Редирект реализован точечно
  (только `browser`, `process_list`).
- 6 фоновых dev-серверов, нет переиспользования/дедупа/своевременного reap.

### P4 — Слабо-модельный UX

- Ошибки тулов не структурированы (`code/retryable/hint`), нет top-k подсказок.
- `load_skill css-expert` → «не найден» (доступен `css-styling-expert`) — нет fuzzy-match.
- Пустое сообщение пользователя запускает полный ход с компакцией.

## 3. Цели / Non-goals

**Цели:**

1. Оценка контекста, пригодная для решений о компакции (±15% от фактического usage в
   оговорённых условиях) и безопасно деградирующая вне них.
2. Компакция: канонический порог, cooldown, гарантия прогресса, слоистость, один триггер,
   легаси-откат.
3. План: предсказуемое владение статусом, actionable-ошибки, отсутствие тупиковых циклов.
4. Тулы: кросс-платформенный поиск без новых зависимостей, понятные ошибки, переиспользование
   процессов.
5. Слабо-модельные митигации: структурированные ошибки (не протекающие в чат), fuzzy-скиллы,
   защита от пустого ввода.

**Non-goals:**

- Не меняем публичные контракты (см. инвариант 1).
- Не переписываем архитектуру агента/Orchestrator/MoE.
- Не оптимизируем под конкретную модель, задачу или язык.
- Не добавляем новых hard-зависимостей.

## 4. Industry patterns (лучшие практики)

1. **Layered compaction** (Anthropic «Effective context engineering», Claude Code, OpenAI
   App Server, LangChain): сначала детерминированно чистить старые tool-результаты
   (перечитываемы), затем тримминг, только затем LLM-суммаризация. Констрейнты (system,
   активный план, задача) закреплены и переживают компакцию («constraint pinning»).
2. **Threshold от эффективного окна**: `effective = window − reserve` (Pi: window−16K;
   Claude Code: 90–95%; Anthropic: 5–20K для части задач). Пороги — по фактическому usage
   там, где он есть.
3. **Calibrated estimation** (`sausheong/harness` — `tokens/ char-4 estimator + Calibrator +
   CalibratorStore`; Strands — baseline+delta от последнего `usage`): эстиматор даёт дельту,
   baseline — реальные `prompt_tokens` провайдера; периодическая калибровка, но только при
   доверии источнику.
4. **Actionable structured errors** (LangChain deepagents `ToolErrorMiddleware`; OpenAI Codex;
   arXiv 2412.04093 «informed retry»): ошибка как данные `{code, retryable, hint}`, повтор
   только при retryable, bounded retries (same args → 1).
5. **Plan — внешнее состояние** (plan-and-execute, arXiv 2604.12147): план детерминированно
   грузится каждый цикл; эвристика не переписывает статусы молча; re-plan по evidence.
6. **Cross-platform search без бинарей**: ripgrep first-class на Windows, но для лёгкого
   пакета предпочтителен zero-dep JS-обход; системный `rg` — ускорение, не обязательство.
7. **Managed subprocesses** (OpenAI/SWE-harness): bounded output, дедуп, join/cleanup на конце
   сессии (не на конце хода).

## 5. Дизайн

### Фаза 0. Диагностика и калибровка контекста

**0.1 Диагностика (до патчей).** Добавить в `context`-событие аддитивные поля
`estimatedTokensRaw`, `contextTokens`, `calibrationRatio`, `calibrationState`
(`cold|warming|trusted|stale`). Воспроизвести скачок +44K фикстурным тестом; локализовать
источник (WeakMap vs иной путь мутации сообщения).

**0.2 Починка измерения.** `estimateMessageTokensCached` — инвалидация кэша на `addMessage`,
`compact`, `updateSystemPrompt` (или ключ по сигнатуре контента). Унифицировать расчёт
tool-токенов на оба места `agent.ts:886-907`.

Новый модуль `src/core/agent/context-calibration.ts`:

```ts
export type CalibrationState = "cold" | "warming" | "trusted" | "stale";

export interface CalibrationSample { actual: number; estimated: number; messageCount: number; }

export class ContextCalibrator {
  /** Реальные токены и число сообщений на момент последнего usage. */
  observe(actual: number, estimatedAtSend: number, messageCount: number): void;
  /** Инвалидация baseline: компакция, reconfigure, смена system-промпта, отсутствие usage. */
  invalidate(): void;
  /** Калиброванная оценка либо консервативный фолбэк. */
  calibrate(estimatedTotal: number, messageCount: number): number;
  getState(): CalibrationState;
  getRatio(): number;
}
```

**0.3 Правила калибровки (критично для безопасности):**

- **Primary — baseline+delta:** `calibrated = baseline.actual + (estimatedTotal −
  estimatedAtBaseline)`, где baseline инвалидируется при любом переписывании истории/промпта.
- **Фолбэк — EMA-ratio** `actual / estimatedAtSend`, `alpha = 0.3`, минимум 2 сэмпла, только
  в состоянии `warming`.
- **Floor-ratio (guard от обрезки провайдером):** калибровка не опускает значение ниже
  `max(raw * ratioFloor, raw - absoluteSlack)` (`ratioFloor = 0.5`). Если провайдер молча
  усекает промпт, `actual` маленький — мы **не** учимся считать раздутый контекст дешёвым.
- **Shadow-период:** первые `calibrationWarmup = 3` вызова состояние `cold`/`warming` — пороги
  считаются по `raw`; калибровка только логируется.
- **Stale:** нет `usage` > 1 вызова или invалидация → фолбэк на `raw`, состояние `stale`.
- **Кламп:** итог всегда в `[ratioFloor * raw, raw]` — калибровка только снижает завышение, не
  поднимает занижение (raw консервативен сам по себе).

**0.4 Точки интеграции.**

- `ContextManager`: `getContextTokens()` — единственный вход для порогов/`getBreakdown`/
  `web-usage`; `getEstimatedTokens()` сохраняется для бюджета prompt-блоков.
- **Явный список вызовов `getEstimatedTokens()` и решение по каждому:** cost-tracking
  (`token-tracker.logUsage`) — оставить raw (учёт стоимости по факту идёт из API-usage);
  prefix-monitor — оставить raw; critic/evidence — оставить raw; пороги компакции — перевести
  на `getContextTokens()`. Список фиксируется в спеке тестом-инвентарём.
- **Хук:** в `agent.ts` рядом с `chunk.usage` (`agent.ts:1068-1074`) вызывать
  `contextManager.calibrate(usageTokens.prompt, estimateAtSend, messageCount)`, где
  `estimateAtSend` снят перед вызовом LLM. При отсутствии `usage` — `calibrate` не зовётся
  (state→`stale`).

**0.5 Safety-clamp (guard от мега-компакции).** Если `estimatedTotal` (в токенах) вырос более
чем в `implausibleJump = 3×` относительно предыдущего значения **без** соответствующего роста
объёма сообщений (допустимый рост ≤ `maxPlausibleDelta`, например 20K токенов) — компакция по
этому сигналу **не запускается**, пишется `warn`-диагностика. Это защищает даже от не найденной
причины скачка.

### Фаза 1. Политика компакции

Изменения `src/core/agent/compaction.ts` + `manager.ts`, за флагом
`contextBudget.policy: "legacy" | "v2"` (default `v2`; `legacy` = поведение 2.18.2).

1. **Канонический порог overflow (одно условие, без OR):**
   `getBreakdown().history > budget.history`.
   Почему достаточно: `historyBudget = window − systemBudget − reserve`, а
   `getBreakdown().history = used − system − tools`, т.е. условие эквивалентно
   `used − system ≈ ≥ window − reserve` с учётом собственного system-промпта. Отдельное
   сравнение total с окном не добавляем, чтобы не получить двойной триггер.
2. **Cooldown.** `state.lastOverflowCompactionIteration` (в `LoopState`, per-run); не чаще
   раза в `FORCED_COMPACTION_COOLDOWN`.
3. **Гарантия прогресса.** `compact()` возвращает `reducedBy`. Если `reducedBy <= 0`:
   - stage A: детерминированная чистка **старых** tool-результатов (оставляем последние
     `toolResultKeep = 6`; никогда не трогаем последние `KEEP_LAST_N` сообщений и
     paired-группы);
   - stage B: тримминг старейших групп сверх `KEEP_LAST_N`;
   - stage C: LLM-суммаризация.
   После каждой стадии — пересчёт; останов, как только ушли ниже порога. Если прогресса нет даже
   после C — жёсткий дроп старейших не-pinned групп с `warn`; триггер в этой итерации больше не
   запускается.
4. **Pinning.** В тримминг/суммаризацию всегда проносить: system-промпт, активный план
   (`planSummaryProvider`), текущую задачу (`lastUserTask`/`sessionMission`).
5. **Один триггер на итерацию.** `compactIfNeeded` (policy) исполняется один раз в начале
   итерации; `compactAfterTool` — лёгкий pre-check, выставляющий флаг, который исполняет
   основной триггер. Дублирующие записи убрать.
6. **Учёт.** `compactionCount` и запись — только при `reducedBy > 2% budget.history`; no-op не
   логируется.
7. **Реактивная компакция.** Классификатор context-length ошибки — консервативный (по коду и
   явному признаку); при неуверенности не срабатывает (fail-open). Один форсированный `compact()`
   + retry, circuit-breaker `state.reactiveCompactionUsed` — не более одного раза за ход.

**Конфиг (аддитивно):** `contextBudget.policy` (`legacy|v2`, default `v2`),
`contextBudget.overflowCooldown` (int, default = `FORCED_COMPACTION_COOLDOWN`),
`contextBudget.toolResultKeep` (int, default 6),
`contextBudget.calibrationWarmup` (int, default 3),
`contextBudget.ratioFloor` (share, default 0.5).

### Фаза 2. План и шаги

1. **Владелец статуса.** `advancePlanIfStepComplete` остаётся мутацией, но:
   - **никогда не архивирует план до `onTurnEnd`**; авто-архив — на границе хода;
   - на каждый auto-advance модель получает явный `<system-summary>`: «Шаг N авто-завершён
     харнессом (файлы на месте). Если работа не закончена — `plan_step step=N status=failed`
     и продолжай»;
   - конфиг `execution.autoAdvance` (bool, default true). При `false` — **сохраняется**
     step-gate nudge (не оставляем шаги застревать, регресс ses_mup6p61q).
2. **Нет активного плана — actionable.** `plan.no_active` дополняется: последний завершённый
   план (`id`, `title`, прогресс) + «создай новый через `plan create`». `plan`, `plan_step`,
   `re-plan` после архива отвечают одинаково.
3. **Авто-архив объявляется.** При архивации — model-visible `plan.completed_archived_notice`
   до следующего вызова тула.
4. **`checks` — необязательный (ключевое решение после grill-me).**
   - Если `checks` отсутствует → харнесс проставляет `manual:<краткая формулировка шага>`
     (self-certified, **никогда не блокирует**). Системный промпт и описание тула обновляются:
     checks «recommended», не «required».
   - **Авто-деривация `file-exists:` не делается.** Она предполагает «шаг создаёт файл» и на
     не-кодовых/`delete`/URL-шагах даёт ложный жёсткий чек, способный заблокировать прогресс —
     это overfit и риск сломать агента.
   - Если `checks` передан, но длина не совпала → actionable-ошибка с числами
     `{expected, actual}` + пример (не тупик).
   - `file-exists:`/`command:` семантика не меняется.
5. **План-чеклист каждый ход** — проверить, что `refreshSystemPrompt` уже инжектит чеклист;
   если да — только тест-сторож, без новых правок (industry: load core files each loop).

### Фаза 3. Тулы и портируемость

1. **grep — без новых зависимостей.** Резолвер: системный `rg` → системный `grep` → **zero-dep
   JS-обход** дерева.
   - JS-обход: regex, `include`-глоб, пропуск бинарных/крупных файлов, уважение
     `.gitignore`/`.mmaignore` (`src/modules/indexer/gitignore.ts`) и `indexer.maxFiles`,
     жёсткий лимит времени/размера, потокобезопасно завершаемый.
   - конфиг `tools.grepEngine` (`auto|rg|grep|js`, default `auto`);
   - при полном отсутствии движков — actionable-ошибка вместо `Executable not found`.
   - WASM-ripgrep **не** добавляется; при желании — отдельным решением.
2. **bash.** Обобщённый редирект: команда начинается с имени зарегистрированного тула
   (`process_log`, `process_wait`, `process_kill`, `lsp_check`, ...) → «это инструмент MMA,
   вызови как tool». Generic-подсказка: **любой** `--cwd <path>` в любой команде → параметр
   `workdir` с примером (не перечисляем только JS-пакетники). Существующие подсказки про
   `&&`/`|`/`>` дополнить одним конкретным переписанным примером.
3. **Процессы.** `ProcessRegistry` (нормализованные `command+workdir`):
   - фоновый `bash` при совпадении с уже запущенным — возвращает существующий `proc_*` (без
     дубля), если не передан `force: true`;
   - reap процессов, запущенных агентом, — **только на stop/закрытии сессии**, не на `onTurnEnd`.

### Фаза 4. Слабо-модельный UX

1. **Структурированные ошибки.** `ToolResult.errorMeta?: { code, retryable, hint }` — отдельное
   model-facing поле; в **чат** по-прежнему идёт только компактное `compactToolError`-сообщение
   (STYLE.md не нарушается, output-тесты не ломаются).
2. **`load_skill` fuzzy.** На мисс — top-3 ближайших имён (`css-expert` → `css-styling-expert`).
   **Только подсказка, без автозагрузки** (иначе можно загрузить не тот скилл).
3. **Пустой ввод.** `POST /api/message` (web) и REPL: пустая строка после trim → no-op +
   локализованная подсказка, без LLM-вызова и компакции.

## 6. Интеграция (три измерения)

**Реальный пользователь.** Меньше ложных компакций и потери контекста; честный прогресс плана
(авто-шаги объявляются); работающий `grep` на Windows; понятные ошибки вместо «Executable not
found»; нет «Нет активного плана» посреди работы.

**ИИ-модель.** Калиброванные пороги → реже теряется рабочее состояние; actionable-ошибки и
top-k скиллов снижают retry-петли; авто-advance становится видимым и обратимым; необязательные
`checks` убирают тупик 9B; детерминированный план-чеклист каждый ход.

**Смежные модули.** `session.jsonl` — только аддитивные поля (`estimatedTokensRaw`,
`calibrationState`, `reducedBy`, `strategy`); `context`-событие и `web-usage.json` — аддитивно;
реестр `/config` — новые ключи (+ en/ru подписи, `registry-extra.ts`); plugin API/`LLMProvider`
не меняются; тесты-сторожа обновляются в тех же коммитах.

## 7. Тестирование

**Юнит:**

- `context-calibration`: baseline+delta; floor-ratio не калибрует вниз при «обрезке»; shadow →
  trusted; stale при отсутствии usage; регресс «оценка не скачет на +44K при добавлении 2
  сообщений».
- `safety-clamp`: неправдоподобный скачок не триггерит компакцию.
- `compaction`: порог по `history`; cooldown; прогресс и эскалация A→B→C; no-op не инкрементит
  счётчик; reactive один раз за ход; `policy=legacy` воспроизводит 2.18.2.
- `plan`: auto-advance объявляется и не архивирует до `onTurnEnd`; `autoAdvance=false` сохраняет
  nudge; `no_active` содержит сведения о последнем плане; `checks` необязателен (default
  `manual:`); mismatch с числами.
- `grep`: работает при отсутствии `rg` и `grep` (JS-фолбэк); уважает gitignore/maxFiles;
  actionable-ошибка при полном отсутствии движков.
- `bash`: редирект tool-as-command; generic `--cwd`→`workdir`.
- `processes`: дедуп фонового запуска; reap на stop, но не на turn end.
- `errorMeta`: не протекает в чат (`compactToolError` показывает только сообщение).
- Пустой пользовательский ввод — no-op.

**Интеграция (фикстурная, без сети/LLM):** записанный набор событий сессии →
проверка `compactionCount`, `estimatedTokensRaw` vs `promptTokens`, отсутствия тупиков плана.
**Generality-тест:** не-кодовая задача (письмо/погода/URL) и не-JS экосистема не деградируют.

**Quality gate:** `bun test`, `tsc --noEmit`, `tsc -p tsconfig.frontend.json` (если трогаем web),
`bun run lint`; при релизе — `bun run quality`.

## 8. Критерии приёмки

1. В фикстурном реплее сессии **0** no-op overflow-компакций; число компакций соизмеримо числу
   ходов (а не 58 на 9).
2. Калиброванная оценка в пределах **±15%** от `promptTokens` **при** свежем `usage` и
   отсутствии признаков обрезки; вне этих условий — консервативный фолбэк на raw без потери
   способности компактить.
3. Отсутствуют циклы: «Нет активного плана» (≥2 подряд), `checks_mismatch` (≥3 подряд).
4. `grep` возвращает результаты при отсутствии `rg`/`grep` в PATH; новых hard-зависимостей нет.
5. Нет дублирующих фоновых dev-серверов; процессы завершённой сессии не текут, но живут между
   ходами.
6. `errorMeta` не появляется в чате.
7. Не-кодовая задача и не-JS стек проходят пайплайн без ложных файловых проверок/компакций.
8. `bun test` + `tsc --noEmit` зелёные; трёхмерная интеграция проверена явно.

## 9. Риски и митигации

| Риск | Митигация |
|---|---|
| Калибровка «вниз» маскирует реальное переполнение (провайдер усекает) | floor-ratio + shadow + safety-clamp + stale-фолбэк |
| Неверная первопричина скачка +44K | сначала диагностика + фикстурный регресс; патч только после локализации; safety-clamp как сеть |
| Смена ядра компакции ломает поведение | `policy=legacy` + фикстурные тесты + поэтапное включение |
| `checks`-релаксация ослабляет верификацию | `manual:` только как фолбэк отсутствия; `file-exists:`/`command:` не ослабляем; конфиг-тумблер |
| `autoAdvance=false` возвращает застревание | nudge-путь сохраняется |
| LS-подсказка `--cwd` ложна для не-пакетников | generic-условие по флагу, а не по имени инструмента |
| Reap убивает нужный dev-сервер | reap только на stop |
| `errorMeta` протекает в чат | отдельное поле + тест |
| Новый JS-поиск медленный/зависает | лимиты времени/размера, gitignore/maxFiles, ранний выход |
| Fuzzy-скилл автозагружает не тот | только подсказка |

## 10. Порядок внедрения и версионирование

Фазы 0→4. Внутри фазы 0 сначала **0.1 диагностика** (без изменения поведения), затем 0.2–0.5.
Каждая фаза — отдельный коммит с зелёными тестами. Рискованные изменения (1, 2) — за флагами,
включаются после фикстурных прогонов.

Релиз — **MINOR** (новые конфиг-ключи, аддитивные поля JSON): обновить `CHANGELOG.md`,
`AGENTS.md` (разделы компакция/план/тулы), зарегистрировать ключи в `registry-extra.ts` + i18n
en/ru. Новых зависимостей нет.

## 11. Открытые решения (принятые дефолты)

1. **Auto-advance:** мутация + явное объявление, без авто-архива посреди хода, флаг
   `execution.autoAdvance=true`, nudge сохраняется при `false`.
2. **grep:** zero-dep JS-фолбэк + системный rg/grep; WASM-ripgrep не добавляем.
3. **`checks`:** необязательный, default `manual:`; авто-деривация `file-exists:` отклонена как
   overfit/риск.
4. **Калибровка:** per-session, in-memory, baseline+delta, floor-ratio, shadow-warmup.
5. **Компакция:** `policy: legacy|v2` (default v2).

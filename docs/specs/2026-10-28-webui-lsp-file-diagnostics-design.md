# Панель LSP: диагностика файла, а не только «серверы живы»

_Дата: 2026-10-28. Ветка: `docs/turn-gate-lsp-specs`. Источник: стресс-тест,
волна 20 (B-41)._

## Что показала проблема (наблюдение)

Панель называется «LSP — диагностика уровня редактора», кнопка — «Проверить».
Фактически `POST /api/lsp/doctor` возвращает `servers[]`:

```json
{"language":"typescript","ok":true,"durationMs":1829,"effectiveCommand":"npx",
 "installCommand":"npm i -g typescript-language-server typescript@5.2.2"}
```

То есть проверяется **запускаемость language-серверов**, а не код. Ошибка типов
в реальном файле (`export const broken: number = "not a number"`) не появилась
ни в панели, ни где-либо ещё в интерфейсе — при этом у агента есть рабочий
`lsp_check`, который такие ошибки находит (см. `src/modules/lsp/module.ts`,
`client.checkFile`).

Пользователь не может ответить на вопрос «а что скажет LSP про этот файл?»,
оставаясь в браузере.

## Решение

Панель получает **вторую секцию** — диагностику выбранного файла. Первая секция
(серверы, `doctor`) остаётся как есть: это разные вопросы («серверы живы» и «что
в файле»), и смешивать их в одном списке — та же ошибка, что была с «Картой».

### API

```
POST /api/lsp/check   {"path":"src/components/Products.tsx"}
→ 200 {"ok":true,"path":"…","diagnostics":[
        {"line":41,"column":7,"severity":"error","message":"Property 'has' does not exist…"}
      ],"truncated":false,"ms":812}
→ 200 {"ok":true,"path":"…","diagnostics":[],"ms":640}
→ 400 {"ok":false,"error":"path-outside-workspace"}
→ 503 {"ok":false,"error":"lsp-unavailable"}
→ 200 {"ok":false,"error":"lsp-timeout","ms":5000}
```

- путь — **workspace-относительный**, приводится тем же нормализатором, что и
  `/api/file`; выход за workspace → 400 (jail остаётся в одном месте).
- проверяется один файл (не проект): это ответ на «что в этом файле».
- таймаут 5 c (существующий `WRITE_CHECK_TIMEOUT_MS` не переиспользуется —
  панель ждёт интерактивно), диагностик не больше 200 (`truncated: true`),
  сообщение обрезается до 300 символов.
- ошибки LSP — `ok:false` с причиной, не 500: панель показывает «LSP недоступен»
  и не ломает остальной интерфейс.

### Панель

```
LSP — диагностика уровня редактора            (i)
LSP              ✓ включён
тулчейн          typescript 5.2.2
typescript       ✓ ок · 1.9s · npx
…
—— файл ——
src/components/Products.tsx                   [проверить]
 41:7  error   Property 'has' does not exist on type 'string[]'
 57:3  warn    'applied' is declared but its value is never read
```

- путь берётся из вкладки «Файлы» (`sb.files.selectedPath`), если файл открыт;
  иначе — поле ввода с подсказкой «путь относительно проекта».
- «файл» — заголовок секции; клик по строке диагностики открывает файл в
  просмотрщике на этой строке (у просмотрщика уже есть номера строк — B-39).
- пустой ответ → «ошибок нет · 0.6s».
- таймаут → «LSP не ответил за 5 c», кнопка снова активна.
- результат не кэшируется: файл мог измениться.

## Что это НЕ решает

Панель не становится «Problems» всего проекта: проверяется один файл по
запросу. Массовая проверка (все открытые/изменённые файлы) — отдельная задача (`DEBT(lsp-project-diagnostics)`),
там нужен инкрементальный кэш и очередь, иначе npx-сервер будет запускаться на
каждый файл.

Живая проверка на `mma_test` показала второй предел: проверка файла упирается в
8-секундный бюджет и честно возвращает `lsp-timeout` (панель так и пишет), даже
когда `doctor` показывает сервер живым. Похоже, веб-хост не удерживает тёплый
пул между запросами и каждый вызов платит за инициализацию TS-сервера. Это
зафиксировано как `DEBT(lsp-web-check-warm-pool)`: критерий — проверка файла
этого проекта отдаёт диагностики в пределах бюджета после прогрева.

## Инварианты

- **INV-L1.** Путь нормализуется и проверяется в одном месте (`/api/file`
  и `/api/lsp/check` используют один jail), панель не строит пути сама.
- **INV-L2.** Диагностика — это данные (`line/column/severity/message`), а не
  готовый текст: рендер и переход к строке делает клиент.
- **INV-L3.** Недоступность LSP — видимое состояние панели (`ok:false`), а не
  молчание и не 500.
- **INV-L4.** Кап 200 диагностик и 300 символов на сообщение: панель не должна
  умирать на сгенерированном файле.

## Тесты

| файл | что держит |
|---|---|
| `tests/modules/lsp/web-check-api.test.ts` | путь внутри/снаружи workspace, `ok:false` при недоступном LSP, кап 200 |
| `tests/webui-lsp-file-diagnostics.test.ts` (DOM) | рендер списка, «ошибок нет», таймаут, клик открывает файл на строке |
| `tests/arch/module-boundaries.test.ts` | webui не импортирует `modules/lsp/*` напрямую (только через `core/api`) |

## План

1. **W1.** `POST /api/lsp/check` (нормализация пути, таймаут, кап) + тесты API.
2. **W2.** Секция «файл» в панели: путь из Files, кнопка, список, пустое
   состояние, таймаут + DOM-тест.
3. **W3.** Переход по клику к строке в просмотрщике (`openFile` + прокрутка к
   номеру) — переиспользует номера строк из B-39.

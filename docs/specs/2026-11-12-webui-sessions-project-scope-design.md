# Web UI: сессии скоупатся проектом

- **Дата:** 2026-11-12
- **Статус:** реализовано
- **Долг:** оплачен `webui-sessions-project-groups` (`docs/agents/debt.md`)
- **Связано:** INV-9/10 (единая точка enforcement), INV-15 (ошибка ≠ пусто)

## Проблема

`~/.mma/sessions` общий на все проекты. `mma web` в одном каталоге показывал в
дропдауне сессии **всех** проектов: мета несёт `projectDir`, но в `/api/sessions`
он не проецировался. Последствие хуже, чем неудобный список:

1. ход в такой сессии строится контекстом **её** проекта
   (`SessionManager` берёт `meta.projectDir`, `manager-state.ts`), а UI рисует
   workspace текущего — агент молча правил файлы другого репозитория;
2. восстановленные вкладки (`mma-open-tabs` в localStorage привязаны к origin, а
   `mma web` у разных проектов на одном порту) воскрешали чужие сессии;
3. пользователь не видел проекта в строке списка и не мог отличить свою сессию
   от чужой.

Живой случай: `ses_mwdlv8tg_…` (`C:\projects\script-city-mvp`) открылась в
webui `micor-models-agent`; «продолжи» выполнило старую задачу в чужом каталоге.

## Решение: скоупинг, а не группировка

Группировка по проекту оставляла бы главный вред — возможность продолжить чужую
сессию. Выбран жёсткий скоупинг по workspace процесса.

### Контракт API

| Точка                         | Было                                 | Стало                                  |
| ----------------------------- | ------------------------------------ | -------------------------------------- |
| `GET /api/sessions`           | все сессии                           | только `projectDir == workspace`       |
| SSE `sessions`                | все сессии                           | то же (общий источник — `sessionList`) |
| `SessionMetaLite`             | id/name/updatedAt/model/messageCount | + `projectDir`                         |
| `POST /api/sessions/activate` | любая существующая                   | чужая → `403 foreign_project`          |
| `POST /api/message`           | любая существующая                   | чужая → `403 foreign_project`          |

`projectDir` в item — не для группировки, а чтобы клиент/диагностика знали, чья
история, без второго запроса.

### Точка проверки

`src/modules/webui/session/project-scope.ts`:

- `normalizeProjectPath(dir)` — `resolve` + без хвостовых слэшей, регистр не
  значим на win32;
- `inWorkspace(meta, workspace)` — сравнение `meta.projectDir` с workspace.

Вызывается ровно в двух местах записи: активация (`sessions-api.ts`) и старт
хода (`turns.ts#parsePost`). Read-пути (`/api/state?session=`, `/api/history`)
не ограничиваются: они не выполняют код в чужом проекте, а прятать чтение
значило бы ломать `?session=`-ссылку без выгоды.

### Fail-open

Сессия без `projectDir` (история до появления поля) считается своей, как и
отсутствие `workspace` у состояния. Иначе апгрейд спрятал бы всю старую
историю. Это осознанно: граница держится для записей, которые её несут.

## UI

Отдельной секции «другие проекты» нет — чужие сессии не приходят. Строка списка
по-прежнему показывает id/имя/время; `projectDir` доступен в payload для
диагностики. Закрепления (`localStorage`) фильтруются тем же списком: id чужой
сессии в `sessions` не попадает, поэтому и вкладка не восстанавливается.

## Не входит

- Перенос сессий между проектами (`mma session move`).
- История `mma serve` (сервис уже живёт в одном workspace на процесс).
- Группировка по проекту в одном дропдауне — не нужна при скоупинге.

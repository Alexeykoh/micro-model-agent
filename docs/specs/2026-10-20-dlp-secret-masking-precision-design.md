# DLP: точность маскирования секретов и наблюдаемость редакции

**Дата:** 2026-10-20 · **Ветка:** `fix/dlp-secret-masking-precision` · **Статус:** принято
**Основание:** спека `2026-10-19-corporate-data-policy-design.md` (DLP-слой), живой прогон
с LM Studio (`localhost:1234`, `qwen/qwen3.5-9b`, `qwen3.8-9b-distill`).

---

## 1. Проблема (наблюдения)

DLP-слой редактирует исходящий к провайдеру вызов. Для **доверенной** (loopback) цели
пути/PII не редактируются, но класс `secret` редактируется всегда (§6 спеки 2026-10-19):
`enabledClasses()` добавляет `secret` вне ветки `!target.trusted`.

Живой прогон (локальная модель, дефолтная политика) показал, что секрет-детектор ловит
**обычный код**:

| Вход (результат `read_file`) | Что увидела модель |
|---|---|
| `if (password === confirmPassword)` | `if ([SECRET] confirmPassword)` |
| `secret: process.env.CLIENT_SECRET,` | `[SECRET]` (вся строка) |
| `OPENAI_API_KEY=sk-proj-…` | `OPENAI_[SECRET]` (маска съела идентификатор) |

Последствия (замерено на `qwen/qwen3.5-9b` и `qwen3.8-9b-distill`):

- **qwen3.5-9b:** отказался работать («похоже на системную защиту/зашифрованное
  содержимое»), попросил загрузить файл заново. 78k токенов / 70 с.
- **qwen3.8-9b-distill:** **выдумал другую функцию** (`login(confirmPassword = "")`) —
  тихая конфабуляция вместо ответа.
- Тот же файл с выключенным DLP: корректный разбор, 37k токенов / 23 с.

Причины:

1. **Ложные срабатывания.** Детектор переиспользует `TARGETED_SECRET_PATTERNS` из
   `data-sanitizer.ts` — это набор для *логов*, без границ слов и без проверки формы
   значения. `password === confirmPassword` попадает под `(password|passwd|pwd|pass)`,
   а значение `==`/`confirmPassword` считается секретом.
2. **Маска съедает идентификатор.** Finding покрывает весь матч, маска `[SECRET]`
   заменяет `API_KEY=…` целиком → модель и критик видят «скрытое содержимое», а не
   «отредактированное значение». Критик отклонил такой ответ как неполный.
3. **Маска необратима.** `<PATH:hex>` — токен (восстанавливается), `[SECRET]` — нет.
   Для локальной цели значение не покидает машину, но уничтожается.
4. **Редакция не фиксируется.** `recordEgressTurn` требует `diag.sessionId` и пишет
   только в per-turn журнал webui; в CLI (и в `session.jsonl`) не остаётся следа:
   пользователь видит `[SECRET]` без объяснения.

Плюс смежный дефект: ре-гидратация токена — точное совпадение. Модель, написавшая
`<PATH:23ED10A52917>` (регистр) или с опечаткой, получит в аргументах тула литерал
`<PATH:…>` → «файл не найден» и цикл. Для 9B вероятность выше, чем для большой модели.

## 2. Инварианты

- **INV-S1 (точность).** Детектор `secret` срабатывает только на секретоподобном
  значении: известный префикс (`sk-`, `ghp_`, `AKIA`, `ctx7sk-`, `github_pat_`, `xox*`,
  JWT) **или** значение с цифрой и буквой достаточной длины. Сравнения и идентификаторы
  (`password ===`, `secret: process.env.X`) секретом не являются.
- **INV-S2 (структура сохраняется).** Маскируется **значение**, идентификатор остаётся:
  `OPENAI_API_KEY=[SECRET]`. Строка остаётся разбираемой и человеком, и моделью.
- **INV-S3 (обратимость там, где возможно).** Токены `<LABEL:hex>` восстанавливаются
  нечувствительно к регистру hex.
- **INV-S4 (наблюдаемость).** Необратимая редакция (класс `secret`) оставляет запись
  `egress_redacted` в `session.jsonl` — только метаданные (счётчики по классам, вид
  цели), без оригиналов и без token id (INV-DLP-1).
- **INV-S5 (управляемость).** Маскирование секретов на egress выключается ключом
  `security.dataPolicy.egress.secrets` (дефолт `true` — текущая политика сохранена).
- **INV-S6 (политика доверенных).** Класс `secret` по-прежнему редактируется и для
  доверенной цели (loopback) — это осознанное решение спеки 2026-10-19 (§6), а не
  побочный эффект. Локальный оператор, которому нужны реальные значения, выключает
  `security.dataPolicy.egress.secrets` (INV-S5) или весь слой (`…dataPolicy.enabled`).

## 3. Решение

### 3.1 D1 — детектор секретов становится точным и отдаёт диапазон значения

`src/modules/security/data-policy/detectors/secrets.ts` больше не переиспользует
`TARGETED_SECRET_PATTERNS` (набор для логов: без границ слов, без формы значения).
Собственный список паттернов, каждый со **диапазоном значения** и флагом «в кавычках»:

- `key = value` / `key: value` — идентификатор на границе слова, разделитель `:`/`=`,
  значение — `[A-Za-z0-9_\-.+/~]` (без кавычек, скобок и запятых → `jwt.sign(payload,`
  и `process.env.X` не попадают);
- известные префиксы и JWT — весь матч;
- `Bearer <token>` — только токен (префикс `Bearer` остаётся).

Форма значения (`looksSecret`): известный префикс **или** (цифра + буква) и
(длина ≥ 16 **или** длина ≥ 8 с разделителем **или** в кавычках и длина ≥ 6).
Отсюда: `password === confirmPassword` — нет цифры → не секрет; `'hunter2'` — цифра,
в кавычках, 7 символов → секрет; `process.env.CLIENT_SECRET` — нет цифры → не секрет.

Finding отдаёт диапазон **значения** → проекция заменяет только значение.

### 3.2 D2 — маска сохраняет идентификатор

Следствие D1: `projectText` подставляет маску в диапазон значения → `API_KEY=[SECRET]`.
Код в ответе модели остаётся синтаксически разбираемым, критик видит «значение
отредактировано», а не «содержимое скрыто».

### 3.3 D3 — токен восстанавливается независимо от регистра hex

`TokenMap` хранит дополнительный индекс в нижнем регистре; `rehydrate()` узнаёт
`<PATH:23ED10A52917>` так же, как `<PATH:23ed10a52917>`. Опечатка в hex по-прежнему не
восстанавливается (это осознанно: «почти правильный» путь опаснее отсутствия пути).

### 3.4 D4 — редакция видна в журнале сессии

`egressDiagnosticSink` пишет `egress_redacted` (новый тип записи `SessionLogEntry`),
когда редакция необратима (класс `secret`). Псевдонимизированные пути/PII не пишутся:
они обратимы и шумны (одна запись на каждый вызов LLM), их счётчик живёт в бейдже webui
(INV-DLP-2). Содержимое записи — метаданные: число отредактированных секретов, вид
цели (`provider`, доверенный/внешний, хост). Без оригиналов и token id.

### 3.5 D5 — ключ `security.dataPolicy.egress.secrets`

Деф `bool` в `registry-data-policy.ts`, эффект `REBUILD` (политика читается при сборке
провайдера). Дефолт `true` — поведение по умолчанию не меняется. Оператор с
полностью локальным стеком выключает его и получает реальные значения у модели.

## 6. Риски и границы

- **Слабеет ли защита?** Да, точечно: короткие/«словарные» значения вроде
  `password = hunter2` (без кавычек) больше не редактируются. Компенсация: в кавычках
  — редактируются; в логах действует прежний `data-sanitizer` (он не менялся);
  оператор может выключить `egress.secrets` осознанно.
- **Секреты для доверенной цели** по-прежнему редактируются (INV-S6) — поведение
  спеки 2026-10-19 не меняется.
- **Компакция/суммаризация** идут через тот же провайдер → редакция применяется и там.
- Проверка форм значения — эвристика, а не криптография: DLP снижает риск, но не
  является границей доверия. Граница доверия — loopback/allowlist (§6 спеки).

## 8. Что НЕ в этой задаче

- Изменение правила «секреты не доверенной цели» (INV-S6) — отдельная задача со спекой:
  оно осознанно зафиксировано в специ 2026-10-19 (§6) и требует решения владельца
  политики, а не молчаливого патча.
- Уведомление пользователя в чате о факте редакции (в CLI): текущий сигнал — бейдж в
  webui и новая запись `egress_redacted` в `session.jsonl`.
  DEBT(dlp-cli-redaction-notice) — критерий выхода и триггер в
  [`docs/agents/debt.md`](../agents/debt.md).
- Перенос секретов в заголовок авторизации (спека 2026-10-19 §6, «секреты идут только в
  заголовок авторизации»): это отдельный контракт LLM-провайдера.

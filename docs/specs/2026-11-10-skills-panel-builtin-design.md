# Скиллы: вид источника в панели веба — дизайн (2026-11-10)

## Задача

Пользователь путает, что приложено к сборке, а что он положил сам: панель
«Навыки» показывала один плоский список. Встроенные скиллы должны быть
помечены бейджем и отделены от внешних.

## Контракт (аддитивно)

- `SkillMeta` (загрузчик скиллов) получает поле `kind: "builtin" | "global" |
  "project"` — присваивается источником (`loadFromAllSources`), а не выводится
  из пути; при дедупе по имени победитель сохраняет свой `kind`.
- `WebSkillInfo` (контракт веб-настроек) — опциональный `kind`.
- `GET /api/skills` — каждый элемент аддитивно несёт `kind` (отсутствует у
  стабов без него; старые клиенты не ломаются).

## UI

Панель рендерит две секции: «встроенные» (скиллы из поставки) и «внешние»
(`global`/`project`), только непустые; элемент встроенного скилла получает
чип-бейдж. Строки — `web.settings.skills_section_builtin` /
`skills_section_external` / `skills_builtin` (en/ru паритет).

## Enforcement/экономия

Enforcement не трогается. Тело скилла — по-прежнему бюджет `skills.budget`;
`kind` токенов не стоит (в промпт-каталог не попадает).

## Проверки (правило 5)

- `tests/modules/skills/kind.test.ts` — kind по каталогам, победитель дедупа,
  дефолт `loadFromDir`.
- `tests/webui-settings.test.ts` — `/api/skills` отдаёт `kind`.
- `tests/webui-skills-panel-dom.test.ts` — секции и бейдж в DOM, пустая секция
  не рендерится.
- `tests/modules/skills/builtin.test.ts` — builtin-каталог грузится с `kind=builtin`.

## Вне рамок

Группировка `/skill list` в REPL не меняется (там путь источника и так виден
при желании); фильтр/поиск по kinds в панели — следующий шаг, если понадобится.

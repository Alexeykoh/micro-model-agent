# Отзыв черновика только при реальном переответе (2026-10-30)

## Дефект (живая сессия `ses_mvv8mr4z_gyztjbjlcqiowkpr`)

Ход «так ты скажешь мне погоду или как?» закончился **пустой лентой**: ответ был
отстримлен, затем удалён отзывом, а ход завершился принятием этого же текста.

Факты из `session.jsonl` (725 с, 5 итераций):

| Итерация | Событие                                                                     |
| -------- | --------------------------------------------------------------------------- |
| 2        | ответ не дал прогноз → критик `critical` → retract + repair                 |
| 4        | прогноз дан → критик `concern` («нет web grounding») → retract + advice     |
| 5        | тот же прогноз (93% повтора) → `claim_retry` + retract → … и ход закончился |

Причина — порядок в `src/core/agent/hallucination-gate.ts`:

```ts
if (result.status === "retry") {
  retractDraft(deps, ...);      // черновик удаляется сразу
  return this.applyRetry(...);  // решение «переответить?» принимается ПОСЛЕ
}
```

`applyRetry` может понизить повтор до предупреждения и принять ответ
(`suppressRepetitionRetry`, выставленный критиком/аудитом на предыдущей
итерации). В этом случае текст уже удалён из ленты, но сервер считает его
финальным: новых `text`-чанков нет, `turn_end` приходит без ответа.

## Контракт

1. **Retract — только если следом будет видимая замена.** Вызов
   `retractDraft` живёт внутри веток, которые действительно ведут к
   переответу или к явной ошибке:
   - `retry` (обычный и claim-повтор) — retract + повторный ответ;
   - `block` (бюджет повторов исчерпан) — retract + `error` в ленте;
   - `accept`/`exit` (в т.ч. понижение повтора после аудита) — **без retract**.
2. `claim_retry` пишется в журнал ровно тогда же, когда и `retract`
   (это одна функция) — принятый ответ не оставляет ложного следа «был отзыв».
3. Лента и журнал не расходятся: если `assistant`-запись принята как финальная,
   её текст остаётся видимым.

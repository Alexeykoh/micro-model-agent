# Поиск по содержимому во вкладке «Файлы»

_Дата: 2026-10-29. Ветка: `fix/stress-register`. Закрывает `C-01` из
[docs/plans/2026-10-27-mma-web-bug-register.md](../plans/2026-10-27-mma-web-bug-register.md)
(волна 10)._

**Статус:** реализовано.

## Проблема

Вкладка «Файлы» умела только дерево и просмотр одного файла. Любой поиск по
содержимому требовал хода агента: `grep`-подобной функции в веб-интерфейсе не было.

## Решение

В тулбар левой колонки добавляется поле поиска. Ввод дебаунсится (300 мс), Enter
запускает поиск сразу, Escape очищает. Пока запрос не пуст, вместо дерева
показывается список совпадений; очистка возвращает дерево.

Строка результата — `путь:строка` и сама совпавшая строка (обрезанная, один
пробел-нормализованный вид). Клик открывает файл в существующем просмотрщике на
этой строке (`openFile(path, line)` → `markAndScrollToLine`), никакого второго
канала навигации.

Серверный поиск — ограниченный обход workspace, а не индексатор: поиск по
содержимому не должен требовать тёплого индекса и не должен читать весь проект.

## API

```
GET /api/search?q=<подстрока>
→ 200 {"results":[{"path":"src/a.ts","line":12,"text":"const x = 1"}],
        "truncated":false,"ms":18,"scanned":42}
→ 400 {"error":"missing_query"}
→ 400 {"error":"query_too_long","limit":200}
→ 503 {"error":"workspace_unavailable"}
```

- `path` — всегда workspace-относительный posix-путь.
- `line` — 1-based номер строки.
- `text` — совпавшая строка после `trim()`, не длиннее 200 символов.
- `truncated` — упёрлись в кап результатов/файлов/байт/времени.
- `scanned` — сколько файлов прочитано (для диагностики, не для UI).

## Границы

| Кап | Значение |
|---|---|
| длина запроса | 200 символов (иначе 400) |
| результатов | 50 |
| просканированных файлов | 5000 |
| прочитанных байт | 32 МБ суммарно, 512 КБ на файл |
| время | 2500 мс |

## Безопасность

- Путь не принимается параметром: обход начинается только от `s.workspace`.
  `?path=` игнорируется, поэтому «выйти» из workspace через запрос нельзя.
- Симлинки/джанкшены не разворачиваются (как в индексаторе) — ссылка внутрь
  не ведёт наружу.
- Те же игноры, что у дерева/индексатора: `IGNORE_DIRS`, `IGNORE_FILE_NAMES`,
  `.gitignore`/`.mmaignore` (`loadIgnoreMatcher`), `apiHiddenGlobs` (D2/INV-D6).
- Защищённые пути (`matchProtectedPath`: `.git/`, `.env*`, ключи) не читаются.
- Бинарные файлы (NUL-байт) пропускаются (`decodeText` из `/api/file`).
- Результат — только строки из файлов, ни один файл не отдаётся целиком.

## Инварианты

- **INV-S1.** Поиск не принимает путь: множество читаемых файлов определяется
  только workspace и общими игнорами.
- **INV-S2.** Обход ограничен по результатам, файлам, байтам и времени;
  превышение видно как `truncated`.
- **INV-S3.** Клик по результату использует существующий `openFile(path, line)`;
  новых путей навигации нет.
- **INV-S4.** Пустой запрос, «нет совпадений» и ошибка — видимые локализованные
  состояния, а не пустая панель.

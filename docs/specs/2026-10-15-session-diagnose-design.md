# `mma session diagnose` — вскрытие сессии по сигнатурам

**Дата:** 2026-10-15 · **Волна:** W5 плана `docs/plans/2026-10-15-harness-bug-detection-plan.md`
· **Статус:** утверждена

## 1. Зачем

Четыре дефекта плана жили в `master` при зелёных `bun test`: разбор боевой сессии
делался руками, по одному `grep` на каждый домысел. Разбор `session.jsonl` —
это чтение 824 записей глазами, и он не воспроизводится: тот же вопрос через
неделю даёт другой ответ.

Команда превращает разбор в **список сигнатур**: патологий, каждая из которых
уже была причиной реального фикса. Не «сводка активности» — а ответ на вопрос
«что в этой сессии сломано».

## 2. Контракт

```
mma session diagnose <sessionId> [--json]
```

- `--json` — обязательный флаг вывода: без него команда не запускается. Причина:
  вывод предназначен и человеку, и разбору в CI; если формат плавает, его
  перестанут читать машинно.
- Человеческий вывод идёт через `OutputChannel` (`◇`-стиль, `t()`), JSON —
  единственный машинный контракт.

### JSON

```jsonc
{
  "sessionId": "ses_…",
  "entries": 824,
  "signatures": [
    {
      "kind": "compaction_stall",
      "count": 20,
      "first": "…ISO",
      "last": "…ISO",
      "detail": "…"
    }
  ],
  "summary": { "compactionCount": 20, "criticErrors": 3, "blockedCommands": 4 }
}
```

Проверяется **структура** (`signatures[].kind/count`), не stdout: тест на текст
ломается от каждого перевода формулировки.

## 3. Каталог сигнатур

Каталог живёт в `docs/agents/observability.md` (INV-15), **не** в `debt.md`:
это сигнатуры, а не долги.

| kind | Что означает | Источник в логе |
|---|---|---|
| `prompt_block_dropped` | блок промпта не влез в бюджет (`included:false`, `reason: budget`) | `context` → `blocks[]` |
| `compaction_stall` | серия компакций подряд без прогресса леджера | `compaction` ×N подряд + `context_degraded` |
| `critic_degraded` | критика нет или он деградировал | `critic_error`, `critic_verdict` |
| `tool_failure_repeat` | один и тот же тул падает ≥ N раз | `tool_result` c `success:false`, группировка по `tool` |
| `security_block_repeat` | один и тот же паттерн блокировки ≥ N раз | `tool_result` c `[SECURITY BLOCKED]` в тексте, группировка по паттерну |
| `claim_retry` | ходы модели уходили в ретрай (короткий/пустой ответ) | `claim_retry` |

Пороги (`N`) — именованные константы в модуле, а не магия в коде: их правка
не должна выглядеть как «случайно поменялось поведение».

## 4. Границы

- Команда **читает**, ничего не чинит: она не меняет конфиг, не удаляет сессию и
  не пишет в лог. Иначе инструмент разбора становится источником изменений.
- Читается только `session.jsonl` (+ `meta.json` для заголовка). `history.jsonl`
  не читается: он большой и его сигнатуры дублируют `session.jsonl`.
- Расшифровка шифрованных сессий — через существующий `SessionStore`, а не
  своим кодом.

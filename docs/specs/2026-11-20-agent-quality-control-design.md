# MMA — Управление качеством агента: доказательства, принуждение, отказоустойчивость

**Дата:** 2026-11-20 · **Версия:** 0.26.1 · **Ветка:** `feat/agent-quality-control`
**Статус:** target (нормативный контракт для этой ветки)
**Источник:** разбор сессий `ses_mwor4q49` / `ses_mwon4u7o`, журнал
[разработки](../development/2026-11-20-agent-quality-control-0.26.1.md).

## 1. Проблема

Три независимые политики позволяют агенту выпустить непроверенный результат:

1. Класс доказательства (`evidence`) объявляет модель; пропущенное поле трактуется как
   `"static"`, поэтому поведенческая проверка для UI-шага не требуется.
2. Один и тот же шаг плана можно закрыть четырьмя путями, и только один из них сверяет
   хэш файла (`file-modified`). Остальные доверяют mtime, существованию файла или
   идемпотентности.
3. При деградации критика гейт возвращает `"pass"`; вердикт уходит в лог/ленту, но не
   удерживает ответ.

Дополнительно: текстовые директивы не меняют поведение слабой модели, а сетевой обрыв
стрияма превращается в `Ошибка LLM` без повтора и без диагностики фазы.

## 3. Публичные контракты

- `CriticAction` расширяется: `"pass" | "retry" | "degraded"`. Значение `degraded` — новый
  сигнал, не меняющий fail-open для шагов без `check`.
- Новый тул `patch_file` объявляет `security: { caps, pathArgs }`, теги `["file","code"]`,
  регистрируется через `registerAllTools`.
- `needsBehaviorEvidence()` меняет семантику отсутствия поля; старые планы без `evidence`
  приравниваются к behavioral — это осознанный разрыв back-compat, компенсируемый
  явным `"static"` в планах, которые создаются тестами и миграциями.

## 4. Что явно не делается

- Forced named `tool_choice` — на llama.cpp object-form до сих пор откатывается к `auto`.
- Генерация новой текстовой директивы как средства борьбы с циклом.
- Очистка контекста после провала (увеличивает повтор проваленного действия).
- Непарный `block` без `stop`.
- Изменение `CHANGELOG.md` и версии пакета — без явной команды на релиз.

# Web UI: favicon проекта, вкладки Subagents/MCP и компактный сайдбар

Дата: 2026-10-27 · Ветка: `feat/webui-sidebar-favicon` · Статус: реализовано

## Задача

Семь независимых правок поверхности `mma web`:

1. Иконка вкладки браузера: favicon проекта, иначе маскот MMART.
2. Вкладка сайдбара со всеми прогонами субагентов активной сессии.
3. Кнопка «Промпт» — над списком Trace, а не отдельной колонкой справа.
4. Activity rail — одна компактная строка вместо двух.
5. Вкладка MCP в сайдбаре.
6. Тумблеры плагинов переключаются сразу и не открывают попап.
7. Пара «контекст: used / limit» — на одной базе (полное окно).

## Контракт

### 1. `GET /api/favicon`

- Источник: `state.workspace`; путь клиента не участвует.
- Имена: `favicon.ico|png|svg|webp|gif`; каталоги: корень, `public`, `static`,
  `assets`, `img`, `images`, `src`, `app`, `src/app`, `docs`, `gh-pages`.
- Кап 512 KiB, MIME — по расширению из allowlist.
- Нет файла → встроенный SVG-маскот (`MASCOT_FAVICON`), `image/svg+xml`.
- Тело отдаётся `Buffer`, а не строкой: egress-обёртка редактирует строки и
  может изменить длину после расчёта `Content-Length`.
- В `index.html` — `<link rel="icon" href="/api/favicon">`.

### 2. Вкладки `subagents` и `mcp`

`TABS` — единственный источник порядка и горячих клавиш (`Alt+1..8`):

```
session · files · lsp · trace · subagents · plugins · mcp · map
```

- **Subagents** читает `GET /api/sessions/:id/subagents` (прогоны живут в
  памяти, не в `session.jsonl`), показывает задачу, агента, модель,
  длительность/итерации и статус. Снимки мержатся в общие буферы
  (`mergeSnapshot`), клик открывает тот же read-only транскрипт (`openRun`),
  что и строка `subagent` в ленте. На узком экране дровер закрывается.
- **MCP** читает новый `GET /api/mcp` (тот же `mcpList`, что у настроек) и
  переключает сервер через существующий `POST /api/mcp/:id`. Смена персистится,
  но соединения поднимаются на старте — вкладка прямо говорит про рестарт.
- SSE `subagent` помечает список устаревшим и перечитывает его с троттлингом
  250 мс; SSE `plugins` — повод перечитать MCP.

### Быстрый доступ к настройкам

Одна контекстная «шестерёнка» в шапке сайдбара (`#sbSettings`), а не шесть
дублирующих кнопок: её назначение зависит от активной вкладки.

| Вкладка | Панель настроек |
|---|---|
| Session | Sessions |
| Files / Map | Context |
| LSP / Plugins / MCP | Plugins · MCP |
| Trace | UI & Theme |
| Subagents | Agent |

- Клик идёт через `hooks.openSettingsAt(panel)` — шов из `settings/modal.ts`;
  сайдбар не тянет настройки в свой граф импортов.
- Подпись (`title`/`aria-label`) — «открыть настройки · <панель>», имя панели
  берётся из `web.settings.<panel>` (локализовано).
- У MCP-вкладки есть ещё явная CTA «Настроить MCP-серверы…» внизу списка
  (и в пустом состоянии): добавление/правка живут только в настройках, поэтому
  одной иконки мало.

### 3. Trace: «Промпт» над списком

`#pane-trace` остаётся `row-reverse` (detail слева), но head и list теперь один
ребёнок `.trace-main` — колонка. Раньше head был третьим flex-ребёнком и
превращался в узкую колонку справа от списка.

### 4. Rail

`l-line` — `flex-wrap: nowrap`: фаза/время/план и счётчики идут одной строкой.
Пустой `last` больше не оставляет висящий `·` и `—` (`hidden` на узле и
разделителе). На телефоне rail снова складывается вертикально.

### 5. Тумблеры плагинов

`makeToggle` переключает себя только при truthy-возврате. Плагины возвращают
`true` и сразу меняют `row.enabled` (оптимистично), ответ сервера перерисовывает
список; отказ откатывает к предыдущему значению. Клик по тумблеру делает
`stopPropagation`, поэтому не всплывает в обработчик строки, открывающий попап.
Тот же контракт — у тумблера внутри попапа.

### 6. Контекст

`contextUsed` включает system + tools. Знаменатель — полное окно
(`contextBreakdown.window`, затем `contextWindow`, и только затем legacy
`contextLimit`). `contextLimit` — history-бюджет (~75% окна) и в паре с полным
`used` давал ложное «19.6K / 98.3K» при окне 131K. Сегментный бар уже жил на
`breakdown.window`, теперь строка сходится с ним.

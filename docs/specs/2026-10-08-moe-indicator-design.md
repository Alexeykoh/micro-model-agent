# MoE-индикатор — строка в чате + бейдж режима в футере

- **Дата:** 2026-10-08
- **Ветка:** `feat/moe-indicator`
- **Проблема:** оркестрация MoE, вид пользователю, дизайн/обвязка

## 1. Проблема

Живой прогон (`ses_muynp9o7_eks83c`, `opencode-go`) показал: при включённом MoE
пользователь не видит, что работает MoE. В чате — только карточки `subagent`
и ошибки, ни плана, ни прогресса, ни признака, что это оркестрация.

Причины:

- **Строки статуса MoE гейтятся `ui.verbose`** (`src/core/agent-moe.ts:106-109`):
  на дефолтном quiet `status()` молчит, поэтому даже существующие 12 ключей
  `moe.*` пользователю не показываются.
- **План MoE не попадает в plan-поверхность.** Он не синхронизируется с
  `ExecutionModule`, поэтому веб-рельс (`assets/js/rail.ts:64`) показывает
  «no plan»/indeterminate, сайдбар-Plans пуст, терминальный `Renderer.planBlock`
  (`src/ui/renderer.ts:533`) не используется. В вебе события MoE видны только
  во вкладке Trace.
- **Стилевой долг:** в `moe.*` остались emoji (`🤖 ⚙️ 🔄 🔧 ✅ ⛔`), STYLE.md
  требует один глиф действия `◇` и семантические `✓ ⚠ ✦`.

## 2. Решение / не-решение

**Решение:**

- **A. Чат-строка:** одна строка на ход — старт (`◇ MoE · план из N шагов`) и
  финал (`✓ MoE · 2/3` / `⚠ MoE · частичный результат`). Терминал и веб.
- **C. Бейдж режима:** чип `MoE` в футере под композером, горит только пока
  идёт реальный MoE-ход. Только веб — в терминале строка чата уже всё говорит,
  дубль был бы шумом.

**Не-решение:**

- Прогресс сабтасков в чате не дублируется: параллельную работу видно по
  карточкам `subagent`, а строка даёт режим и итог.
- План MoE не синхронизируется с `ExecutionModule` (это отдельная задача
  «честный done/total в рельсе»).
- Бейдж не показывает счётчик сабтасков: это потребовало бы прокидывать
  прогресс в `HostStateSnapshot` и делать `pushState` на каждый сабтаск.
- Терминальный бейдж между ходами.

## 3. Что пользователь увидит

Терминал и веб-лента (quiet):

```
◇ MoE · план из 3 шагов
  …карточки subagent…
✓ MoE · 2/3 готово
```

Веб-футер (рядом с `dir` и версией), только во время MoE-хода:

```
dir E:\projects\micro-models-agent                    MoE   mma 2.29.1
```

При `moe.enabled: false`, фолбэке на single-agent и вне хода чипа нет.

## 4. Контракты

| Событие | Что видит пользователь |
| --- | --- |
| MoE пошёл (план валиден) | строка `◇ MoE · план из N шагов`; чип `MoE` в футере |
| Сабтаск | ничего сверх карточки `subagent` |
| Ход завершён | `✓ MoE · D/T` или `⚠ MoE · частичный результат`; чип гаснет |
| Фолбэк на single-agent | строки нет, чип не загорается |
| Abort (Esc) | чип гаснет (гарантированный сброс) |

Инварианты:

- `moeActive` — **факт «MoE ведёт этот ход»**, а не `moe.enabled`: чип не
  должен гореть на фолбэке (`moe.no_orchestrator`, `moe.plan_failed`).
- Сброс флага не зависит от ветки выхода: `try/finally` вокруг исполнения.
- Per-session: у веба параллельные вкладки, флаг хранится по `sessionId`.

## 5. Изменения

**Ядро**

- `src/core/agent-moe.ts`: опция `onMoEState?: (active: boolean) => void`;
  `true` — после успешного плана, `false` — в `finally`. `status()` больше не
  гейтит `moe.started`/`moe.finished` (уходят через `onMeta`), `replan`,
  `plan_autofixed`, `scope_*` остаются на `ui.verbose`. Планирование больше не
  печатает отдельную строку — её покрывает спиннер thinking.
- `src/core/agent.ts`: `AgentDeps.onMoEState` прокидывается в opts `runWithMoE`.
- `src/i18n/{en,ru}.json`: `moe.started`, `moe.finished`; emoji из `moe.*` убраны.

**Веб**

- `src/core/host.ts`: `HostStateSnapshot.moeActive?: boolean`.
- `src/modules/webui/host-state.ts`: проброс поля из входов.
- `src/modules/webui/state.ts`: `moeSessions: Record<string, boolean>` +
  хелпер `activeMoe(state, sessionId)` (по образцу `activeUsage`).
- `src/modules/webui/module.ts`: `getState` передаёт `moeActive` по сессии.
- `src/core/bootstrap/session-runner.ts`: раннер каждой сессии ставит
  `onMoEState` → `state.moeSessions[sessionId]` + `pushState(state, sessionId)`.
  Главный агент (терминал) ничего не передаёт.
- `src/modules/webui/assets/js/footer.ts`: чип `MoE` перед версией.
- `src/modules/webui/assets/styles.css`: `.ws-moe` (акцентный цвет, dim).

**Тесты**

- `tests/core/agent-moe-indicator.test.ts`: ungate старт/финиша, verbose-only
  для replan, сброс флага на фолбэке и на abort.
- `tests/webui-workspace-footer.test.ts`: чип включается/гаснет по флагу.
- `tests/webui-usage.test.ts`: `moeActive` в снапшоте по сессии.

## 6. Риски

- **Терминальный шум.** На quiet одна строка на ход — приемлемо; полный набор
  `moe.*` остаётся за `/verbose`.
- **Чип вводит в заблуждение при долгом ходе.** Чип живёт весь ход, а не только
  фазу планирования, — это и нужно («работает MoE»).
- **Событийная vs pull-модель.** Флаг едет в снапшоте (`pushState`), а не
  отдельным SSE-типом: по правилу 2.24.0 клиент не плодит источники синхронизации.
- **Забытый сброс** оставил бы чип гореть навсегда — отсюда `finally` и
  тест на abort.

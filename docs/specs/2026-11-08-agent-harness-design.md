> LSP — спека до кода (правило 2 AGENTS).

## 1. Что правильно и чего эта правка НЕ делает

Сессия показала шесть системных дефектов харнеса, а не модели:

1. `maxTokens=8192` на reasoning+output одновременно — модель вынуждена выбирать
   между думать и писать код. Три раза `Truncated before output — retry with reasoning off`.
2. `write_file` одним вызовом > 11k символов (`products.ts`) — гарантированный обрыв.
3. `file-exists` врёт: шаг «done» при шаблонном `page.tsx` и при упавшем typecheck
   (`Helmet` из lucide-react) — auto-completed по факту наличия файла.
4. LSP pre-write блокирует 4 корректные записи с алиасом `@/` на холодном старте
   (индекс не построен) — модель переписывает тот же файл по 2–3 раза.
5. Bash-thrashing: 17 вызовов `shadcn --help / init --help / add` по кругу, 16 `process_wait`.
6. `process_wait`/скаффолд не приоритезируется, `question` выдаётся мелкими раундами.

**Это не меняет:** модель и промпты, набор тулов, интерфейс плана для пользователя,
формат `session.jsonl`.

## 2. Инварианты

- **INV-H1 (бюджеты).** reasoning и completion бюджетируются раздельно. Для вызовов
  с крупными `write_file/append_file` — повышенный completion-бюджет (12–16k),
  для навигационных — малый. Один ретрай обрыва дешевле, чем систематические обрывы.
- **INV-H2 (размер записи).** `write_file` > 6–8k символов запрещён одним вызовом;
  модель пишет через `append_file` кусками. Enforcement в `ToolExecutor` до handler'а.
- **INV-H3 (честный done).** `plan_step done` / auto-complete требует не только
  `file-exists`, но и отсутствия `tool_result.success=false` на шаге (и, где заявлено,
  успешного typecheck), иначе статус `blocked`, а не `done`.
- **INV-H4 (LSP-tolerance).** Файлы холодного старта / с `@/`-алиасом не блокируют
  запись; запись пропускается с пометкой `unverified`, верификация — после индекса.
- **INV-H5 (bash-loop).** Одна команда + смена версии + ошибка 3 раза подряд =
  стоп-детект с директивой перечитать help/docs один раз и не повторяться.
- **INV-H6 (нет регрессии).** Каждый инвариант — с гейтом из правила 5 AGENTS
  (падает без правки).

## 3. Реализация (по волнам, каждая — отдельная ветка/коммит)

1. **Бюджеты (INV-H1):** `llm-call` параметры: `reasoningBudget` и `completionBudget`
   раздельно; выбор completion-бюджета по размеру следующих `write/append` args в батче.
2. **Размер записи (INV-H2):** лимит 6–8k на `write_file`, подсказка про `append_file`,
   тест на отказ > лимита и успех кусками.
3. **Честный done (INV-H3):** `plan` auto-complete проверяет `tool_result` шага;
   при `Project typecheck failed` / `success=false` — `blocked` + директива чинить.
4. **LSP-tolerance (INV-H4):** детект холодного состояния LSP / `@/`-алиаса,
   пропуск pre-write с `unverified`, повторный typecheck после индекса.
5. **Bash-loop (INV-H5):** счётчик повторов команды+ошибки, директива stops, тест.
6. **Очереди (INV-H6):** приоритет `process_wait`/`npm install` над интерактивом,
   батчинг `question`.

## 4. Приёмка

- Корректная сессия welkomagasin-стиля не падает на обрывах: 0 `Truncated` при
  8–16k генераторах файлов.
- План не показывает `done` при шаблонном `page.tsx` или упавшем typecheck.
- 4 записи с `@/` на холодном старте не блокируются.
- 3+ повторов одной bash-команды приводят к стоп-директиве.
- Гейты: `bun test` + `bun run quality` зелёные; для каждой правки — тест,
  который падает без правки.

# Project Map Indexer — анализ лучших практик и план улучшений

Дата: 2026-10-04 · Ветка: `feat/indexer-search-quality` · Релиз: 2.18.0

Разбор того, как лучшие инструменты 2026 решают задачу ориентации агента в
кодовой базе, что из этого применимо к MMA (universal-харнесс для маленьких
моделей, 32K–64K контекста, Bun/TS, минимум зависимостей), и что реализовано.

## 1. Контекст: замеры базовой версии

Проект dev-чекаута: ~971 индексируемый файл, 8.5 МБ, 2109 символов.

| Операция | Время |
|---|---|
| Холодный `walk()` (чтение + regex) | ~310 мс |
| `scanSignature()` (stat + sort + sha1) | ~150 мс |
| `find()` (линейный substring) | ~0.3 мс |
| `MAX_FILES` | 1000 (запас 29 файлов) |

Вывод: **поиск уже мгновенный**, узкое место — построение/валидация индекса и
качество выдачи, а не скорость.

## 2. Что говорят практики

- **Скорость поиска — не главный рычаг.** Бенчмарк entire.io (`fff` vs raw
  `ripgrep` vs `pgr`): ускорение поиска 14.7→1.7 мс дало лишь ~4% end-to-end
  (tool execution ≈ 0.4% wall-clock), а **ранжирование** (definition-first,
  path-aware) подняло Hit@1 26%→34%, MRR 0.32→0.41 на первом запросе.
- **Гибрид трёх модальностей**, а не «grep vs embeddings»: лексическая
  (grep/trigram), структурная (tree-sitter AST), графовая (кто вызывает кого).
- **Aider repo-map**: дерево-ситтерные символы + PageRank по графу ссылок +
  бинарный поиск под токен-бюджет (`--map-tokens`, default 1k). Карта дёшева
  настолько, что регенерируется без накопления устаревания.
- **Источник правды — диск.** Даже при индексе агент верифицирует результат по
  живым файлам; индекс лишь «скипает первые 10 минут разведки».
- **Staleness tax.** Embedding-индексы требуют Merkle-синхронизации (Cursor);
  Sourcegraph Cody отказался от эмбеддингов в пользу BM25 по code-graph;
  Anthropic рекомендует начинать с agentic search и добавлять semantic только
  при симптоме «агент блуждает».
- **Инкрементальный индекс по mtime** (repo-map, code-symbol-index): первый
  индекс 17 с → последующие 0.3 с на 284-файловом TS-проекте.

Источники: aider.chat/docs/repomap, agentpatterns.ai (Repository Map Pattern),
sourcegraph/zoekt design, particula.tech (semantic vs grep 2026),
entire.io/blog (improving agentic search), zzet.org (three search modalities).

## 3. Что реализовано (Фаза A, 2.18.0)

| # | Идея | Реализация | Эффект (замер) |
|---|---|---|---|
| 1 | Инкрементальный индекс по mtime | `IndexedFile.mtimeMs`; `walk(prev)` переиспользует неизменные, `cache.loadForReuse()` (схема v3) | 3000 файлов: пересбор после 1 правки 302→168 мс (1.8×) |
| 2 | Ранжирование `find` | `rank.ts`: exact>prefix>substring>path, код>тест>доки, короче путь | MRR 0.93→1.00, Hit@1 0.90→1.00 (`plugin` 7→1) |
| 3 | Символы с позициями + `symbol`/`outline` | `extractSymbolsDetailed` → `{name,line,kind}`; новые действия `project_map` | навигация без чтения тела; тул-набор не вырос |
| 5 | Конфиг `indexer.maxFiles` (1000→5000) | `registry-extra`, Settings → Context, маркер `[!] truncated` | убран «упор в 1000» |
| 6 | `.gitignore`/`.mmaignore` | `gitignore.ts`, fail-open (комментарии, `!`, `/`, `dir/`, `*`, `?`, `**`) | 971→934 файла |

Цена: `find` 0.4→1.6 мс (приемлемо, независимо от числа совпадений).

## 4. План дальше

### Фаза B — PageRank-карта под токен-бюджет (идея 4, +8)
1. **Граф ссылок** файл→файл: из импортов и использования имён (regex-эвристика,
   затем tree-sitter). Узлы — файлы, рёбра — зависимости.
2. **PageRank** с персонализацией по файлам/символам текущей задачи.
3. **Токен-бюджет**: бинарный поиск максимального набора ранжированных
   сигнатур, влезающего в системный бюджет, вместо фиксированных `MAP_FILE_LIMIT=80`.

### Идея 7 — LSP в карту
Использовать существующий `LspModule` для `definition`/`references` при наличии
сервера, с фолбэком на индекс. Детерминированный ответ «где символ» точнее
regex; для типизированных языков — крупный выигрыш.

### Идея 8 — tree-sitter (WASM)
Точные сигнатуры и call-граф (Aider/Cline/Roo). Ломает zero-dep: нужны
vendor-грамматики (хотя бы JS/TS/Python). Даёт основу точного PageRank из Фазы B.

### Отложено осознанно
- **Trigram persistent index** (Zoekt) — не нужен до 100k+ файлов.
- **Semantic search** (embeddings/MCP) — infra + staleness + IP-risk; только
  опциональным плагином, off по умолчанию.

### Живой прогон (qwen3.5-9b через LM Studio)

Изолированный `MMA_CONFIG_DIR` + песочница из 8 файлов, задача «найди определение
`computeDiscount`, ответь `путь:строка`»:

| Сборка | Ответ | Итераций | prompt-токенов | Тул-вызовы |
|---|---|---|---|---|
| master | `src/billing/discount.ts:3` (неверно) | 2 | 13 195 | `read_file` |
| ветка (свободный выбор) | `src/billing/discount.ts:6` (верно) | 3 | 20 053 | `project_map find` + `read_file` |
| ветка (`project_map symbol`) | `src/billing/discount.ts:6` (верно) | 2 | 13 192 | только `project_map symbol` |

Вывод: действие `symbol` даёт точную строку **без чтения тела файла** при том же
бюджете, что старый `read_file`-путь. Один прогон на сборку — не статистика, но
интеграция новых действий с реальной моделью подтверждена.

**Дата:** 2026-10-12 · **Релиз:** `0.3.3` (`65ba2f68`, тег `v0.3.3`)
**Источник:** документ [`docs/plans/2026-10-12-harness-runaway-followups.md`](../plans/2026-10-12-harness-runaway-followups.md)
(аудит живой сессии `ses_mv44qabg_s1przq`) и
[`docs/plans/2026-10-11-harness-runaway-session-fixes.md`](../plans/2026-10-11-harness-runaway-session-fixes.md)
(5 закрытых харнесс-фиксов)

**Метод.** Семь параллельных deep-read проходов по модулям (agent loop / web+skills /
context+compaction / webui / security+tools / MoE+critic / session+config+providers /
UX+i18n+indexer+LSP / service+updater) + личная верификация ~20 ключевых находок в коде.
Из ~180 находок отобраны те, что подтверждены или имеют конкретный путь отказа.

`finalizeWithoutTools`; калибровка контекста и компакция v2; tool-ledger; `contextAuto`+
probe контекста; изоляция per-session раннеров; слоты плана; event-sourced state;
MMART; MoE-индикатор; Service API v1.

## Главный вывод

План закрывает **симптомы** конкретной сессии (упаковка релиза, лимит итераций, директива
веб-ресёрча). Реальные первопричины глубже и лежат в четырёх классах:

1. **Инструменты, которые тихо ломаются.** `web_search` без проверки HTTP-статуса
   сообщает «No results found» на 429/403; `browser` падает с `spawn node ENOENT` на
   bun-only сборке. Модель получает ложь и верит ей.
2. **Инварианты, которые не являются инвариантами.** Все счётчики прогресса в петле —
   streak-счётчики, сбрасываемые одним успешным тулом. Кумулятивной метрики прогресса
   в `LoopState` нет вообще.
3. **Компакция удаляет собственные директивы харнесса** — все `<system-summary>` вырезаются
   из удерживаемого хвоста, а one-shot флаги не сбрасываются. Директива, вытесненная из
   контекста, никогда не будет отправлена повторно.
4. **Сервисный слой без авторизации по тенанту** и **тулы, обходящие границы** (`bash`
   вне jail, `browser` вне SSRF-политики, сужение по тегам как декорация).

Пункт 5 отчёта («быстрая проверка фиксов») остаётся актуальным, но он не может быть
единственным P0: часть живых дефектов §2.3 плана имеет харнесс-причину, а не модельную.

## 2. Web / browser / skills — почему модель ходила по кругу

Плана прав: цель «собрать данные/картинки из интернета» была структурно недостижима. Но
конкретные дефекты не закрыты и часть из них **делает ловушку глубже**.

| # | Дефект | Место |
|---|--------|-------|
| 2.1 | **`web_search` не проверяет HTTP-статус.** Нет `response.ok`. DDG отдаёт 403/429 страницу-челлендж → регулярка ничего не находит → `success: true, results: []` → модель получает `No results found for "<query>"` и делает вывод «этого факта не существует» вместо ретрая. Прямой генератор галлюцинаций. `web-fetch.ts:61` и `download-file.ts:109` проверку имеют. | `web-search.ts:66-81`, `:150` |
| 2.2 | **`web_browse` — строго худший двойник `web_fetch`.** Без проверки статуса (404-тело отдаётся как контент), без `extractMainContent`/`looksLikeShell`, `.replace(/\s+/g," ")` уничтожает переводы строк ⇒ `fullLines` всегда 1, ветка `MAX_PREVIEW_LINES` мёртвый код. ## Приоритет

**P0 — ломает достоверность ответов (модель/пользователь получают ложь):**
`web_search` без `response.ok` (2.1) · hard-stop с `success:true` (1.1) · MoE отбрасывает
результаты сабтасков (5.5) и печатает «✓» на проваленном ходе (5.6) · критик — no-op на
больших ходах (5.8) · evidence галлюцинаций от прошлого хода (1.12) · MoE обходит все гейты (5.1).

**P0 — обходы границ:**
`browser` без SSRF (2.3) · `bash` вне jail/scope (4.1) · сужение по тегам не enforced (4.6) ·
ADS + регистр в protected paths (4.2, 4.3) · `mma serve` без авторизации по тенанту
(9.1–9.3) · updater без проверки целостности и неатомарно (9.9).

**P1 — харнесс не ловит петлю (главная тема плана, но лечится не теми фиксами):**
Компакция удаляет собственные директивы (1.5) · streak сбрасывается одним успешным тулом
(1.3, 1.4) · без плана StuckDetector мёртв (1.2) · нет кумулятивной метрики прогресса (1.13) ·
меню `question` невидимо (8.10).

**P1 — тихая потеря данных:**
Деструктивная «миграция» конфига (7.1) · неатомарная нешифрованная запись (7.4) · prune
сессий у живых раннеров (4.14) · `session.jsonl` без ротации (7.14) · переписывание истории
до персиста (7.15) · LSP-серверы не убиваются (8.1).

**P2 — качество и соответствие STYLE.md:**
Подписи к параметрам `subagent`, которые игнорируются (2.13) · терминальный markdown без
нормализаций веба (8.13) · resize / Ctrl+D (8.11, 8.12) · инкрементальный индекс,
откатанный `invalidate()` (8.7) · exit code 0 на всех подкомандах (7.2).

## Что НЕ стоит делать

- **Не поднимать `maxToolIterations` обратно и не откатывать `MAX_RESEARCH_BATCHES`.**
  Ни один из выявленных дефектов петли не лечится порогом — они все про «счётчики, которые
  не являются счётчиками прогресса». Пункт 6 плана (валидировать 200 на длинной задаче)
  стоит закрывать, но по результату — не откатом.
- **Не добавлять hard-stop веб-ресёрча.** Пункт 7 плана правильно отложен: с учётом 1.4
  (одно перемежающее чтение обнуляет streak) и 1.5 (директива стирается компакцией)
  hard-stop сначала станет ложноположительным, потом — бесполезным. Правильная
  последовательность: **сначала** (а) сделать счётчик не-сбрасываемым на посторонних
  тулах и (б) сделать директивы переживающими компакцию; **потом** — смотреть, нужна ли
  жёсткая граница.
- **Не начинать с prompt-усиления (п.6 рекомендаций плана).** Пока `web_search` сообщает
  «No results found» на 429, а `browser` падает с `spawn node ENOENT`, усиление промпта
  заставит модель **больше** верить этим инструментам.
- **Не брать guard «попросили план — не начинать реализацию» (п.9 плана).** Риск п.9
  совпадает с уже откатанным `MAX_READONLY_BATCHES`, а дрейф scope — модельная проблема:
  корректный харнесс всё равно дал ей «план» вместо «сделай сайт», и структурного механизма,
  который отличил бы «дай план по X» от «спланируй и сделай», в системе нет. Если и делать —
  то как необязательную подсказку в первом ответе, не как блокировку.

## Рекомендуемый порядок работ

1. **Наблюдаемость перед правками.** ~15 правок в этом отчёте невидимы: критик,
   MoE-верификатор и часть гейтов пишут «ок» при поломке. Без `critic.error` /
   `verify.error` / `tool_attempt` в `session.jsonl` и без разделения «сказал ок» /
   «сломался» в чате следующий живой прогон снова придётся разбирать вручную.
2. **Пакет A — достоверность** (P0-ложь): `web_search` ok-check + `web_browse`
   статус/нормализация, MoE surfacing результатов и честный итог, критик
   `maxTokens`/диагностика, `terminalize` на hard-stop.
3. **Пакет B — границы** (P0-обходы): SSRF в `browser`, jail/scope в `bash`, enforcement
   тегов в `executor`, ADS/регистр в protected paths, tenant-authz в `mma serve`,
   обязательность sha256 + атомарность в updater.
4. **Пакет C — петля** (то, ради чего написан план, но правильно): переживание директив
   компакцией, не-сбрасываемые счётчики, кумулятивная метрика прогресса. **После A и B** —
   потому что сейчас петлю частично вызывают сами баги инструментов.
5. **Пакет D — данные**: конфиг (атомарность, шифрование, не-деструктивная миграция),
   сессии (ротация, prune с учётом раннеров), LSP (pid, stderr).
6. **Пакет E — UX**: меню `question`, resize, Ctrl+D, терминальный markdown, exit codes,
   `subagent`-параметры, инкрементальный индекс.

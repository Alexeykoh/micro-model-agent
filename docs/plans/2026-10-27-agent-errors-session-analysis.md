### A1 (P0). Glob в `allowed_files` = «нет доступа», без диагностики

**Симптом.** Все четыре первых субагента получили
`allowed_files: ["E:/projects/micro-models-agent/**/*"]` и не смогли открыть ни одного файла:

```
16:33:07 list_dir(".")                 → Path is not within the allowed scope for this sub-agent
16:33:08 list_dir("src")               → то же
16:35:17 read_file("…/package.json")   → то же
16:37:37 write_file("pytest.ini")      → Path is not within the writable scope for this sub-agent
```

Из 12 вызовов `list_dir` прошёл 1, `read_file` — 0/1, `write_file` — 0/2.

**Причина.** `matchesScopeEntry` (`src/tools/path-utils.ts:36-39`) — это сравнение путей по
префиксу (`target === entry || isInsideDir(target, entry)`), а не glob. Запись `…\**\*` не
совпадает ни с каталогом, ни с файлом. Проверка на живом коде (`isPathInScope`, `security.paths.enabled`):

| `allowed_files`                      | `""` | `.` | `src` | `src/index.ts` | `package.json` |
| ------------------------------------ | ---- | --- | ----- | -------------- | -------------- |
| `["E:/…/**/*"]`                      | no   | no  | no    | no             | no             |
| `["**/*"]`                           | no   | no  | no    | no             | no             |
| `["."]`                              | ok   | ok  | ok    | ok             | ok             |
| `["E:/projects/micro-models-agent"]` | ok   | ok  | ok    | ok             | ok             |
| `["src"]`                            | no   | no  | ok    | ok             | no             |

Корректные формы (`"."`, абсолютный корень, каталог) работают. Ломается именно glob-форма —
и агент **принимает её молча**, без нормализации к каталогу и без отказа «запись не
поддерживается». В `tests/` нет ни одного теста с glob-записью в `allowed_files`
(`rg allowed_files tests/` — только файлы/каталоги), поэтому дефект невидим для гейтов.

**Почему это ошибка агента, а не модели.** Контракт `allowed_files` («Files/directories…»)
не выражает «весь проект» иначе как `"."`, но и не говорит, что glob не поддержан. Модель
передала самую естественную форму для «все файлы проекта»; harness обязан либо понять её,
либо отвергнуть до запуска прогона.

**Направление фикса (нужна спека — правило 2, меняется контракт скоупа).** Один из трёх:
(1) `allowed_files` нормализуется: glob-запись раскрывается в базовый каталог до первой
мета-группы; (2) валидация аргумента на входе `subagent` с внятным отказом; (3) явный
маркер «весь workspace». Плюс `matchesScopeEntry` → поддержка `**` хотя бы для хвоста.

**Воспроизведение:** `subagent(task: "прочитай src/index.ts", allowed_files: ["**/*"])` →
любой `read_file` получает отказ по скоупу.

**Гейты:** `tests/security/path-validator.test.ts` (+glob-запись: разрешено/отказ),
`tests/tools/enforcement-path.test.ts` (субагент со `**/*` читает `package.json`).

### A2 (P0). `glob` врёт о результате, когда скоуп скрыл всё

**Симптом.** 14 из 14 вызовов `glob` детей вернули `success: true` и «Нет совпадений»,
хотя родитель теми же паттернами получил 780+ файлов:

```
16:39:26 parent glob src/**/*.ts   → 780+ files
16:33:16 child glob (тот же скоуп) → Нет совпадений
```

**Причина.** `src/tools/glob-tool.ts:46-62` считает `hidden`, но при `visible.length === 0`
делает ранний `return t("file.no_matches")`; заметка `file.glob_hidden` печатается только
когда хоть что-то видно. Для модели «нет совпадений» и «всё скрыто скоупом» — один и тот же
факт, и следующий шаг она строит на неверном («в проекте нет `.ts`»).

**Фикс.** При `visible === 0 && hidden > 0` — отдельный текст: «найдено N, скрыто N (скоуп
субагента / denied / protected)». Отдельно: `success:false` при полностью скрытой выдаче, если
это не «действительно пусто».

**Гейт:** `tests/tools/glob-scope.test.ts` — «скрытое ≠ пусто» (сейчас проверяет только
отсутствие скрытых путей в выдаче).

### A3 (P1). Пустой `path` обходит enforcement путей

**Симптом.** В прогоне, где `list_dir(".")` и `list_dir("E:/projects/micro-models-agent")`
заблокированы, один `list_dir` (16:34:27) вернул листинг корня проекта.

**Причина.** `src/tools/executor.ts:175`: `if (typeof value !== "string" || value.trim() === "") continue;`
— пустая строка считается «аргумент не задан». При этом `list_dir` через
`safeResolvePath(baseDir, "")` резолвит пустую строку в **корень проекта** (проверено:
`E:\projects\micro-models-agent`). То есть необязательность аргумента трактуется как
«не проверять», а хендлер подставляет самый широкий путь.

Оговорка: аргументы тулов детей в журнал не пишутся (A4), поэтому соответствие «успешный
`list_dir` ⇔ пустой `path`» — реконструкция. Сама дыра в enforcement подтверждена кодом;
`list_dir(".")` при том же скоупе стабильно отказывает.

**Фикс.** Для `pathArgs` пустое значение — ошибка аргумента, а не «пропустить». Проверять
также эффективный путь, который вычислит хендлер (или запретить `""`/`.` в тулах, где путь
обязателен).

**Гейт:** `tests/tools/enforcement-path.test.ts` — `list_dir("")` в закрытом скоупе → отказ.

### A4 (P1). Журнал прогона не восстанавливает, что падало

**Симптом.** У всех 60 записей `type: "subagent", content: "tool"` поле `args` **отсутствует**
(не пустое — его нет в объекте):

```json
{
  "ts": "…",
  "type": "subagent",
  "source": "core",
  "subagent": "srun_…",
  "content": "tool",
  "tool": "list_dir",
  "success": false,
  "duration": 17,
  "summary": "Путь недоступен: . — Path is not within the allowed scope for this sub-agent"
}
```

**Причина.** Журнал (`feat/subagent-run-journal`, `tests/tools/subagent-session-log.test.ts`)
фиксирует имя тула, успех, длительность и хвост вывода, но не аргументы. Итог: журнал отвечает
«был `list_dir` и упал», но не «с каким путём» — ровно та непрозрачность, которую он должен
был убрать, на уровень ниже. Именно из-за этого A1 и A3 пришлось восстанавливать по коду.

**Фикс.** Писать `args` (с тем же редактированием секретов, что и `history.jsonl`), плюс
`end` — счётчики «тулов ок / упало / файлов прочитано» (см. A7).

**Гейт:** `tests/tools/subagent-session-log.test.ts` — у `tool`-записи есть `args`, секреты
отредактированы.

### A5 (P1). Счётчики антифлейлинга общие для родителя и субагентов

**Симптом.** Совет «Инструмент bash упал N раз» приходит родителю за вызовы, которых он не
делал, и повторяется каждую итерацию:

```
16:38:22 «bash упал 14 раз»
16:39:22 «bash упал 14 раз»
16:39:34 «bash упал 15 раз»
16:40:31 «bash упал 21 раз»
16:40:37 «bash упал 21 раз»
16:41:24 «bash упал 21 раз»
```

Арифметика сходится с логом детей: 22 падения `bash` в первой волне дали окно 14; падение
`bash` самого родителя (16:39:34) → 15; 6 падений второго прогона (`srun_8a373d38`) → 21.
Собственных `bash`-вызовов у родителя за весь ход два.

**Причина.** `ToolExecutor.fork()` даёт форку собственные `scope`/`cleanup`, но **общий**
`pluginManager` (`src/tools/executor.ts:74-80`), а плагин execution мутирует один и тот же
`stuckDetector`: `execution-plugin.ts:439` (`recordBashAttempt(false)`), `:465`
(`recordToolError`), `:472` (`recordToolSuccess`). Плюс `FAILING_FIRST_WORDS` в
`src/tools/bash.ts:516-519` — модульная Map на процесс: счётчик «failed N times in a row»
тоже накапливается между родителем и детьми и переживает сессию.

**Следствия.** (а) ложный совет родителю; (б) загрязнённый `escalationCount` — анти-гейминг
может сработать на здоровом родителе; (в) жёсткий стоп по `forbiddenWindowsCommand`
(`forbiddenBashFailures`, `execution-plugin.ts:450`) считает чужие падения; (г) один и тот же
варнинг переинжектится в контекст 7 раз без нового события.

**Фикс.** Состояние флейлинга — на прогон/агента, а не на процесс: детектор в форке (или
исходы детей с меткой `subagent: …` и отдельным окном), сброс `FAILING_FIRST_WORDS` на сессию,
варнинг — один раз на изменение счётчика.

**Гейт:** `tests/modules/execution/stuck-turn-scope.test.ts` — падения ребёнка не меняют
счётчики родителя; `tests/tools/bash-process-hint`-соседний тест — «failed N» не растёт между
сессиями.

### A6 (P1). Критик: число без провенанса → `critical` → три итерации впустую

**Симптом.**

```
critic_verdict (critical): «заявлен 1487 TS-файлов, а на самом деле >4000»
critic_check  (concern):   «glob confirms 11680+ files exist»
```

1487 — счёт индекса (`typescript:1487` в `project_map`, то есть `src` + `tests`); 4052 —
диск вместе с `node_modules`. Верное число у агента было с итерации 1.

**Причина.** (а) Критику не требуется провенанс числа: не видно, какой тул, в каком скоупе и
когда дал «4052»; (б) `critical` эскалируется без проверки, что утверждение вообще проверяемо;
(в) собственные проверки критика (`CRITIC_READONLY_TOOLS` в `src/modules/critic/tools.ts`)
не оставляют событий в `session.jsonl` — в логе нет ни одного `critic_tool`/`critic_check`
с результатом, только `critic_check` с числом тулов родителя и вердикт. Вердикт неаудируем.

**Фикс.** Требовать у критика `evidence` для числовых утверждений (тул + аргументы +
скоуп), логировать его проверки и результаты (INV-15: fail-open/деградация обязана оставить
след), не эскалировать `critical` на утверждении без провенанса — даунгрейд до `info`.

**Гейт:** `tests/modules/critic/*` — вердикт с числом без evidence не эскалируется;
`tests/arch/observability-coverage.test.ts` — проверки критика попадают в журнал.

### A7 (P1). Результат субагента не несёт здоровья прогона

**Симптом.** Пять прогонов вернулись как «Субагент завершил работу», `success: true` в
`end`-событии — при 38 падениях из 60 вызовов и 0 успешных чтений у двух прогонов. Родитель
принял их отчёты за результат.

**Причина.** `end`-событие несёт `status`, `success`, `iteration`, `promptTokens`,
`completionTokens`, `totalTokens` — и ни одного признака работы с файлами. `runSubagent`
возвращает текст ребёнка (с «Итераций: N»), но не счётчики «прочитано/записано/упало», по
которым родитель мог бы отличить «поработал» от «был полностью заблокирован».

Сама выдумка в отчётах (§3) — ошибка модели; отсутствие сигнала — ошибка агента.

**Фикс.** В результат субагента и в `end`: `toolsOk`, `toolsFailed`, `filesRead`,
`filesWritten`, `blocked`. При `filesRead === 0` и задаче-анализе — `success:false` с явной
причиной («прогон не прочитал ни одного файла»).

**Гейт:** `tests/tools/subagent-session-log.test.ts` (+поля), новый
`tests/tools/subagent-empty-run.test.ts` — прогон без чтений не рапортует успех.

### A8 (P2). Заголовок сессии: 512 токенов без восстановления

**Симптом.** `app.jsonl:3`: `session title not generated: Лимит генерации (512) исчерпан на
рассуждениях модели — ответ не начался`. В `meta.json` остался первый вопрос пользователя
(`nameSource: auto`).

**Причина.** Восстановление после обрыва до первого символа (`f17e8499`, ветка
`fix/subagent-reliability` §B) реализовано в петле агента; генерация заголовка идёт мимо неё
со своим фиксированным бюджетом 512 и на reasoning-модели тратит его целиком.

**Фикс.** Прогнать title-gen через ту же классификацию `truncated_no_content` (повтор с
выключенным reasoning и удвоенным бюджетом) или не считать заголовок падением — тихий
фолбэк без WARN.

**Гейт:** `tests/core/llm-truncation-recovery.test.ts` (+кейс заголовка) либо
`tests/cli/session-title*.test.ts`.

## 3. Что ошибкой агента не является

Проверено и оставлено в зоне модели/политики — в задачи не идёт:

- Два отчёта про несуществующий Python-проект (`pytest.ini`, `model.py`) и попытка создать
  `pytest.ini` — выдумка модели, когда доступа нет. Лечится сигналом A7 и гардом A2, а не
  отдельной правкой.
- Выдуманные каталоги `src/agents/`, `src/models/`, `config/`, `.mma/config.yaml` в ответе;
  проценты (`1487` = 86 % от 1725, не 59 %); «tests/core 63+ тестов».
- 22 из 24 падений `bash` у детей на `>`, `|`, `&&`, `powershell`, `bun -e` — command-validator
  сработал по политике; повтор того же вызова — поведение модели (смягчение — в A5/подсказках,
  но отдельным дефектом не считаю).
- `grep path: "/"`, `list_dir "/testbed"`, `/workspaces/micro-models-agent` — модель искала
  другое окружение, агент корректно отказывал.
- `project_map` с несколькими glob-паттернами в `query` («Нет совпадающих файлов для …») —
  misuse аргумента; сам ответ `success:true` на пустую выдачу — тот же класс, что A2, но
  отдельного пункта не заводим.
- Параллельность и изоляция форков: 4 ребёнка стартовали одновременно (16:32:58), `setScope`
  не потёк между сиблингами, `tests/tools/executor-fork.test.ts` соответствует поведению.
- `egress: total 0`, `contextQuality: 82`, `overcommitted: false`, кеш промпта 0.91–0.99.

## 5. Как повторить разбор

```powershell
$s = "$env:USERPROFILE\.mma\sessions\ses_mvqwky8y_cjcjhgbdigannujp"
$out = "$env:TEMP\mma-ses-report.txt"
Get-Content "$s\session.jsonl" -Encoding UTF8 |
  ForEach-Object { $_ | ConvertFrom-Json } |
  Where-Object { $_.type -in 'tool_call','tool_result','llm_usage','critic_verdict','subagent' } |
  Out-File -Encoding utf8 $out
Get-Content "$s\audit.jsonl" -Encoding UTF8 |
  ForEach-Object { $_ | ConvertFrom-Json } |
  Where-Object action -eq 'security_block' | Out-File -Encoding utf8 -Append $out
```

Консоль Windows в OEM-кодировке портит кириллицу — вывод писать в файл и читать оттуда
(или парсить через `bun -e`, как делалось при разборе).

## Дефекты

### S1. «Нет новых улик» после `critical` не распознаётся; принятие вердикта невидимо

После первого `critical` гейт впрыскивает repair и ждёт нового ответа. Модель
отвечает **новым текстом без единого тула** — то есть тем же evidence. Гейт
считает вход другим (отпечаток включает `answerText`, `packFingerprint`),
платит второй LLM-вызов (18.8 с) ради того же вердикта, а затем молча
принимает ответ: `logExhausted` писал только `logger.diagnostic`, в
`session.jsonl` не оставалось следа (INV-15: «приняли critical» ≠ «критик
сказал ок»).

**Фикс** (`fix/critic-no-evidence-loop`):

- `evidenceSignature` (`critic-budget.ts`) — подпись **только тул-событий**;
  `packFingerprint` = она + текст ответа (прежняя семантика сохранена).
- Если прошлый вердикт `critical`, подпись улик не изменилась и тулы в ходу
  были — повторный вызов критика не делается. Вместо него один раз (за ход)
  выдаётся директива `critic.act` («не описывай план — вызови тул или дай
  честный финальный ответ»), а при повторе ответ принимается с событием
  `critic_verdict { accepted: true, exhausted: true }`.
- Правило не действует для `concern` (переписанный ответ — законный ответ на
  совет) и для чат-доставки без тулов (там текст и есть улика, INV-C7).
- Гейты: `tests/core/critic-gate-stall.test.ts`; обновлён
  `tests/core/agent-critic.test.ts` (новая семантика: одна проверка вместо
  двух).

### S2. `finishReason` терялся в стриме

Ни один `assistant` в журнале не имеет поля `finish`. В `openai-compat`
`done`-чанк эмитился **только при наличии `usage`**, а LM Studio завершает
стрим `data: [DONE]` без usage. `finish_reason` копился в `StreamState`, но до
петли не доходил: обрезка (`length`) неотличима от полного ответа, метрики
хода теряют причину финала.

**Фикс** (`fix/stream-finish-reason`): финальный `done` несёт
`finishReason` из `StreamState` (с сужением типа). Гейт:
`tests/llm/stream-finish-reason.test.ts`.

### S3. Модель «рассказывает» вместо действия — вне контракта харнесса

Причина поведения — сама модель (9B-класс, локальный провайдер): она пишет
«checking…», не вызывая тул. Харнесс не может это «починить» за модель, но
обязан (а) не платить второй раз за тот же вердикт (S1), (б) один раз явно
потребовать действия (S1) и (в) не выдавать невыполненную работу за успех
(S1 + запись в журнал).

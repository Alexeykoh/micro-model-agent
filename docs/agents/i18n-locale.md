# Локаль: запрос, boot и кэш

Норматив: [monolith split §13](../specs/2026-11-10-monolith-split-design.md).
Гвард: `tests/arch/i18n-module-level.test.ts`, `tests/i18n-locale-scope.test.ts`.

## Приоритет

`t(key)` резолвит локаль так:

1. **ALS запроса** — `runWithLocale(locale, fn)` из `src/i18n/index.ts`. Демон
   оборачивает в него HTTP-обработчик по заголовку `X-Mma-Locale`; thin-REPL,
   SSE и one-shot шлют его на каждом запросе.
2. **Boot-локаль процесса** — `setLocale()` из конфига/CLI. Это fallback для
   фоновых задач, bootstrap, плагинов и стартовых сообщений.
3. **`en`** — если ключа нет ни в выбранной локали, ни в английской.

Скоупы изолированы: параллельные запросы с разными локалями не влияют друг на
друга (`Promise.all` в `tests/i18n-locale-scope.test.ts`).

## Почему boot-локаль не удалена

Полный отказ от процесс-глобального `setLocale` — отдельная волна: строки
команд/тулов/баннеров частично резолвятся на старте, а плагины и фоновые
таймеры живут вне ALS. Удаление fallback без аудита даёт ключи вместо текста.
Спека §13 фиксирует это как осознанный долг, а не как недоделку разделения.

## Правила

- **Не** вычисляйте `t()` на уровне модуля (`const LABEL = t("…")`): значение
  замирает до рестарта. Гвард падает на таком паттерне.
- Пользовательские строки — только через `t()`; ключи `en`/`ru` симметричны
  (`tests/i18n.test.ts`).
- Веб-статика локализуется своим словарём (`app-i18n.ts`), серверный вывод —
  локалью запроса.
- Модельные промпты не локализуются: язык модели не зависит от UI.

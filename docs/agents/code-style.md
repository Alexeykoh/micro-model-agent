# Code Style Guide

Стандарт стиля кода MMA. Основан на актуальных практиках TypeScript 2026:
typescript-eslint v8 (strict / stylistic), рекомендованные флаги TS 5.9, ts.dev/style.
Дополняет `Key Design Rules` в `docs/agents/architecture.md` (правила #1–18).

> **Правило:** при добавлении/рефакторинге кода следуй этому документу. Отклонения допустимы только
> с комментарием-обоснованием в коде.

## Форматирование

Единый формат обеспечивает Prettier (`.prettierrc.json`) — не обсуждается в ревью, применяется
автоматически (`bun run format`):

- 2 пробела, без табов;
- двойные кавычки;
- `trailingComma: "all"`;
- `printWidth: 100`;
- точка с запятой обязательна.

## Типизация

### Запрет `any`-кастов

`as any` и `as unknown as X` запрещены. Вместо них:

- `unknown` + type guard / narrowing (`typeof`, `in`, проверка на `null`, предикаты);
- `satisfies` для проверки формы без потери вывода типа;
- `Record<string, unknown>` с явными проверками значений;
- для динамических ключей — `keyof` / индексированные типы, а не `(obj as any)[key]`.

Единственное исключение — тестовые seam-касты (подмена зависимостей). Каждый такой каст
сопровождается комментарием-обоснованием (правило #15). Пример легитимного контракта — `ToolContext`
расширяется через `Object.defineProperty` в `bootstrap.ts`; потребители читают поля по типу, без кастов.

### Импорт типов

Типы из других модулей — только через `import type` / inline `type`-модификатор:
`import { foo, type Foo } from "./mod"`. Это направление к `verbatimModuleSyntax`, но сам флаг пока
не включён (см. «Постепенное ужесточение tsconfig»).

### Возвращаемые типы и вывод

- Экспортируемые функции и методы публичных классов — явный тип возврата.
- Локальные переменные и стрелочные колбэки — вывод типов, если он очевиден.

### Обработка ошибок в типах

- Переменная в `catch` — `unknown` (обеспечивается `strict`); извлекать сообщение через хелпер
  `errMsg()` (`src/utils`), не через `(e as Error).message`.
- Ошибки с дополнительными полями — расширять через явный интерфейс, а не ad-hoc property
  на `Error` без типа.

### Формы данных

- Discriminated unions вместо строковых «магий»: `{ type: "end"; ... } | { type: "start"; ... }`.
- `interface` — для расширяемых контрактов (`ToolContext`, `*Deps`, `*Config`).
- `type` — для union, alias, utility-типов.
- `enum` запрещён: `as const`-объект + union-тип (`type Level = (typeof LEVELS)[number]`).

## Постепенное ужесточение tsconfig

Добавлять по одному, отдельными PATCH, без массовых правок сразу. Порядок:

1. `noUncheckedIndexedAccess` — поверхностные ошибки доступа по индексу.
2. `noImplicitOverride` — защита наследования.
3. `noFallthroughCasesInSwitch`.
4. `exactOptionalPropertyTypes` — после рефакторинга конфиг-типов.
5. `verbatimModuleSyntax` — после приведения модульной конфигурации.

## Асинхронность

- Каждый `await` в цикле или фоновой операции проверяет `signal.aborted` (урок
  `moe-executor.ts`: retry-sleep без проверки задерживает Esc на секунды).
- Ожидания — прерываемые: используй abortable-обёртку, а не голый `sleep`.
- `Promise` без `await` — обязательный `.catch` с логированием (правило #14).
- Сетевые и дочерние процессы — всегда с таймаутом.

## Обработка ошибок

- Пустой `catch {}` допустим ТОЛЬКО с вызовом `logger.*` внутри И комментарием-обоснованием рядом
  (правило #14). То же для `.catch(() => {})` / `.catch(() => null)`.
- Парсинг JSON из пользовательских/модельных данных — всегда с fallback и логированием; молчаливый
  `{}` или `null` вместо результата запрещён.
- Инициализация необязательной подсистемы, упавшая молча, — дефект: писать `logger.warn`
  с причиной (иначе пользователь включает фичу и не понимает, почему она не работает).

## Порядок в файле

1. Докстрока модуля (назначение, инварианты).
2. Импорты: `import type`/типы первыми, затем значения.
3. Константы (CONSTANT_CASE).
4. Типы/интерфейсы (если не вынесены).
5. Функции/классы: публичные → приватные.

Комментарии — на русском (правило #15), объясняют «почему», а не «что»; идентификаторы, ключи API,
строки протокола и цитаты форматов не переводятся.

## Именование

| Сущность                            | Стиль          |
| ----------------------------------- | -------------- |
| функции, переменные, поля, методы   | `lowerCamelCase` |
| типы, интерфейсы, классы            | `UpperCamelCase` |
| модульные константы                 | `CONSTANT_CASE`  |
| файлы                               | `kebab-case.ts`  |

Без венгерской нотации, без `I`-префиксов у интерфейсов. Имя не дублирует информацию из типа.

## Пользовательские строки

Все строки, видимые пользователю (CLI/REPL/тулы/ошибки), — только через `t()` из `src/i18n/index.ts`
(правило #8). Ключи обязаны присутствовать и в `en.json`, и в `ru.json`. Строки для LLM-модели
(model-facing tool output) — на английском и не переводятся; они не считаются пользовательским выводом.

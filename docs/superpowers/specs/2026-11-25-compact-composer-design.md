# Компактный композер web UI — дизайн

Дата: 2026-11-25 · Статус: одобрен пользователем (вариант A визуального сравнения)

## Контекст

Строка селекторов под композером (`провайдер / модель / контекст / рассуждения`) вместе с подсказками и футером не влезает в узкое окно: пять «пилюль» с метками и длинное имя модели (`[heretic/38ts] ornith-1.5-9b-uncensored`) занимают всю ширину. Пользователь выбрал вариант A: одна тихая строка без меток, разделитель `/`, семантические Lucide-иконки.

## Решение

1. **Одна строка вместо пяти пилюль.** `.selectors` становится однойstroкой текста: бренд-иконка провайдера + значение, `/`, имя модели, `/`, иконка контекста + значение, `/`, иконка рассуждений + значение, затем иконки возможностей модели. Метки `провайдер/модель/контекст/рассуждения` из видимого ряда уходят.
2. **Разделитель `/`.** Заменяет `·` именно в этой строке. Причина: короче, не путается с путями (путь в футере пишется через `\`). STYLE.md предписывает `·` для чат-статусов и формально не покрывает GUI, но веб на него ссылается — гайд обновляется следом, чтобы договор не разошёлся с UI.
3. **Семантические иконки.** Бренд llama.cpp остаётся существующим `providerIcon` (не Lucide). Добавляется одна Lucide-иконка `ruler` для окна контекста. Уже есть в `js/icons.ts`: `brain` (рассуждения), `eye`/`wrench` (возможности), `image` (вложение), `arrow-up`/`square` (отправить/стоп), `chevron-down` ( affordance меню по наведению), `git-branch` (ветка в футере). Chat-глифы `◇`, `✦`, `·` остаются текстовыми по STYLE.md.
4. **Длинное имя модели.** Полное имя показывается, пока влезает. При нехватке места строка усекается слева с сохранением хвоста (`…38ts] ornith-1.5-9b-uncensored` в узком окне): главное — не потерять узнаваемую часть имени. Полное имя и авторский префикс `[heretic/38ts]` всегда доступны через `title`/`aria-label`.
5. **Подсказки сжаты.** Видимыми остаются `Enter — отправить`, `Ctrl+V — вложить` и группа `Ctrl+K · Ctrl+P`; `?` раскрывает скрытую подсказку `Shift+Enter`. Клавиши и действия не меняются (`js/shortcuts.ts`). (Пункт уточнён по одобренному макету вариант A: `Ctrl+K`/`Ctrl+P` не сворачиваются за `?`.)
6. **Футер не меняется.** `директория: …`, git-пилюли, версия и dev-метка остаются как есть.

## Поведение и ограничения

- Все четыре меню продолжают открываться из своих элементов; `.selectors[data-pending]` и `button.pending` (индикатор `◐`) сохраняются — скрытие стрелки не должно спрятать индикатор ожидания.
- Строка не переносится: при нехватке места сжимается имя модели, затем скрываются второстепенные иконки.
- Доступность: у каждого элемента остаются `title` и `aria-label` с полной меткой и полным значением; у усечённого имени — полное имя.
- i18n: новые пользовательские строки не нужны — все ключи (`web.selectors.*`, `web.input.*`) уже есть в `src/i18n/{ru,en}.json` с паритетом. Изменение только в том, какие ключи видимы.
- Никаких изменений в `session.jsonl`, публичном API модулей, REST/SSE и конфиге — значит, отдельная архитектурная спека по правилам репозитория не требуется; этот документ — дизайн-решение UI.

## Проверка

- `bun run quality` (typecheck + frontend + arch-гейты + файлы ≤300 строк) и `bun test` — зелёные.
- `tests/i18n.test.ts`, `tests/webui-i18n.test.ts` — паритет не сломан.
- Живой прогон `bun run web:dev` с изолированным `MMA_CONFIG_DIR`: проверить широкое и узкое окно, открытие всех четырёх меню, pending-состояние и усечение длинного имени.
- Скриншот/описание результата — в ответ пользователю, без изменения `CHANGELOG.md` (только по явной команде).

## Отклонения от одобренного варианта (финальная проверка)

- `#capsChip` вложен в `.sel[data-sel="model"]` (после кнопки и меню), а не показан после рассуждений. Причина: `tests/webui-caps-chip.test.ts` требует чип между моделью и контекстом в DOM-порядке; скрытый чип как непосредственный сиблинг разделителя `/` заставлял `syncSelectorSeparators()` прятать этот разделитель, пока возможности неизвестны. Вложенность держит чип рядом с моделью и оставляет все три разделителя видимыми; DOM-порядок закреплён тестом.
- Видимость подсказок: `Enter`, `Ctrl+V` и группа `Ctrl+K · Ctrl+P` остаются видимыми, `?` раскрывает скрытую `Shift+Enter` — как в одобренном макете вариант A. П. 5 выше уточнён: `Ctrl+K`/`Ctrl+P` не спрятаны за `?`.

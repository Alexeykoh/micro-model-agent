Документация MMA

Micro Models Agent — универсальный harness для небольших языковых моделей (9B, 32K–64K контекста), который держит их на задаче: бюджет контекста, структурная компакция, проверяемое планирование и настоящие гарантии исполнения. Не только код: разработка, веб-исследование, API, умный дом, ассистент.

Это руководство покрывает полный цикл: установка → настройка → повседневная работа → интеграции → безопасность → разработка → эксплуатация.

Обзор

MMA — это CLI-агент с единым циклом исполнения INIT → THINK → OBSERVE → VERIFY → OUTPUT → ERROR. Один и тот же агент доступен через три поверхности:

Терминал

mma — REPL и однократный запуск, markdown→ANSI, без TUI.

Браузер

mma web — SSE + REST, вкладки, файлы, Trace, MMART.

HTTP-сервис

mma serve — Agent Service API v1, задачи, SSE, webhooks.

Что важно знать сразу

  • Провайдер — любой OpenAI-совместимый сервер: LM Studio, Ollama, vLLM, llama.cpp, cloud-провайдеры. Работает офлайн, если модель локальная.
  • Контекст — окно задаётся автоматически по провайдеру или вручную; при заполнении включается компакция, а [Tool ledger] не даёт модели перечитывать уже прочитанное.
  • Гарантии — шаг плана закрывается только по факту (файл существует, команда прошла), а не по словам модели.
  • Beta — версии только 0.x.y; 1.0.0 не выпускается, пока проект в бете.

Установка

Релиз самодостаточный: внутри Bun runtime, собранный агент, production-зависимости и веб-ассеты. Node.js/npm/Bun ставить не нужно.

Windows (PowerShell 5.1+)

irm https://raw.githubusercontent.com/Alexeykoh/micro-model-agent/master/scripts/install.ps1 | iex

macOS / Linux

curl -fsSL https://raw.githubusercontent.com/Alexeykoh/micro-model-agent/master/scripts/install.sh | bash

Откройте новый терминал и запустите mma setup, затем mma.

Что делает установщик

  1. Определяет ОС/архитектуру: win-x64, mac-arm64, mac-x64, linux-x64, linux-arm64.
  2. Скачивает latest.json и нужный mma-<os>-<arch>.tar.gz, проверяет sha256.
  3. Распаковывает в ~/.mma/versions/<version> и переключает ~/.mma/current.
  4. Добавляет ~/.mma/bin в PATH и пишет launcher.
Требования к модели: любой OpenAI-совместимый backend. Проверено на Qwen3.5-9B через LM Studio / Ollama / llama.cpp. Для инструментов нужна поддержка tool-calling.

Быстрый старт

mma setup                 # провайдер, модель, контекст, безопасность
mma                       # интерактивный REPL
mma "перепиши auth на JWT"  # однократный запуск и выход
mma web                   # браузерный интерфейс на том же ядре и сессиях

Полезные первые команды в REPL:

/status                  # модель, контекст, сессия
/help                    # все slash-команды
/config                  # действующая конфигурация (секреты скрыты)
/doctor                  # полная диагностика окружения

Первый запуск и провайдеры

mma setup проводит по шагам: провайдер → base URL → API-ключ → модель → контекст → политика безопасности. Конфиг пишется в ~/.mma/config/ по доменам (провайдер, модель, безопасность, тулы, UI…).

Без мастера

mma provider check делает бесплатный listModels, mma provider list показывает записи и активную. Несколько записей дают failover по приоритету.

Контекст

Окно обычно определяется автоматически. Вручную:

mma context            # разбивка бюджета
mma context 65536      # зафиксировать окно
mma context --system 0.20 --reserve 0.15

Онбординг

mma meet          # интервью о вас и задачах → глобальная память
mma agents init   # создать/обновить AGENTS.md для проекта

Обновление и удаление

Повторный запуск установочной команды обновляет до последнего релиза; предыдущие версии остаются в ~/.mma/versions/ для отката. Встроенный updater проверяет GitHub Releases; при updater.autoInstall: true скачивает и активирует обновление в фоне (текущий процесс работает до рестарта).

Откат

# macOS / Linux
ln -sfn versions/<old-version> ~/.mma/current

Удаление

# macOS / Linux
rm -rf ~/.mma
# Windows: удалить %USERPROFILE%\.mma и убрать его bin из PATH

Web UI

mma web                 # случайный порт, браузер откроется сам
mma web -p 4096 --no-open

Тот же агент, ядро и сессии, но поверх SSE + REST. Первый запуск при пустом конфиге открывает мастер настройки прямо в браузере.

Чат

  • Параллельные ходы в разных вкладках; в одной сессии — очередь сообщений (Esc останавливает ход).
  • MMART — маскот-индикатор: отражает фазу (думает, читает, пишет, выполняет, ошибка).
  • Субагенты: строка «Задача подагенту» кликабельна → read-only транскрипт прогона; в шапке — маскот, статус и кнопка «■» остановки; чипы переключают параллельные прогоны; в правом верхнем углу — сетка маскотов субагентов (клик открывает прогон).
  • Reasoning: ступень показывается бейджем с лампочкой в шапке блока «думаю».
  • ML: длинный вывод тулов сворачивается, в quiet-режиме тела тулов скрыты; ошибки видны одной строкой.
Безопасность: --host не на loopback требует --token. Не выставляйте UI в интернет без токена и обратного прокси.

Сессии

Сессии персистентны: ~/.mma/sessions/<id>/ хранит meta.json, history.jsonl и подробный session.jsonl (тулы, аргументы, длительность, ошибки).

mma session list
mma session show <id>
mma session export <id> --format md --out report.md
mma session diagnose <id>    # разбор по сигнатурам сбоев
mma session prune            # удалить сессии без сообщений пользователя

Имя сессии выводится автоматически по первому сообщению, если не задано вручную. /resume поднимает историю; search_history ищет по всем history.jsonl.

Контекст и компакция

Бюджет окна делится на системный промпт, определения тулов, историю и резерв ответа. Приближение к лимиту запускает структурную компакцию: она сохраняет факты, решения и ошибки, а не просто режет историю.

  • [Tool ledger] — список уже прочитанного, чтобы модель не ходила по кругу.
  • Оценка токенов калибруется по реальному prompt_tokens провайдера.
  • При переполнении инструкций/карты — честная деградация с причиной, а не тихое усечение.
  • Настройки: context.*, доли system/reserve; пороги компакции.
mma context                  # текущая разбивка
mma context 65536            # окно вручную
mma context --system 0.2 --reserve 0.15

Планирование и гарантии

Планы ведутся тулами plan / plan_step / todo. Шаг закрывается только проверкой: файл существует, содержимое совпало, команда выполнилась. Дополнительно работают:

  • Hallucination detection — проверка путей, противоречий, уверенности и claims («создал файл X»).
  • Critic — встроенный ревьюер хода (опционально).
  • Stuck detection и honest-stop: повторяющиеся вызовы/серии провалов останавливают петлю с честным статусом.
  • Final audit — финальная проверка перед ответом.
  • Auto-advance — шаг плана двигается по факту изменения файлов/команд.

Субагенты

Тул subagent запускает изолированного агента со своим контекстом, скоупом файлов и набором тулов. Несколько вызовов в одном сообщении выполняются параллельно (через форки исполнителя).

task: "напиши тесты для src/auth.ts"
allowed_files: ["src/auth.ts", "tests/auth.test.ts"]
tool_tags: ["file", "code"]
expert_tag: "reviewer"       # опционально: роль из config.experts
result_mode: "file"          # вернуть путь+сводку вместо полного текста
max_tokens: 8000
  • Глубина рекурсии ограничена security.maxRecursionDepth.
  • Результат в режиме file сохраняется в <workspace>/.mma/artifacts/<session>/.
  • Остановка: кнопка «■» в шапке прогона в web UI; стоп родительского хода гасит и дочерних.
  • Таймаут — subagent.timeoutMs (по умолчанию 180 с).

Память, скиллы, AGENTS.md

  • Память (remember / recall, /memory) — глобальные факты и предпочтения, переживают сессии.
  • Скиллы (load_skill, /skill) — подключаемые инструкции/процедуры из каталогов навыков.
  • AGENTS.md — проектные правила; mma agents init создаёт или улучшает файл, --no-agents-md отключает загрузку.
  • Профиль — mma meet записывает предпочтения и домен использования.

Инструменты

Ядро поставляет ~37 инструментов. Набор сужается тегами и enable_tools; структурные тулы (plan, todo, verify, project_map, lsp_check) доступны всегда.

КатегорияТулы
Файлыread_file, write_file, append_file, edit_file, glob, grep, list_dir, create_dir, delete_file, move_file, file_info
Исполнениеbash, process_list/log/kill/wait, pipeline_run, browser, subagent, mcp_call
Вебweb_search, web_fetch, web_browse, download_file
Контекст/поискchunk_query, scan_corpus, search_history, project_map
Память и профильremember, recall, meet_done, load_skill
Структураplan, plan_step, todo, verify, lsp_check, set_thinking, enable_tools, define_capability

Все пути проходят enforcement: скоуп, защищённые пути, SSRF, rate-limit — в одной точке ToolExecutor.execute().

Поиск и веб

  • web_search — поиск (провайдер настраивается, по умолчанию DuckDuckGo).
  • web_fetch / web_browse — загрузка и чтение страниц; контент помечается как недоверенный.
  • download_file — скачивание с проверкой размера/редиректов.
  • SSRF-политика блокирует приватные адреса; DNS-резолв учитывается.

Браузер

Тул browser управляет Chromium через Playwright: навигация, снимок DOM, клики, ввод, скриншоты. Браузер скачивается при первом использовании:

~/.mma/current/runtime/bun x playwright install chromium

Если Chromium не установлен, тул возвращает понятную ошибку, а не зависает. Приватные адреса блокируются так же, как в веб-тулах.

MCP

Подключение MCP-серверов (stdio или SSE) описано в конфиге mcpServers; вызов — через mcp_call. Серверы и их статус видны в web UI: Plugins → MCP.

{
  "mcpServers": {
    "everything": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-everything"] }
  }
}

Плагины

Плагин — JS/TS-модуль, который добавляет тулы, хуки жизненного цикла и метаданные. Плагины бывают глобальные и проектные; отключение — живое.

mma plugins list
mma plugins show <name>
mma plugins disable <name>
mma plugins reload
mma plugins drafts            # черновики, написанные агентом
mma plugins drafts approve <id>
Важно: disable плагина — не sandbox. Код модуля уже загружен; permissions в манифесте — декларация для показа, не enforcement.

Агент может написать собственный плагин через define_capability: файл создаётся, но остаётся инертным, пока вы не разрешите черновик.

Пайплайны

pipeline_run исполняет YAML-DAG: шаги, зависимости, параллельные волны, ретраи. Удобно для повторяемых многошаговых сценариев (сборка, проверка, публикация).

steps:
  - id: build
    run: bun run build:prod
  - id: test
    run: bun test
    needs: [build]

LSP

Языковые серверы дают диагностику после правок и по запросу lsp_check. Поддерживаются TypeScript, CSS, HTML и другие серверы, установленные в системе.

/lsp doctor      # почему сервер не работает
/lsp             # состояние

Холодный старт LSP не блокирует запись: правка завершается сразу, проверка приходит следом.

Карта проекта

Индекс символов (определения, сигнатуры, outline) с PageRank-ранжированием под бюджет токенов. Учитывает .gitignore/.mmaignore, обновляется инкрементально.

mma map summary
mma map refresh
mma map find <query>

Сертификация моделей

Набор сценариев проверяет, тянет ли модель агентский цикл: тулы, планы, файлы, восстановление после ошибок.

mma model certify <name>
mma model cert-status <name>
mma model cert-list

Политики и защита

Безопасность включена по умолчанию (пресет balanced): валидация bash, политика путей, сетевой SSRF-фильтр, сканирование контента, шифрование сессий, аудит.

mma security status
mma security policies
mma security set-policy balanced
mma security enable-encryption
mma security enable-audit

Всегда включено

  • Защищённые пути: .git/, .env*, *.key|pem|p12|crt, .npmrc, .netrc — независимо от настроек.
  • Скоуп записи: мутирующие тулы пишут только в разрешённые пути.
  • Bash: рабочая директория ограничена, опасные команды блокируются, вывод санитизируется.
  • SSRF: приватные адреса и метаданные облака недоступны сетевым тулам.

DLP и данные

Корпоративная политика данных (security.dataPolicy) фильтрует egress к провайдеру, скрывает пути от API, маскирует секреты и может требовать локального провайдера. При failClosed сомнительный запрос не уходит наружу.

  • apiHiddenGlobs — 404 на скрытые пути в web/serve.
  • providerBlockGlobs — что нельзя отправлять модели.
  • Шифрование сессий: mma security enable-encryption; ключ хранится вне сессий.
  • Аудит: события безопасности и уведомления (auditNotifier).

Service API

mma serve --host 127.0.0.1 --port 7331 --token <secret>

Agent Service API v1: сессии, задачи, SSE, webhooks. Живой контракт — GET /v1/openapi.json, человеческая страница — GET /v1/docs. Bearer-токен обязателен для всех приватных маршрутов; один тенант = один процесс.

МетодПутьНазначение
GET/v1/health, /v1/readyliveness, readiness (проба провайдера)
GET/v1/openapi.json, /v1/docsконтракт
POST/GET/v1/sessionsсоздать/список (externalRef, status)
GET/DELETE/v1/sessions/:idметаданные/удаление (занятая → 409)
POST/v1/sessions/:id/tasksсабмит задачи
GET/v1/tasks/:jobIdстатус/результат

Ошибки — RFC 9457 (application/problem+json). Вебхуки подписываются; URL проходит SSRF-проверку. Подробности — docs/agents/service-api.md.

Конфигурация

Конфиг разбит по доменам в ~/.mma/config/*.json (provider, security, tools, ui, session, service, …). Единый реестр ключей валидирует значения; mma config show скрывает секреты.

mma config show
mma config set model qwen/qwen3.5-9b
mma config set ui.verbosity verbose
mma config set subagent.timeoutMs 300000
mma config migrate          # legacy config.json → домены

Архитектура

Слои: поверхности (REPL / web / serve) → ядро (Agent, ToolExecutor, контекст, промпт, наблюдаемость, ModuleHost) → модули (LSP, browser, indexer, skills, MCP, memory, critic, execution, service, …). Критерий границы: модуль можно отключить и продолжить работу; ядро — нельзя.

  • Одна петля: Agent.run вызывает цикл ровно один раз, все гейты внутри.
  • Одна точка enforcement: ToolExecutor.execute() — allowlist, теги, scope, protected-пути, SSRF, rate-limit.
  • Один позвоночник наблюдаемости: события с source, ошибки объектом, fail-open с записью.
  • Один путь записи конфига: ConfigStore.set возвращает эффекты, ключи объявляет модуль.
  • Один writer терминала: OutputChannel/OutputBus, без прямого console.*.

Нормативная спека: docs/specs/2026-10-12-architecture-v2-design.md.

  • Правило ≤300 строк: крупные файлы — только в .arch-allowlist.json, потолки не растут.
  • Спека до кода, если меняется контракт (путь данных, граница модуля, формат события, схема конфига).
  • Инвариант — это тест: гейты tests/arch/*, tests/output/*, профильные guard-тесты.
  • Новый тул объявляет security: { caps, pathArgs?, urlArgs?, manual? } — без этого не компилируется.

Релиз

  1. Зелёные bun test и bun run quality.
  2. Запись в CHANGELOG.md и версия в package.json (beta: только 0.x.y).
  3. bun run build:prod, smoke node dist/main.js --version.
  4. Commit chore(release): X.Y.Z, аннотированный тег vX.Y.Z.
  5. git push origin master --follow-tags → GitHub Actions собирает 5 платформ и публикует Release + latest.json.

npm-публикации нет: раздача только через GitHub Releases; сайт обновляется workflow pages.

Участие

  • Ветка от master: feat/, fix/, docs/, refactor/, chore/.
  • Одна задача — одна ветка и один контракт; массовые правки «заодно» не принимаются.
  • Для изменения поведения — тест, который падал бы без правки; для UI — живой прогон.
  • Долг фиксируется в docs/agents/debt.md сразу, а не «потом».
  • PR/merge — после зелёных тестов и quality.

Частые проблемы

Модель «думает», но не вызывает тулы

Проверьте, что backend поддерживает tool-calling и модель не слишком мала. Увеличьте retry.noDataTimeoutMs, если провайдер буферизует SSE. mma model certify покажет, тянет ли модель агентский цикл.

Context overflow / частые компакции

Уменьшите системный промпт и карту проекта, поднимите окно (mma context 65536), проверьте /sysprompt и Trace. Компакция с причиной видна в session.jsonl.

Провайдер недоступен

mma provider check, затем mma provider list — активная запись должна указывать на рабочий URL. Для локальных серверов проверьте curl http://localhost:PORT/v1/models.

Браузер не запускается

Установите Chromium: ~/.mma/current/runtime/bun x playwright install chromium. В headless-окружении нужен системный Chromium и MMA_BROWSER_EXECUTABLE.

LSP не отвечает

/lsp doctor объяснит причину: сервер не установлен, холодный старт, офлайн-режим. Правка файла не блокируется ожиданием LSP.

Веб-интерфейс не открывается

mma web --no-open печатает URL; при --host не на loopback обязателен --token. Порт можно задать -p.

Сессия повреждена/не читается

mma session diagnose <id> (только чтение), затем mma session export. Не редактируйте session.jsonl вручную.

FAQ

Нужен ли интернет?

Нет, если модель и провайдер локальные. Веб-поиск/браузер и облачные провайдеры требуют сеть.

Минимальный контекст?

Комфортно от 32K; 8K работает с агрессивной компакцией. Окно определяется автоматически.

Это только для кода?

Нет. Позиционирование — универсальный агент: разработка, исследование, API, автоматизация, ассистент.

Почему нет TUI?

Осознанно: минимальный CLI + REPL и браузерный UI. TUI остаётся возможной поверхностью, но не целью.

Где хранятся секреты?

В конфиге провайдера; config show их скрывает, сессии и экспорт редактируются, .env*/ключи защищены always-on.

Можно ли выставить web UI наружу?

Да, с --token, обратным прокси и TLS. Без токена не-loopback bind запрещён.

# Как контрибьютить в MMA

MMA — beta-проект (`0.x.y`). Мы ценим маленькие, обратимые изменения с зелёными
проверками больше, чем большие «заодно».

## Требования

- **Bun** (проект собирается и тестируется через Bun)
- **Node.js ≥ 20** — для собранного CLI
- **Windows / macOS / Linux**; полный набор тестов ориентирован на Windows, POSIX-подмножество
  отдельно гоняется в CI

## Быстрый старт из исходников

```bash
git clone https://github.com/Alexeykoh/micro-model-agent.git
cd micro-model-agent
bun install
bun run mma setup     # мастер провайдера
bun run mma           # REPL
```

Полезные команды:

```bash
bun test                  # все тесты
bun run quality           # typecheck + frontend typecheck + arch-гейты + lint + fallow
bun run quality:posix     # POSIX-подмножество (Linux/macOS)
bun run mma "<промпт>"    # прогнать агента вживую
bun run web:dev           # web-режим с watch
```

`test:e2e` запускается только по явной просьбе: браузерные сценарии не должны идти в
обычном цикле.

## Ветки и интеграция

- Интеграционная ветка — **`dev`**. Любая задача — отдельная ветка от `dev`:
  `<type>/<краткое>` (`feat/`, `fix/`, `docs/`, `refactor/`, `chore/`).
- `master` — ветка релиза. В неё не коммитят напрямую: `dev` попадает туда осознанным
  merge после стабилизации.
- Задача, которая правит шесть файлов в шести подсистемах, — это шесть задач. Дробите.
- Спека коммитится в той же ветке, что и код.

## Определение «готово»

Задача закрыта, когда:

- `bun test` зелёный;
- `bun run quality` зелёный;
- для изменения поведения есть тест, который **падал бы** без правки;
- для UI/CLI — живой прогон;
- для текста, видимого модели или пользователю, — запись в `session.jsonl` или логе.

## Документация

- Меняется контракт (путь данных, граница модуля, точка enforcement, формат события,
  схема конфига) — сначала спека в `docs/specs/`, потом код.
- Завершённая спека не удаляется, а переезжает в `docs/archive/specs/<год>/`.
  Правила — в [`docs/README.md`](./docs/README.md).
- Отложенный костыль фиксируется в [`docs/agents/debt.md`](./docs/agents/debt.md)
  с причиной, критерием выхода и триггером.

## Стиль кода

- TypeScript strict, без `as any`.
- Пользовательские строки — только через `t()`; ключи `en`/`ru` симметричны.
- Форматирование — Prettier, линт — Biome (linter only).
- Прямой `console.*` в `src/` запрещён: вывод идёт через `OutputChannel`.
- Файл больше 300 строк — повод разрезать, а не дописать.

Подробности: [`docs/agents/code-style.md`](./docs/agents/code-style.md) и
[`AGENTS.md`](./AGENTS.md).

## Pull request

1. Ветка от свежего `dev`.
2. В описании: что меняется, зачем, как проверено.
3. Приложите вывод `bun run quality`.
4. Если меняется поведение — ссылка на тест и/или спеку.
5. Не смешивайте рефакторинг и новую функциональность в одном PR.

Шаблон PR подставится автоматически.

## Безопасность

Не открывайте публичный issue для уязвимостей. Напишите мейнтейнеру напрямую
(контакт — в профиле GitHub) и дайте время на фикс.

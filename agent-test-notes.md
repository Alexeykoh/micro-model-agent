# Результаты тестирования агента (режим base)

## Что исправлено

### 1. Агент больше не спамит tool_calls после приветствия
- **system-prompt.ts**: убрана инструкция "спроси имя и сохрани", правило на английском
- **system-prompt.ts**: правило 12 запрещает list_dir/tree без явной просьбы
- **loop.ts**: nudge (продолжить работу) не срабатывает если агент уже написал ответ

### 2. Агент не упоминает user profile
- Правила 11/9 явно запрещают комментировать профиль пользователя

### 3. Авто-загрузка навыков только при реальной работе
- **loop.ts**: авто-загрузка @skill срабатывает только если ответ содержит tool_call
- Описательный ответ с упоминанием навыков больше не триггерит загрузку

### 4. Невалидные tool_call в описательном тексте игнорируются
- Если в ответе > 100 символов текста вне `<tool_call>` — теги считаются примерами
- Агент не получает ошибку за упоминание формата вызова

## Оставшиеся проблемы (Qwen3.5-9B)

### 1. Empty response после каждого tool result
Агент стабильно возвращает пустой ответ после получения результата инструмента.
Требуется retry (`[continue]`) чтобы сдвинуться дальше.
- Каждый tool_call тратит ~2 лишних шага: empty → retry → следующий tool_call
- Особенно заметно при чтении больших файлов (чтение 900 строк = 6-8 лишних шагов)
- **Корень**: малая модель "задумывается" между tool_call, не умеет сразу планировать следующий шаг
- **Текущее смягчение**: retry сообщение сокращено до `[continue]`, минимизирует расход токенов

### 2. Чтение больших файлов чанками по 200-300 строк
- Агент вызывает read_file несколько раз подряд для чтения всего файла
- Каждый чанк → empty response → retry
- Для файла в 900 строк: ~8 шагов вместо ~3

### 3. Отсутствие stdin режима в REPL
- Тестирование через `--stdin` делает ровно один запрос и завершается
- Нельзя протестировать многошаговый диалог

### 4. Агент не отличает вопрос о коде от задачи на изменение
- На "show me the function" — читает файл (ок, надо)
- На "tell me about the project" — просто отвечает (ок, не надо читать)
- Но грань тонкая, может ошибиться

## Что ещё можно улучшить

- При пустом ответе после tool result — не слать retry, а автоматически продолжать
  (но это требует изменения архитектуры — модель должна явно сказать "continue")
- Увеличить лимит строк при первом чтении файла (сейчас 200) — меньше чанков
  (но это в системном промпте, модель сама выбирает offset/limit)
- Если модель возвращает только tool_call без текста — не ждать текста
  (сейчас tool_call + empty text = норм, код уже обрабатывает)
